从设备看，因特网连接的是端系统

手机、计算机和服务器都是端系统（end system），也叫主机（host）。端系统运行应用，通过通信链路（communication link）连接分组交换机（packet switch）。教材在这里把链路层交换机和路由器都归入分组交换机；它们查看的地址和承担的职责不同，后面再拆开。

发送方把数据组织成分组（packet），网络让分组经过一串链路与交换设备到达接收方。这串经过的设备与链路构成路径（path / route）。链路速率用 bit/s 表示，它说明单位时间能把多少位送入链路，不直接说明一个分组多久到达远处。

读 Figure 1.1 时不要把每个浅色区域当成一台设备。家庭网、校园网、运营商网和内容提供商网络各自包含多台设备。因特网的规模来自这些网络互联；图只是结构示意，不对应某次实际探测的路径。

从应用看，网络提供通信服务

网页浏览涉及浏览器和服务器两个进程，它们运行在端系统上。网络核心负责转送分组，不必运行用户的浏览器或网页业务逻辑。教材采用这种边缘与核心的职责划分；网络设备还可能运行管理程序，后续也会讨论中间盒，不能据此断言路由器“完全没有软件”。

应用通过套接字接口（socket interface）请求通信服务。可以把它理解为程序交数据给网络的接口，但它不是某一根网线，也不等于一种网络协议。第 2 章研究进程怎样使用接口，第 3 章研究接口背后的运输服务怎样实现。

协议同时规定格式、顺序和动作

协议（protocol）规定通信实体交换消息的格式与次序，以及发送、接收或其他事件发生时采取的动作。只约定“字段里写什么”还不够：收到回复后是否继续、等不到回复怎么办，也属于协议行为。

图右侧先建立连接，再发送 GET、接收文件，展示的是教材选择的简化 Web 例子。图中的 connection request / reply 省略了 TCP 握手细节，不能把两根箭头当成完整握手，也不能把此图当作所有 Web 协议版本的实际抓包。

两个程序即使互相收到了字节，也可能因为格式、状态或时序约定不同而无法合作。例如接收方把消息长度看成字符数，发送方却填入字节数，后续边界就可能被解释错。这是补充解释，用来说明互操作为什么依赖共同约定。

标准让不同实现能够配合

IETF 推进互联网协议标准，IEEE 802 系列涉及 Ethernet、无线局域网等技术。标准约定可观察行为，各厂家和操作系统仍可采用不同的内部实现。

补充限定：RFC 是文档系列，并非每份 RFC 都是互联网标准。阅读时要看文档状态及更新、替代关系。依据 RFC 1796（查阅 2026-10-23）。本课不沿用教材当时的 RFC 数量、联网设备预测作为现状。
