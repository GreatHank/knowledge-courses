12 · TCP Socket与消息边界

监听套接字和连接套接字有什么区别，怎样从字节流读出一条消息？

监听入口与会话通道各司其职

TCP 服务端先创建并绑定监听套接字，调用 listen 开始接受连接请求。客户端 connect 发起连接；服务端的 accept 返回一个已连接套接字和对端地址。后续收发使用这个新套接字，原监听入口保留给后续连接。

accept 返回的是内核管理的连接，不能理解为应用执行它才开始所有握手动作。两个套接字的区别也不要求“每个客户分配新的服务器端口”：不同 TCP 连接可以共享服务器监听端口，由双方地址与端口组合区分。

recv没有读到一行的承诺

教材的短例子用一次 send、一次 recv 展示收发意图。迁移到真正的字节流程序时，必须补上消息边界：一次 send 可能只提交部分字节，一次 recv(1024) 也只返回至多1024字节，可能少于一条消息，也可能包含多条消息的内容。

这里纠正书内193页把 recv 描述成“一直累积到回车”的说法。Python Socket HOWTO明确要求应用选择定长、分隔符、长度前缀或连接关闭等定界方式。本课采用 LF 换行分隔；readline 在缓冲层累积读取，sendall 处理完整提交。该方式负责消息边界，不负责保证业务成功。

文本转UTF-8→添加LF字节→TCP字节流→读取至LF再解码

一条含中文的消息可能在多字节字符中间被分成两次接收。先收齐以 LF 结束的字节序列，再统一解码，就不用假设每次到来的字节都正好是完整字符。

一条连接处理一行

tcp_server.py

import socket

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as listener:
    listener.bind(("127.0.0.1", 12000))
    listener.listen(5)
    print("TCP server ready", flush=True)
    while True:
        connection, address = listener.accept()
        with connection:
            with connection.makefile("rb") as reader:
                line = reader.readline()
                if not line.endswith(b"\n"):
                    raise ValueError("Incomplete request: missing LF")
                reply = line[:-1].decode("utf-8").upper()
                connection.sendall(reply.encode("utf-8") + b"\n")

查看 Python 源文件

listen(5) 的参数与等待接纳的连接队列有关，不表示程序会同时处理5个客户。这里的循环一次处理一个连接：读一行、回复一行、关闭连接，再接下一位。makefile("rb") 提供带缓冲的二进制行读取；它是额外的一层接口，读取到行尾后才解释 UTF-8。

tcp_client.py

import socket

message = input("Input a sentence: ").encode("utf-8") + b"\n"
with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as client:
    client.settimeout(3)
    client.connect(("127.0.0.1", 12000))
    client.sendall(message)
    with client.makefile("rb") as reader:
        reply = reader.readline()
        if not reply.endswith(b"\n"):
            raise ValueError("Incomplete response: missing LF")
        print(reply[:-1].decode("utf-8"))

查看 Python 源文件

客户端在文本后显式添加 b"\n"，因此服务端知道什么时候可以开始转换。如果对端在 LF 到来前就关闭连接，示例会报告消息不完整。发送和接收都用同一个已连接套接字，不再每次附上目的地址。

演示跑通不等于实现了通用服务

在示例目录先运行 python tcp_server.py，再运行 python tcp_client.py；两者只连接本机回环地址。TCP 12000与前一课的 UDP 12000属于不同协议的端口空间。服务器持续运行，用 Ctrl+C 结束。

这个程序约定一条连接只处理一行，未设计持久多消息会话、并发处理、输入上限和身份验证；遇到违反协议的请求会显式报错。它展示了连接生命周期和消息定界，不能直接拿来对外提供生产服务。TCP 内部怎样处理确认、重传与拥塞，留到第3章。
