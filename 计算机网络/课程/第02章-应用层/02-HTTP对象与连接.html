页面包含多个可请求对象

一个页面可能包含基础 HTML、图片、脚本和样式表。教材以“1个 HTML + 10张图片”为例，共有11个对象。浏览器先取得 HTML，解析其中的引用，再请求所需对象；HTTP 规定对象怎样请求和响应，浏览器怎样排版显示则是另一项工作。

例如 http://www.example.com/course/network.html 中，主机名用于寻找服务地址，/course/network.html 标识所请求的资源路径。本节先采用教材的明文 HTTP/1.x、TCP 80 模型；HTTPS 还涉及 TLS，HTTP/3 的运输方式也不同。

沿着一条非持久连接看时间

非持久连接（non-persistent connection）为这一对请求与响应建立连接，响应完成后关闭。教材的简化时序中，TCP 建连的前两步约占1个 RTT；第三步确认与 HTTP 请求一起发出，再经过约1个 RTT 开始收到服务器发来的对象；收齐对象还需要对象的发送时间。

T单对象 ≈ 2 RTT + L / R

RTT 是小分组往返时间，L 是对象的比特数，R 是用于估算的发送速率。这是忽略 DNS、TLS、服务器处理、TCP 启动过程等影响的粗略模型，不是浏览器总耗时公式。若 RTT=50 ms，L=1 Mbit，R=10 Mbps，估算为100 ms +100 ms =200 ms。

11个对象逐个使用新连接，简化模型就反复支付建连代价。若图片用多个并行连接取得，则这些时间会重叠，不能直接把单对象时间乘11；共享瓶颈也不会因开更多连接而变宽。

复用连接与流水线是两个决定

方式连接怎样使用仍需关注
非持久连接本节模型中每对象一条新连接重复建连和维护状态。
持久连接，逐次请求同一连接取得多个对象，每次等待前一个响应省去重复建连，但仍逐次等待请求/响应。
持久连接，流水线不等前一个响应就发出后续请求HTTP/1.1 响应仍按请求顺序交付。

持久连接（persistent connection）让服务端在响应后保留连接，后续请求可继续使用它。它也不会无限保留：超时、错误或明确关闭都可能结束连接。

标准补充：HTTP/1.1 默认采用持久连接；支持持久连接的客户可以使用流水线（pipelining），两者不能合并成“默认必定流水线”。见 RFC 9112 §9.3。本课据此区分教材书内131页的两种机制。
