03 · HTTP报文与Cookie

服务器怎样读懂请求，又怎样把多次请求关联成同一会话？

先读首行，再读头部与正文

GET /course/network.html HTTP/1.1
Host: www.example.com
Connection: close

这是按教材格式改写的请求示意，不是抓包记录。首行给出方法、请求目标和版本；头部的 Host 指明所访问的主机名，不能仅凭已经建立的 TCP 连接就删掉它。Connection: close 表示本次响应之后不继续复用连接。

线上 HTTP/1.1 的行以 CRLF 结束，头部末尾还有一个空行，即连续两个 CRLF。GET 常用来获取资源；表单既可以用 GET 把参数放进请求目标，也可以用 POST 提交消息体。HEAD 请求响应头信息而不返回相应的消息体；PUT 与 DELETE 则表达不同的资源操作，是否允许执行由服务端决定。

响应状态和内容长度各回答一个问题

HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Content-Length: 5
Connection: close

hello

状态行的 200 表示成功；Content-Type 描述内容类型，Content-Length 给出字节数。这里 hello 是5个 ASCII 字节。若正文含中文，字符数通常不能当作 UTF-8 字节数。上例选择长度字段分隔正文；HTTP/1.1 还有其他消息体定界规则，不是所有响应都有这个字段。

状态应怎样理解
200 OK请求成功，依方法和响应规则返回结果。
301 Moved Permanently资源有永久新位置，位置由 Location 等信息给出。
400 Bad Request请求有问题，服务端无法或拒绝处理。
404 Not Found未找到所请求资源。
505 HTTP Version Not Supported服务端不支持所用 HTTP 版本。

Date 与 Last-Modified 也不同：前者是响应的时间信息，后者描述所选表示的最后修改时间。后者可参与缓存验证；下一课会用到。

无状态 HTTP 上仍然可以建立会话

HTTP 的“无状态”不要求网站忘记所有用户数据。教材的 Cookie 例子把状态放在浏览器和服务端数据库中：初次请求后，服务端建立标识与记录；响应携带 Set-Cookie；浏览器保存该 Cookie；符合发送条件的后续请求再携带 Cookie，服务端由此查到购物车或会话。

Set-Cookie: session=abc123
Cookie: session=abc123

这两行分别属于响应和后续请求，不应放在同一个方向理解。Cookie 可以只是一个查表用的标识，并不要求把整份购物车或密码装进去。识别一个浏览器会话，也不天然证明正在操作的是某个真实的人；登录验证与会话管理还需要各自的规则。

教材列出四个参与部分：响应头、请求头、浏览器保存的数据、网站后台数据库。Cookie 帮助维持会话，也可能用于跟踪。图中的单一数字是机制示意，不是完整的 Cookie 语法或安全配置。
