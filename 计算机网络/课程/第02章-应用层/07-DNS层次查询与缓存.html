07 · DNS层次查询与缓存

本地域名服务器怎样逐步找到答案，为什么不必每次从根查起？

名称解析提供的是服务地址线索

人使用主机名，网络传送需要地址。DNS 既是一套分布式数据库，也是一种应用层查询协议。浏览器解析 URL 中的主机名后，取得地址，再与相应服务建立通信。DNS 不下载网页，也不代替 HTTP 请求资源路径。

DNS 的用途不止查询主机地址：它还表达别名、邮件接收服务器，并可为一个名字返回多个地址以支持分发。DNS 运行在端系统之间，使用运输服务，虽承担关键基础功能，仍属于应用层。

按图中的1到8追一遍

  1. 主机把查询交给本地 DNS 解析器（local DNS / recursive resolver）。
  2. 没有可用缓存时，解析器向根服务器查询，得到下一层的线索。
  3. 解析器向对应顶级域（TLD）服务器查询，取得权威服务器的线索。
  4. 解析器向权威服务器查询目标记录，把最终结果返回主机，并按规则缓存。

图2.19为简化例子：主机与解析器之间1问1答，加上解析器向3类服务器各1问1答，共8条 DNS 消息。真实名称可能还有更多委派层级；命中缓存又可能减少查询。不能把8条消息当作所有域名解析的固定成本。

“本地”描述它为这台主机提供解析服务，不保证物理上就在附近；它也不是根→TLD→权威委派树中的又一级。

递归问的是结果，迭代问的是下一步线索

主机向解析器请求“替我找到答案”，是递归查询（recursive query）。图2.19中解析器自己连续访问根、TLD和权威服务器，遇到转介就继续下一步，是迭代解析（iterative query）。图2.20是教材用于对比的全递归链，不应据此认为根服务器通常替每个用户一路查到底。

解析器可以缓存最终地址，也可以缓存委派及名称服务器的地址。若已有有效的 TLD 或权威服务器线索，就能跳过前面的步骤。TTL（time to live）约束缓存使用时间；DNS 的 TTL 是时间概念，别与 IP 分组逐跳递减的 TTL 混为一谈。

缓存返回的答案不因此变成权威数据来源。缓存尚未失效时，权威端的修改也未必立即体现在所有客户看到的结果中；不同缓存的剩余寿命可能不同。

协议补充：本书主要用 UDP 53 展示查询。DNS 也使用 TCP；RFC 7766明确要求通用 DNS 实现支持 TCP。不能把教材的 UDP 示例推广为“DNS 只能走 UDP”。
