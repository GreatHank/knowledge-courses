06 · 邮件传送与邮箱访问

发件、服务器间转交和收件，为什么需要不同的协议角色？

邮件先进入服务器，收件人可以稍后再读

邮件是异步通信：Alice 发信时，Bob 的手机不必在线。Alice 的用户代理（user agent）把邮件交给自己的邮件服务器；服务器负责向 Bob 的邮件服务器传送，后者把邮件放入邮箱。Bob 方便时再访问邮箱。

外发队列与收件箱不同。前者保存待送出的邮件，遇到目标服务器不可达时可以稍后再试；后者保存已接收、等待用户阅读和管理的邮件。具体重试间隔与保留时间是实现策略，教材给出的时间不是统一协议常数。

SMTP 是一段有状态的交接过程

S: 220 mail.example.net
C: HELO sender.example.org
S: 250 Hello
C: MAIL FROM:<alice@example.org>
S: 250 OK
C: RCPT TO:<bob@example.net>
S: 250 OK
C: DATA
S: 354 Send message, end with a dot line
C: From: alice@example.org
C: To: bob@example.net
C: Subject: A short note
C:
C: Hello Bob.
C: .
S: 250 Accepted
C: QUIT
S: 221 Bye

这是按教材基本 SMTP 对话改写的教学记录，没有实际发信；C/S 是说明方向的标签，不是发到网络上的正文。先完成 TCP 建连，再进行应用层问候、声明发件人与收件人、提交内容、结束会话。服务器间 SMTP 的教材示例使用 TCP 25。DATA 后的单独点行终止邮件数据；SMTP 还规定正文点行的转义处理，不能把上例直接当作完整邮件客户端。

MAIL FROM、RCPT TO 是传送信封中的命令；From:、To:、Subject: 是邮件内容自身的头部。把显示给读者的 To 改掉，并不等于改变 SMTP 实际投递的收件人。邮件头部和正文之间也以空行分隔。

同一连接可传多封邮件，每封重新开始一轮传送命令；一条 TCP 连接可以复用，但每次 SMTP 邮件传送仍有自己的命令和状态。服务器接受邮件也不证明 Bob 已阅读。

送到邮箱之后，还要访问邮箱

SMTP 主要承担推送与转交。Bob 想列出邮件、读取某封邮件、移动文件夹或标记已读，需要邮箱访问协议。教材介绍 IMAP，以及 Web 邮箱的 HTTP 接口。Alice 用浏览器发信时，也可以先经 HTTP 交给自己的服务，再由服务器用 SMTP 转交。

因此“在网页里写邮件”不表示服务器之间也改用 HTTP；同一项用户功能可以经过多个不同协议。图中箭头概括邮件的流向，HTTP/IMAP 的请求与响应本身仍是双向交互。

协议范围补充：教材按基本 SMTP 解释7位 ASCII 与附件编码。扩展 SMTP 已有 8BITMIME（RFC 6152），因此不能把“所有 SMTP 内容只能是7位”作为无条件结论。本课不配置邮箱、不连接公共邮件服务器。
