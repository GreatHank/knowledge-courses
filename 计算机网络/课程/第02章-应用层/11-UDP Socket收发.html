11 · UDP Socket收发

一次数据报发送需要哪些地址信息，服务端怎样知道回给谁？

先把应用协议说清楚

沿用教材的大小写转换任务：客户端发送一条短文本，服务端把字母转成大写，再返回。输入输出采用 UTF-8；本课以一个 UDP 数据报承载一条请求，并用一个数据报承载响应。客户端只尝试一次，不实现重传。

本课的 Python 文件是依据教材改写的本机演示版，不是原书代码逐字复制：使用显式模块名和上下文管理器；固定回环地址 127.0.0.1；客户端限定输入长度并设置3秒超时。服务端与客户端仍是独立进程，但测试不会经过外部网络。

服务端先绑定，客户端再发送

udp_server.py

import socket

with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as server:
    server.bind(("127.0.0.1", 12000))
    print("UDP server ready", flush=True)
    while True:
        data, client = server.recvfrom(65535)
        reply = data.decode("utf-8").upper().encode("utf-8")
        server.sendto(reply, client)

查看 Python 源文件

AF_INET 选择 IPv4 地址族，SOCK_DGRAM 选择数据报套接字。bind 把服务绑定到本机回环地址的 UDP 12000端口；随后 recvfrom 等待一条数据报，并返回数据与发送方地址。服务端把回复发给这个地址，随后继续等待。

udp_client.py

import socket

message = input("Input a short sentence: ").encode("utf-8")
if len(message) > 1024:
    raise ValueError("This teaching example accepts at most 1024 UTF-8 bytes")
with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as client:
    client.settimeout(3)
    client.sendto(message, ("127.0.0.1", 12000))
    reply, address = client.recvfrom(65535)
    print(reply.decode("utf-8"))

查看 Python 源文件

客户端没有显式绑定端口，操作系统会在需要时分配本地端口。sendto 每次给出目的 IP 和端口；encode/decode 把字符串和网络字节转换。服务端返回的 address 说明响应来源，但这段教学代码没有实现身份认证。

数据报边界保留，不代表可靠交付

UDP 保留数据报的边界：正常接收一个数据报不会像 TCP 字节流那样与下一条自动合并。但接收缓冲若太小，数据报可能被截断或产生平台相关错误；扩大缓冲也不会给 UDP 添加重传和可靠性。

这里客户端限制最多1024个 UTF-8 字节，接收调用预留较大的数据报缓冲。settimeout(3) 只限制等待，不会自动重试；超时只能说明这次等待未得到响应，不能单凭它证明是哪一段丢了包。错误会显示出来，不会伪装成成功。

在示例文件夹打开两个终端，先运行 python udp_server.py，再运行 python udp_client.py。例如输入 hello network，正常响应为 HELLO NETWORK。服务器持续等待，可用 Ctrl+C 结束。这个例子没有实现丢包恢复、并发业务或安全会话。
