06 · Go-Back-N滑动窗口

一个累计ACK怎样推动窗口，丢一个分组为什么可能重传一串？

先确定窗口的左边界

Go-Back-N（GBN）允许连续发送最多 N 个尚未确认的分组。窗口从 base 开始，长度为 N；从 base 到 nextseqnum−1 的分组已经发出，窗口内其余位置可用于新数据。

例如 base=2、nextseqnum=5、N=4，窗口为2、3、4、5；2–4已经发送，5还可以发送。收到能确认到3的 ACK3 后，base 变成4，窗口右移，腾出新的发送机会。这里暂不跨越序号回绕点。

累计确认与单个逻辑定时器

GBN 的 ACKn 表示从开头到 n 号分组都已按序收到。ACK1 丢失后，如果 ACK2 已经到达，发送端无需等 ACK1 重发：较新的累计确认覆盖了它。

事件发送端动作
上层有新数据且窗口未满以nextseqnum发送并保存副本；必要时启动定时器
收到有效且推进base的ACKnbase移动到n+1；仍有未确认分组则重启定时器，否则停止
最早未确认分组超时重传base到nextseqnum−1的所有未确认分组，并重启定时器

这个逻辑定时器跟踪最早未确认的分组。超时重传的是当时尚未确认的集合，不一定恰好 N 个。序号字段有限，实际比较要按序号空间循环处理；教学算例先用不回绕的整数显示窗口。

接收端丢弃乱序分组，持续指出缺口

按图从上向下读：发送端先发0–3，2号丢失。ACK0、ACK1到来后又允许发送4、5；接收端仍等2号，因此丢弃3、4、5，并反复返回 ACK1。2号超时后，发送端重发2–5；接收端这次按序收齐并确认。

GBN 接收端只需记住下一个期待序号，无需缓存缺口后面的数据。代价是3、4、5曾经完整到达，却还得再过一次网络。在窗口大、时延长的路径上，这种浪费会更明显。

同一个窗口，同时约束发送与恢复

窗口左边界由累计确认推进，右边界由左边界加 N 决定。即使后续分组已经到达接收端，只要它们因缺口被丢弃，就不能推动这个边界。

因此分析 GBN 时，应依次记录：哪个分组丢失、接收端当前期待哪个序号、ACK能累计到哪里、超时那一刻还有哪些分组未确认。仅凭“中间丢了一个”无法直接说重传多少个。
