09 · RTT估计与重传定时

网络时延不断变化，重传超时怎样兼顾恢复速度与误判？

超时不能简单等于最近一次RTT

超时时间 RTO 太短，会把仍在路上的数据当成丢失并重传；太长，真丢失后又恢复得慢。TCP 用往返样本 SampleRTT 估计典型时延，同时跟踪波动，给超时留出余量。

SampleRTT 从发送一个报文段到收到其确认计时。若数据重传过，某个 ACK 可能对应原件，也可能对应重传件，未经区分就采样会产生歧义。这是 Karn 算法排除含糊样本的原因；时间戳选项可帮助区分。

平均值与偏差各保存一项信息

教材用指数加权移动平均，让旧估计保留大部分权重，新样本逐步影响结果。令 S 为旧 EstimatedRTT，D 为旧 DevRTT，R 为新样本：

D新 = 0.75D + 0.25|R − S|
S新 = 0.875S + 0.125R
教材简式：RTO = S新 + 4D新

平均值估计典型水平，偏差估计波动程度。同样平均100 ms的两条路径，若一条时延非常稳定、另一条起伏很大，就不应使用完全相同的安全余量。

更新顺序按RFC 6298 §2明确：偏差使用更新前的S，再更新S。该标准还规定首次样本的初始化与时钟粒度G，公式为 S+max(G,4D)，并建议将小于1秒的计算结果取至1秒；不能把教材简式的输出直接称为所有系统的实际RTO。

一次完整的更新算例

量补充算例
旧S、旧D、新R100 ms、10 ms、140 ms
新偏差D0.75×10 + 0.25×|140−100| = 17.5 ms
新估计S0.875×100 + 0.125×140 = 105 ms
教材简式RTO105 + 4×17.5 = 175 ms
按RFC建议下限处理假设G≤70 ms，再取1秒下限，得到1000 ms

首次拿到样本 R 时，标准初始化为 S=R、D=R/2。之前尚无测量时，RFC 6298 建议初始 RTO 为1秒。初始化、后续平滑更新和超时后的退避是三个不同步骤。

超时后退避，避免反复施加相同负载

发生重传超时后，RTO 加倍，重传最早未确认的报文段并重新计时。连续超时会继续退避；不能收到任意重复 ACK 就把超时立即降回原值。新的有效 RTT 测量会参与后续重新估计。

本课确定重传前的等待时间；下一课再看确认怎样推进、超时或重复ACK后重传哪些数据。超时是恢复的依据，但单凭超时仍不能确定网络已经拥塞。
