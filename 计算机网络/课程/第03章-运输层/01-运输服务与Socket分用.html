主机通信之上，再区分应用进程

网络层提供主机之间的逻辑通信；运输层把这项服务交给端系统中的进程。发送端从不同 Socket 取得数据，加入运输层首部后交给 IP；接收端根据首部字段，把数据送入对应 Socket。这两个方向分别叫多路复用（multiplexing）和多路分解（demultiplexing，简称分用）。

教材的家庭邮递类比中，IP 把信送到一户人家，运输层再把信交给某个家庭成员。类比说明分工；真实应用中，一个进程可以使用多个 Socket，一个服务端口也可以对应许多连接，不能把“进程、Socket、端口”当作一一对应。

本章把协议逻辑放在端系统中讨论，路由器负责转发 IP 数据报。这个分层模型不表示现实中的防火墙、NAT 等设备永远不查看运输层字段。

IP 的尽力而为服务不保证交付、顺序或到达时间。TCP 可以在其上恢复丢失的数据、整理字节顺序，但不能保证任意故障下都成功，也不能凭空提供硬性的时延和带宽保证。UDP 开销小、无需先做 UDP 握手；需要额外可靠性或拥塞控制的应用，必须由上层承担这些工作。

UDP按接收入口分用，TCP还区分通信双方

源端口与目的端口各为16位，数值范围0–65535。目的端口帮助定位接收入口，源端口提供回复线索。应用可以显式绑定端口；未显式选择时，由系统在需要时分配。分配时机与动态端口范围依实现而异。

在教材的普通、未连接 UDP Socket 模型中，目的 IP 与目的端口决定接收入口。因此，不同源主机发来的报文可以进入同一个 UDP Socket，应用从每次接收结果中取得发送方地址。连接式 UDP、地址复用等系统细节不在这个模型内。

已建立的 TCP 连接用四元组区分：源 IP、源端口、目的 IP、目的端口。图中 A:26145→B:80 与 C:26145→B:80 的源端口相同，但源 IP 不同；C:7532→B:80 又是另一条连接。服务器的监听 Socket 接受建连请求，之后由各连接 Socket 收发数据。

这也解释了第2章的 accept()：监听入口继续等候新客户，已接受的连接有自己的通信状态。后面学习 TCP 序号、窗口和定时器时，它们都应放回具体连接理解。
