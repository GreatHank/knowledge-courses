连接是一组端系统状态

TCP 提供面向连接、全双工的有序字节流。通信双方保存序号、缓冲、窗口、定时器等状态；沿途无需为这条 TCP 连接预留专用电路。全双工意味着两个方向可以同时传数据，而且各有自己的字节序号和确认进度。

应用的一次写入不必对应一个 TCP 报文段，对端的一次读取也不必对应一次写入。TCP 按传输条件分段，接收端再整理为字节流；应用仍要用长度、分隔符等规则识别消息边界。

最大报文段长度 MSS 指 TCP 数据部分的上限，不包括 TCP 首部。若链路 MTU 为1500字节，采用20字节 IPv4 首部和20字节 TCP 首部且无其他开销，则可用 MSS 为1460字节。路径、IP版本与选项变化时，不能固定套用1460。

把首部分成定位、恢复与控制几组

字段本章中的作用
源/目的端口与双方IP一起识别连接
Sequence number本段第一个数据字节的序号；SYN/FIN另有序号规则
Acknowledgment number下一个期待收到的字节序号；由ACK标志说明其有效
Header length / Options首部长度按32位字计，最小5即20字节；选项可增加长度
Receive window接收方通告的可接收范围，服务于流量控制
Checksum检测首部与数据等覆盖范围的差错
SYN / FIN / RST建立、正常关闭一个方向、异常复位连接
ECE / CWR用于显式拥塞通知

图中还含 PSH、URG 和紧急指针等字段。它们不能当作普通应用消息边界；本章重点是序号、确认与窗口，也不能据教材的简化文字断言这些字段在所有实现中都不使用。16位接收窗口字段还可配合窗口扩大选项使用，字段宽度不等于所有连接的有效窗口上限。

序号标记字节，ACK指出连续数据的末端

假设为了讲解把第一字节记为0，且每段携带1000字节，则前几个报文段的序号是0、1000、2000。真实连接中，双方各自选择并交换初始序号，SYN 自身也占一个序号；这里的0只是相对编号。

TCP 的累计 ACK=536 表示536之前的字节已经连续收到，现在期待536。如果已经收到0–535与900–1000，中间536–899仍缺失，累计 ACK 不能跳到1001。缺口补齐且后段已缓存后，才可以确认到1001。

ACK 说明对端 TCP 的接收进度，不证明对端应用已经读取数据、写入磁盘或完成业务。业务确认需要应用协议另外约定。

同一报文可以一边送数据，一边确认反向数据

连接已经建立，A当前从42号字节发送，B当前从79号字节发送。A发出1字节字符 C，Seq=42、ACK=79；B回显1字节，Seq=79、ACK=43；A再发纯确认，Seq=43、ACK=80。

第二个报文同时携带反向数据和确认，叫捎带确认（piggybacking）。最后的纯 ACK 不携带数据，也不含 SYN/FIN，因此不消耗新的序号。这个 Telnet 图用于解释字段，未运行远程登录或抓包。
