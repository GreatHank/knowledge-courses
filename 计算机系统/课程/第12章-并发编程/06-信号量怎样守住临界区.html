06 · 信号量怎样守住临界区

怎样让每次更新都使用前一次更新后的值？

只允许一个线程进入更新过程

让 cnt 初始为 0，再给两个线程共用一个初值为 1 的信号量（semaphore）s。谁成功执行 P(s)，谁暂时取得更新许可（permit）；另一个线程如果遇到 s = 0，就等待。

P(s)：取得许可

s 大于 0 时，原子地减一并返回；为 0 时等待可用许可。

V(s)：归还许可

增加一个许可；若有人等待，使一个等待者有机会继续。

原子性来自同步原语

检查许可和取得许可不能拆成用户代码里的 if (s > 0) 与 s--。

教材使用 P / V 名称，对应 POSIX 信号量的 sem_wait / sem_post。这里采用同一进程各线程共享的信号量，初始化为 sem_init(&s, 0, 1)；pshared 的 0 说明它供同一进程的线程使用。

锁必须包住 L、U、S 三步

/* 使用教材检查错误的包装；初始化发生在线程创建前 */
Sem_init(&mutex, 0, 1);

/* 每个线程执行更新时 */
P(&mutex);
cnt++;
V(&mutex);
保护方式会发生什么
只锁 store两个线程仍可能先读到同一个旧值；各自计算后的旧结果被依次写回。
覆盖 load / update / storeB 只能在 A 归还许可后开始整段更新，从 A 写回的新值继续。
每个线程一把不同的锁没有形成共同约束；它们仍能同时进入。
有些访问绕过这把锁共同约定被破坏；只保护一部分访问不能消除全部冲突。

进度图怎样表达“不能进入”

在图中，P 和 V 把临界区包住。两个线程同时持有唯一许可的区域不可达，因此原来危险的重叠区被挡住了。图上标出的 −1 是假设两个 P 都通过后算出的非法状态，用来标记禁止区域；不是说信号量真的先变成负数再阻塞。

可以回到上一课的交互演示，选“临界区外加互斥”。B 尝试 P 时停住，A 写回并 V 后，B 才能完成自己的 P 和更新。

信号量的许可，与互斥锁的所有权

问题本课需要的区别
初值为 1，就永远是二元信号量吗？只有成对、正确地使用 P/V 才保持互斥协议；多做一次 V 可能把许可数加到 2。
能把 sem_t 一律替换成 pthread_mutex_t 吗？不能。POSIX mutex 有持有线程的所有权规则；信号量的 post 可以由另一个线程执行。
被唤醒者一定最先到吗？本课不假定 FIFO 公平性，也不把“可被调度”当成立即运行。
wait 被信号打断怎么办？sem_wait 可能失败并返回 EINTR；失败不表示取得了许可。原始接口需要明确处理错误。

例如原始 sem_wait 可以在 errno 为 EINTR 时重试；其他错误应报告或处理。不要失败以后继续访问临界区。接口依据：sem_wait(3)。

互斥保证一段更新，计数还能表示资源数量

临界区（critical section）是必须按互斥（mutual exclusion）协议访问共享状态的那段代码。把整个服务函数都锁起来虽然简单，却可能让所有客户端又排成一队；通常只保护确实共享的状态，并避免在锁内进行无关的长时间等待。

回到总图“互斥与资源计数”：初值 1 用来保护共享更新。下一课把许可数改成空槽位和已有项目的数量，让线程等待真正需要的资源。
