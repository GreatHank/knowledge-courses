把处理函数交给另一个执行流

第 7 行创建线程，让它从 thread 函数开始执行；第 8 行等待这个指定线程结束，然后主线程才走向 exit。创建成功以后，哪一方先运行不能靠代码上下位置判断。

void *worker(void *arg);                 /* 线程入口 */
pthread_create(&tid, NULL, worker, arg);  /* arg 是一个指针值 */
pthread_join(tid, NULL);                 /* 等待指定线程结束 */

片段展示接口形状，省略了错误分支。原始 pthread 接口通常直接返回错误码，不能一律按 errno 处理；原图首字母大写的 Pthread_* 是教材检查错误的包装。pthread_t 是线程标识（thread ID）类型，不应假定等于 Linux 的内核 TID 或可移植的整数。

结束当前线程，与结束整个进程分开看

操作作用
普通工作线程的入口函数 return结束这个线程，返回值可供 join 获取。
pthread_exit(value)结束调用线程；其他线程仍可继续运行。
主线程从 main 返回，或任意线程调用 exit结束整个进程，其他线程也随之终止。
pthread_join(tid, &value)等待特定的可连接线程结束，取得返回值并回收其相关线程资源。
pthread_detach(tid)安排该线程结束后自动回收相关线程资源，不再由 join 回收。

原书 PDF 1026 对“主线程调用 pthread_exit”的说明不准确：它结束调用线程，并不是自动等待并 join 其余线程。最后一个线程结束时，Linux 按退出状态 0 结束进程。依据：pthread_exit(3)。

分离不表示取消不了，也不表示工作已做完

joinable

需要安排一次 join 或将其分离；退出本身与资源回收（resource reclamation）是两个问题。

detached

不能再 join。分离状态决定结束后的回收方式，不改变共享数据的访问规则。

cancel 请求

pthread_cancel 只是请求取消；何时生效受目标线程的取消状态和取消类型约束。

教材 PDF 1026–1027 把 detached 说成不能被其他线程终止，不能照此理解。detach 不会让线程免于进程退出，也不禁止取消请求。依据：pthread_detach(3)、pthread_cancel(3)。

线程版服务器交接的是同一张表里的连接

先看第 21–23 行：主线程为本次连接分配一个独立 int，把 accept 的结果放进去，再传递这个地址。工作线程第 30 行复制描述符值，第 32 行释放参数块；它随后回显并 close。释放 int 参数块不会关闭连接，两者是不同资源。

资源交接方式谁最后释放
参数 int 的堆块主线程初始化；工作线程读取。工作线程复制值后 free。
connfd 对应的连接线程共享描述符表；传整数没有新建内核引用。接手的工作线程 close。
工作线程资源工作线程将自身 detach。线程终止后按分离规则回收。

这里主线程不能照搬多进程版本，在 create 后再 close(connfd)：线程共享描述符表，那会影响工作线程正在使用的连接。若原始 pthread_create 失败，连接和参数仍由主线程负责清理；教材包装在失败时终止程序。

初始化只做一次，也必须有同步保证

static pthread_once_t once = PTHREAD_ONCE_INIT;
pthread_once(&once, init_shared_state);

多个线程同时走到这里，使用同一个 once 控制对象，初始化函数只执行一次；调用返回时相应初始化已完成，见 pthread_once 的 POSIX 说明。不能用一个未同步的全局“已经初始化”布尔变量代替它。第 8 课会在累计字节计数里看到实际用法。

回到总图右侧：线程让处理函数并发执行，也让描述符、堆和普通全局对象进入同一个共享空间。下一课先判断“究竟是哪一个对象被共享”。
