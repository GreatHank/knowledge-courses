两个同名局部变量，和一个局部对象的两个地址

两个线程各调用一次函数，各自的自动局部变量（automatic local variable）通常是不同对象。但如果主线程把自己的局部数组地址交出去，其他线程就可以访问这个数组。判断共享，需要追踪对象和指针，不能只看变量声明写在哪一行。

原图第 16 行 ptr = msgs 把主线程局部数组的地址放进全局指针。工作线程随后通过 ptr[myid] 访问同一个数组。这正是“局部声明”与“是否被共享”分开的例子。

先数对象，再数访问者

原图名字对象有几份谁能够访问
ptr普通全局指针一份。主线程赋值；工作线程读取。
msgs主线程这次调用中的数组一份。主线程初始化；工作线程通过 ptr 间接访问。
myid每次工作线程函数调用各一份。原例中只由对应线程使用。
cnt局部 static 对象一份。所有调用共享它；static 不等于每线程一份。
寄存器、栈指针各线程有自己的执行上下文。线程切换要保存和恢复；栈所处内存仍在进程地址空间里。

这里讨论普通全局、静态与自动变量，没有把 C 的线程局部存储（thread-local storage，TLS）_Thread_local 混进来。一个对象可被多个线程访问，也不意味着这些访问已经安全地同步。

共享地址空间，不会自动安排先后关系

共同读只读对象

初始化和发布完成后，多个线程读取不再变化的对象，可以不争抢写权限。

至少一方会写

检查是否存在冲突访问，以及锁、原子操作等同步是否建立了需要的顺序。

对象必须仍然存在

地址看起来没变，也可能已经指向结束生命期的栈对象或已释放的堆块。

原图还有两处不能当成正确范例：++cnt 没有同步；主线程用 pthread_exit 结束后，其他线程仍引用其栈上的 msgs，不能依赖该栈内容继续有效。此处依据 pthread_exit(3) 的线程栈生命期说明。

把对象活到什么时候写进代码结构

/* 伴读片段：省略错误分支；worker 只读取各自的参数 */
struct job { int id; const char *message; };
struct job jobs[2] = {{0, "foo"}, {1, "bar"}};
pthread_t tids[2];
for (int i = 0; i < 2; ++i)
    Pthread_create(&tids[i], NULL, worker, &jobs[i]);
for (int i = 0; i < 2; ++i)
    Pthread_join(tids[i], NULL);
/* 直到两个线程结束，main 才离开 jobs 所在的作用域。 */

每个参数先初始化，再创建对应线程；之后主线程不修改这些参数。join 让主线程等到读取者结束，再离开作用域。这样同时明确了对象的身份、访问方式和生命期。这个片段省去了共享计数器；若仍要累计次数，必须另外同步 ++cnt，printf 的内部锁不能代替它。

回到“哪些对象被共享”：看清同一个对象以后，才有办法判断两次操作是否冲突。下一课把一次加一拆成读取、计算和写回。
