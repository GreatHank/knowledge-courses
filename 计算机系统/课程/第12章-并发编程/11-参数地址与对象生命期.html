创建四个线程，为什么打印了重复编号？

关键是第 13 行的 &i。传入的是同一个循环变量的地址，不是创建当时 i 的快照。主线程下一次修改 i 时，工作线程可能还没执行第 22 行的解引用（dereference）。

一次可能的先后关系参数对象发生什么
主线程 i = 0，创建 A，传入 &i。A 尚未读取；地址指向 main 的 i。
主线程将 i 改成 1，又创建 B。仍然是同一个地址、同一个对象。
A、B 随后才读取。两次读取可能看到同一个较晚的值。

这个顺序用于说明错误原因；真实 C 代码还有未同步读写 i 的数据竞争，因此不能据此限定所有可能输出。书中一趟运行的具体打印结果也不是固定规律。

join 在最后，不能把此前的读取变成快照

最后 join 所有线程只能确保它们结束之后主线程再继续，不能撤销此前循环对 i 的覆盖。加 sleep 同样没有建立可靠的先后关系。即使用原子变量消除对 i 的数据竞争，反复传同一个地址也未必满足“每个线程拿到不同编号”这个业务要求。

这里要区分：数据竞争（data race）是内存模型里的冲突访问问题；竞态条件（race condition）是正确性依赖未保证的执行先后。没有数据竞争，不代表业务顺序就一定正确。

每个线程得到自己的参数对象

主线程每次分配一个独立的 int 对象，写好编号，再传给对应线程。worker 先读到自己的 myid，再 free 原参数块。此后它使用 myid，不再访问已释放的内存。

动作谁负责不能提前做什么
分配并初始化主线程。不能先 create 再填值，让 worker 看到未准备的内容。
读取并释放参数成功接手的 worker。主线程不能在 create 返回后立刻 free，worker 可能还没读。
创建失败仍由主线程处理。没有 worker 接手时，不能遗忘参数块；还要处理相应资源。

也可以用数组，前提是数组活得足够久

/* 伴读片段：与第 4 课的生命期安排相同 */
int ids[N];
pthread_t tids[N];
for (int i = 0; i < N; ++i) {
    ids[i] = i;
    Pthread_create(&tids[i], NULL, worker, &ids[i]);
}
for (int i = 0; i < N; ++i)
    Pthread_join(tids[i], NULL);
/* worker 只读取 ids 中自己的元素，不 free 这些栈对象。 */

每个 ids[i] 都是不同对象；写好后不再改，数组所在作用域一直持续到所有读取者结束。数组方案不需要逐个分配堆块，但不能让函数提前返回，再期待后台线程继续用这些地址。

参数修正以后，打印仍不保证 0、1、2、3 的顺序；正确要求是每个线程拿到自己的编号。如果确实需要按编号输出，还得另行安排顺序。

回到连接交接

线程版服务器里的 connfdp，正是为每个连接独立分配的参数块。线程池则把描述符值复制进受同步保护的队列。两种方式都必须明确：值何时准备好，谁可以读取，谁最终释放参数和连接。

参数与生命期（lifetime）已经明确，线程还可能因等待关系出错。最后一课检查：所有人都在等时，究竟谁还有机会产生被等待的条件？
