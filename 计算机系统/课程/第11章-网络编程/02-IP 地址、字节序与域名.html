同一个 IPv4 地址有两种常见写法

教材使用 128.2.194.242 演示 IPv4。点之间的四个数分别表示一个 8 位字节；合在一起是 32 位地址。以下是同一组位的不同显示方式。

字节位置十进制十六进制
第 1 字节12880
第 2 字节202
第 3 字节194C2
第 4 字节242F2

点分十进制（dotted-decimal notation）是便于人阅读的文本；struct in_addr 保存的是地址值。IPv6 使用 128 位地址，后面用 getaddrinfo 处理不同地址族（address family）；不能把这里的四字节结构推广到所有 IP。

网络字节序约定了哪一个字节在前

取端口 8000，它的十六进制值是 0x1F40。在教材的 x86-64 小端主机中，一个主机序的 16 位整数按地址从低到高存为 40 1F；网络字段约定高位字节在前，应该是 1F 40。

htons / ntohs

在主机字节序和网络字节序（network byte order）之间转换 16 位量；常用于端口。

htonl / ntohl

转换 32 位量，不能按本机 C 的 long 大小推断。

只转换规定的字段

sockaddr_in 的端口和 IPv4 地址用网络序；sin_family 使用主机的地址族值。

图中 sin_zero 是这个 IPv4 结构的填充。把指针转成 struct sockaddr * 是适配通用接口的参数类型，不会自动改字节序，也不会把 IPv4 变成 IPv6。

数字文本转换不需要 DNS

struct in_addr addr;
int rc = inet_pton(AF_INET, "128.2.194.242", &addr);
if (rc == 1) {
    char text[INET_ADDRSTRLEN];
    if (inet_ntop(AF_INET, &addr, text, sizeof text) == NULL)
        perror("inet_ntop");
    else
        printf("%s\n", text);
} else if (rc == 0) {
    fprintf(stderr, "invalid IPv4 text\n");
} else {
    perror("inet_pton");
}

这是伴读片段，需相应头文件并放入函数中。inet_pton 成功时返回 1，非法文本返回 0，不支持的地址族等错误返回 -1。它已经生成网络字节序的地址，不要再对结果重复 htonl。inet_ntop 做反向的显示转换；二者都不会把普通域名查询成 IP。

名字为什么还需要一层查询

从图上方的根向下看，edu → cmu → cs → … 逐层细分名字空间；写成域名时，最具体的部分在左。图中地址是教材示例，不是今天的连通性记录。

关系实际含义
一个名字 → 多个地址同一服务可以给出多个可尝试的地址。
多个名字 → 一个地址不同名字可以指向相同地址，名字与地址并非一一对应。
查询成功 → 候选地址说明取得了地址信息，不保证目标服务正在监听或连接一定成功。

域名系统（Domain Name System，DNS）用分布式数据库组织名字与地址等记录。程序通常调用系统名字解析接口，解析结果也可能来自本机 hosts 等配置；因此“调用 getaddrinfo”不能直接等同于“发出了一次 DNS 网络查询”。这个接口在第 4 课展开。

从一台主机继续找到一个服务

IP 地址还不足以区分同一台主机上的多个网络服务。端口加入后组成一个端点（endpoint）；TCP 连接再用两端的地址和端口区分。回到总图的“地址、端口与名字 → 套接字与连接”，下一课观察服务器为什么同时需要两个描述符。
