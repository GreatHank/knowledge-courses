主循环只负责一条连接的来去

先看第 29 行：监听入口只创建一次。循环中 accept 返回 connfd，doit 处理一次事务，再 close(connfd)。如果 doit 一直等请求，主循环就不会进入下一次 accept。

main 管连接

创建入口、接待、调用处理函数、释放连接。

doit 管请求

读取并解析请求，选择静态或动态内容路径。

内容函数管输出

读取文件或启动 CGI，把响应写入同一个 connfd。

沿 doit 的判断走一遍

原图步骤条件／动作接下来
读取请求行得到 method、uri、version。检查是否支持这个方法。
方法检查Tiny 只实现 GET；其他方法走 501 分支。返回错误响应并结束这次处理。
解析 URI 后 stat取得文件类型、大小和权限位。stat 失败时，教材实现返回 404。
静态分支检查普通文件和所有者读位。调用 serve_static。
动态分支检查普通文件和所有者执行位。调用 serve_dynamic。

这是一段简化实现的分派规则。只检查所有者权限位不等于完整的访问授权判断；stat 失败也不总是“文件不存在”。把它们读成 Tiny 的代码行为，不能当作操作系统错误的全部分类。

请求没发完就断开，不能一直等空行

原函数不断读行，直到遇到 \r\n，却没有检查 Rio_readlineb 返回了多少字节。若空行到达前已 EOF，旧缓冲区可能继续被比较，循环没有正确的退出条件。首次读取就 EOF 时，缓冲区甚至还没有有效内容。

下面只修正“读取并寻找首部结束”的基本循环。它限制单行长度并要求 CRLF；不解析首部语义，也没有加入总首部大小或超时管理，不能当作完整 HTTP 解析器。

/* 伴读片段：1 = 找到首部结束，0 = 截断、非法行或读取错误。 */
int discard_headers(rio_t *rp) {
    char line[8192];
    for (;;) {
        ssize_t n = rio_readlineb(rp, line, sizeof line);
        if (n <= 0)
            return 0;
        if (n < 2 || line[n-2] != '\r' || line[n-1] != '\n')
            return 0;
        if (n == 2)
            return 1;
    }
}

请求行（request line）也要检查读取返回值，再检查拆分是否取得三个字段；使用 sscanf 时需要字段宽度上限，不能把任意长的外部文本写入固定数组。正文、首部和错误返回应由同一套协议规则协调处理。

URI 如何变成文件名和参数

请求目标Tiny 选的路径附带参数
/./home.html空
/image.png./image.png空
/cgi-bin/adder?15000&213./cgi-bin/adder15000&213

看第 5 行：原实现用 strstr 查找任意位置的 “cgi-bin”，并没有严格验证目录前缀。静态分支也不会通用地剥离查询字符串，例如 /image.png?x=1 会被拼成带问号的文件名。

这里的 URI（Uniform Resource Identifier，统一资源标识符）用来标识请求的资源。给 URI 加一个点，只是在当前目录下拼路径，并没有完成路径规范化（path normalization）、目录边界检查或百分号解码（percent-decoding）。理解教材这段映射即可；若要接受任意外部请求，这些都是需要另外实现的输入规则。

错误响应也是一次有格式的输出

clienterror 把状态行、首部和解释正文写入连接，让客户端知道请求为什么失败。它同样需要正确的正文长度和缓冲区管理；教材采用的重叠 sprintf 拼接方式与上一课 adder 有相同问题。
