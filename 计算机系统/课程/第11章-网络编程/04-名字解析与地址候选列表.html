查询一次，为什么会得到一串结果

一个名字可能解析出多个地址；同一地址还可能适用于不同的通信方式。getaddrinfo 把可用组合组织成链表（linked list），让调用者逐个尝试。

图中沿 ai_next 向下走，是不同候选；每个节点的 ai_addr 向右指向具体套接字地址。节点本身保存接口参数，ai_addr 指向地址数据，两者不能当成同一个结构。

字段接到哪个调用
ai_family、ai_socktype、ai_protocol作为 socket 的三个参数。
ai_addr、ai_addrlen作为 connect 或 bind 的地址和长度。
ai_next本候选失败后，用它走到下一个。

只查询 TCP 字节流需要的候选

struct addrinfo hints = {0}, *list = NULL;
hints.ai_family = AF_UNSPEC;
hints.ai_socktype = SOCK_STREAM;
int rc = getaddrinfo(host, "8000", &hints, &list);
if (rc != 0) {
    fprintf(stderr, "getaddrinfo: %s\n", gai_strerror(rc));
    /* 结束本次查询；不能继续使用 list。 */
} else {
    /* 在这里逐个尝试候选地址。 */
    freeaddrinfo(list);
}

伴读片段中的 host 由调用者提供。AF_UNSPEC 允许返回适合的地址族（address family），SOCK_STREAM 限制为流式套接字。查询成功后仍要尝试连接；freeaddrinfo 释放整个结果链表及其关联地址，之后不再使用这些指针。

getaddrinfo 通常返回 EAI_* 错误码，用 gai_strerror 解释，不能把所有失败都当成 errno；其中 EAI_SYSTEM 才需要再看底层 errno。依据 getaddrinfo(3)。

服务器查询时为什么有 AI_PASSIVE

设置在本例中的含义
node = NULL，设置 AI_PASSIVE取得可用于绑定本地通配地址的候选，等待进入连接。
node = NULL，不设置 AI_PASSIVE取得本地回环地址的候选。
给出具体 node按给出的名字或地址查询；AI_PASSIVE 不会把它改成任意本地地址。
AI_NUMERICSERVservice 必须是数字端口文本，避免服务名查询。
AI_ADDRCONFIG按本机已配置的地址族筛选；回环地址不计入该判断。

教材助手函数使用 AI_ADDRCONFIG。只有回环配置的环境可能因此少返回候选，不能把这个标志理解成任何环境都必须加的通用修复开关。上表是接口补充，依据同一份 getaddrinfo 手册。

反向显示：把套接字地址写进日志

accept 返回的是二进制地址。getnameinfo 可以把它转成主机和服务字符串；如果只想记录数字地址和数字端口，可设置下面两个标志。

int rc = getnameinfo((struct sockaddr *)&peer, peerlen,
                     hostbuf, sizeof hostbuf,
                     portbuf, sizeof portbuf,
                     NI_NUMERICHOST | NI_NUMERICSERV);
if (rc != 0)
    fprintf(stderr, "getnameinfo: %s\n", gai_strerror(rc));

这个片段假定 peer 已由 accept 成功填入，hostbuf 和 portbuf 是当前作用域内足够大的数组。数字标志避免为显示名字再做反向名字查询。getnameinfo 的输出用于显示，不会替应用建立连接。接口补充见 getnameinfo(3)。
