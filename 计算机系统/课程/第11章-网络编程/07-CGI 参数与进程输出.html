把一次加法放进请求

GET /cgi-bin/adder?15000&213 HTTP/1.0

路径 /cgi-bin/adder 选中程序；问号之后的 15000&213 是这个示例约定的输入。服务器要把两者分开，不能把整个字符串当作一个磁盘文件名。

位置本例中的内容由谁读取
可执行文件路径./cgi-bin/adder服务器交给 execve。
QUERY_STRING 环境变量15000&213adder 用 getenv 取得。
标准输出 stdout响应首部和加法结果正文重定向后经连接送往客户端。

CGI 是公共网关接口（Common Gateway Interface），约定 Web 服务器怎样把请求信息交给外部程序，并接收其输出。这里的数字没有作为 main 的 argv 参数传入。用 & 分隔两数是 adder 的约定，不是所有 CGI 程序通用的参数格式；百分号编码、缺少参数等情况也需要程序按自己的输入规则处理。

从 fork 到 stdout，沿三条作用不同的操作读图

单独打开交互图 · Archify 伴读示意。时序自上而下；虚线返回与实线请求分别标出。

看父进程到子进程的 fork 连线：它让子进程继承连接描述符。接着子进程执行 dup2，把描述符 1 指向连接；execve 替换程序映像，保留这个描述符关系。CGI 的 printf 因此写到连接，不需要父进程把输出再读一遍转发。

Tiny 父进程先发状态行和 Server 首部，CGI 再补其余首部、空行和正文。图特指教材 Tiny 的接线方式；CGI 接口本身不要求所有服务器都把 CGI 的 stdout 直接接到客户端套接字。CGI 响应与服务器处理规则可参见 RFC 3875 §6。

原程序里，哪些行负责输入，哪些行负责输出

第 9–16 行取得并拆开查询字符串（query string）；第 19–24 行试图拼接 HTML；第 27–31 行输出首部、空行、正文并刷新 stdout。先辨认这三段职责，再检查它们的条件。

原图位置需要注意的具体条件
第 10–13 行若找不到 &，p 为 NULL，不能写 *p；strcpy 也没有长度限制。
第 14–15 行atoi 不提供完整的格式与范围检查；相加还要考虑 int 溢出。
第 19–20 行第 20 行覆盖第 19 行刚写入的内容。
第 21–24 行sprintf 的目标 content 同时作为 %s 输入，源与目标重叠，行为未定义。

这些问题来自原图代码本身。课程保留原图用于理解结构，不把它当作健壮的输入处理范本。源目标重叠的限制见 POSIX 格式化输出说明。

把正文构造与发送长度分开

下面是伴读改写片段。前提：两个整数已经完成格式与范围验证，并且它们的和能用 int 表示；这里仅展示构造正文及输出，不替代完整的查询字符串解析。

char body[128];
int n = snprintf(body, sizeof body,
                 "<p>%d + %d = %d</p>\r\n", n1, n2, n1 + n2);
if (n < 0 || (size_t)n >= sizeof body) {
    /* 构造失败或被截断：交给调用者处理。 */
    return 1;
}
if (printf("Content-Type: text/html\r\n"
           "Content-Length: %zu\r\n\r\n%s",
           (size_t)n, body) < 0 || fflush(stdout) == EOF)
    return 1;

这里的 n 是正文实际需要的字节数，不包含末尾 NUL。先判断没有截断，再把 n 写进 Content-Length。printf 的固定格式与 body 分开，正文不会被当作格式字符串（format string）解释。状态行由本例的 Tiny 先前输出。

fork 了，为什么 Tiny 仍不能同时服务多个请求

看图最后子进程返回父进程的线：父进程在 wait 中等待 CGI 退出，然后才结束这次处理、关闭连接并回主循环。创建子进程本身不等于并发服务器；还要看父进程是否继续接待其他请求。
