静态内容：响应首部和文件正文分开写

先看上半部分第 8–13 行：Tiny 发送状态行、Connection、Content-Length 和 Content-Type。第 18 行以后才准备正文。首部是程序构造的文本，正文来自文件的原始字节；图片里即使含有 NUL，也要按文件大小发送。

原图操作持有的资源如何变化为什么这样做
open取得文件描述符 srcfd。让进程能够访问文件。
mmap建立指向文件内容的地址映射 srcp。把文件内容作为一段内存访问。
close(srcfd)关闭描述符；已有映射仍然有效。映射的生命期不依赖这份描述符继续打开。
rio_writen(fd, srcp, filesize)把指定字节数交给连接写接口。不能用 strlen 计算二进制文件长度。
munmap移除这段映射。释放该虚拟地址区间。

两种“释放”对应不同资源

close

释放进程的一份描述符引用；忘记关闭会积累描述符。

munmap

移除虚拟地址映射；关闭文件描述符不会代替这一步。

close(connfd)

结束本次处理持有的连接引用；监听描述符（listening descriptor）另行保留。

原书在这里用“内存泄漏（memory leak）”描述未关闭描述符的后果，伴读将它明确称为描述符泄漏（descriptor leak），以免和堆内存、映射空间混淆。三类资源都需要管理，但释放方式不同。

教材代码的 filesize 参数是 int，而 stat 的 st_size 通常是 off_t；大文件不能假定转换无损。空文件也不能直接照搬长度为 0 的 mmap；Linux 要求映射长度大于 0，见 mmap(2)。下半图 get_filetype 只是用 strstr 查找几个字符串，不是完整的媒体类型识别规则。

动态内容：把前一课的时序放回函数

第 6–9 行先写状态行与 Server 首部。fork 后，子进程设置环境变量、dup2(fd, STDOUT_FILENO)、execve；父进程走到第 17 行 Wait。这里的 Wait 是教材包装，底层等待子进程退出。

对子进程来说，execve 替换了正在执行的程序，连接描述符却仍可使用；对父进程来说，等待结束前不会回到主循环接待下一位。可以回看 第 7 课的 CGI 时序图，沿“子进程 → 浏览器”那两条线确认正文的去向。

Tiny 已经发送 200 后，CGI 若再失败，不能把已发送的状态行收回来改成另一个状态。实际程序需要安排好确认成功、发出首部和处理错误的先后关系。

对端消失时，错误不按固定次数出现

网络连接可能在读写过程中失败。对一个已经不可写的连接发送数据，Linux 可能返回 EPIPE 并产生 SIGPIPE；其他状态也可能得到 ECONNRESET 等错误。不能把教材关于“第一次写、第二次写”的示例顺序当成每次都成立的规律。

处理或抑制 SIGPIPE 只是不让默认信号动作终止进程，写操作的失败仍必须检查。已写出的部分也不会回滚；是否重试、是否重新连接，要由应用协议决定。接口依据：send(2)。

现象程序需要区分
read 返回正数得到的只是这次读取结果，可能仍缺后续消息字节。
read 返回 0正常接收方向 EOF；还要核对消息是否完整。
read / write 返回 -1按错误码处理，不能继续把缓冲区当成成功结果。
write 成功数据已交给本机写接口，不等于对方业务处理成功。
