同一个文件，怎样变成一次正在发生的执行？

linux> ./hello
hello, world
linux>

这三行看起来紧挨着，背后却有命令解释、建立运行环境、取指执行、输出、结束。先沿图的绿色箭头跟一次运行，再看灰色箭头中代码和数据的去向。

单独打开、放大或导出此图 · Archify 伴读重组图；核心关系直接显示，节点可展开补充。

上面是“谁让下一件事发生”，下面是“执行所需的信息从哪里来”。两条线在 CPU 执行处相遇；它们不是两次独立的运行。

shell：接收命令的人

shell 是命令解释程序，本身也要运行。./hello 指定当前目录中的 hello；shell 请求操作系统启动它。

操作系统：建立运行条件

内核参与准备地址空间、装载与安排执行。程序从启动代码开始，随后进入 main；启动细节留到进程与链接章节。

这是前台命令的简化路径。shell 启动外部程序所需的进程创建与 exec 细节未展开；也不表示内核在一条机器指令之后，才把整个文件一次性装完。

先认清原书硬件图中的四个角色

CPU：执行指令

图左上角。PC 保存指令地址；寄存器保存少量工作信息；ALU 执行算术和逻辑操作。

主存：正在使用的代码与数据

图右侧 Main memory。程序运行时需要的指令和数据通过存储系统供 CPU 使用。

I/O：与外部交换信息

图下方的磁盘、键盘与显示设备。它们通过控制器或适配器接入系统。

总线：传输信息的通道

图中的宽灰线连接各部件。这里强调传输关系；主存、CPU 和设备各有不同职责。

定位右下角磁盘中的 hello executable：它仍是一个保存着代码和数据的文件。接下来才是让其中的指令参与执行。

放大两次搬运：装入，然后输出

① 磁盘 → 主存

磁盘保存的机器代码和字符串进入主存。教材用 DMA（直接内存访问）说明：数据可由设备传到主存，不必每个字节都经 CPU 寄存器中转。

CPU 与操作系统仍参与发起和管理传输；“直接”描述的是数据搬运路径。

② 主存中的字符串 → 显示输出

CPU 执行输出相关指令，把字符串送入输出路径。实际程序通过库函数和操作系统 I/O 服务完成输出；图把软件层次暂时省略了。

hello, world 来自程序的数据。CPU 此刻执行的是机器指令，不是在现场重新翻译 hello.c。

CPU 负责执行并协调许多操作；数据的每一次移动，并不都等于 CPU 逐字节亲自复制。

“执行指令”可以先理解到什么程度？

假设内存中的 x 当前为 2，要实现 x = x + 3。下面是把效果拆开的教学模型，R 代表一个寄存器。

动作CPU 内的 R内存中的 x发生的变化
开始尚未使用2数值在内存里
Load：取数22把 x 的值取到 R
Operate：加 352运算结果先在寄存器中
Store：存回55把结果写回 x

这是操作效果的分解，不是实际 x86-64 汇编，也不承诺编译器会生成恰好三条指令。

PC 决定去哪里取指令

CPU 取出并解释指令，完成它要求的操作，然后继续。通常转到后续指令；跳转指令则改变接下来执行的位置。

“下一条”不等于地址简单加 1；x86-64 指令长度并不固定。

指令效果与内部实现分开看

ISA（指令集体系结构）规定软件能依赖的指令行为。微体系结构解释处理器内部怎样实现这些行为。

本轮按顺序讲指令效果。真实处理器可以重叠处理多条指令，第 4–5 章再深入。

回到局部图的右上角：“hello 的指令在 CPU 上执行”现在可以拆成取指、操作寄存器或内存、改变控制位置。执行需要持续获得信息，因而 CPU 再快，也会受到数据供应速度的影响。

把这一段放回章节图

文件：保存了什么

可执行文件是静态内容；程序结束后，它仍可留在磁盘中。

进程：这一次运行

进程包含执行状态与运行资源。同一个文件可以被多次运行，形成不同的进程。
