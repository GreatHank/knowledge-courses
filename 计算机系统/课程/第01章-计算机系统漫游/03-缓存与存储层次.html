缓存与存储层次

CPU 在等什么，缓存又帮了什么忙？

章节图位置：CPU 与“缓存／主存／存储”之间的联系。这是运行期间持续发生的配合，不是执行完 CPU 阶段后才进入存储阶段。

上一页的搬运，可能比计算更费时间

CPU 做加法前要取得操作数，取指时要取得指令字节。存储系统（memory system）供应不及时，CPU 的计算能力就无法充分发挥。

往上看：快，但空间有限

靠近 CPU 的存储通常更小、更快、单位容量更贵。不能简单用同样成本把所有数据都放进最快的一层。

往下看：大，但取得更慢

较低层提供较大的容量，较高层保存有用内容的副本，让尽可能多的访问能在较高层完成。

缓存（cache）把可能再次使用的信息留在更快的一层，减少从较慢层重复读取的次数。

这是一种层次组织示例。图中的 L0–L6 是整张层次图的层级编号；不能把 “L4 主存”误读为所有机器都配备了“L4 CPU 缓存”。

放大一次读取：命中与未命中

单独打开、放大或导出此图 · Archify 伴读重组图；核心关系直接显示，节点可展开补充。

先走横向绿线：命中 hit

当前缓存已有所需内容，就可以直接从这一层读取，无需再沿图中向下的路径查找。

再走向下紫线：未命中 miss

这一层没有，需要向下一层取回包含目标内容的块（block），并放入缓存。下一层可能仍是缓存，也可能是主存。

看右下角“取回一块”：传输单位通常大于本次所需的一个值。所以刚访问某个位置后，附近内容也可能已在缓存里。

L1 未命中 ≠ 必须读磁盘。未命中只说明“当前这一层没有”；后续要看下一层是否能提供。

图示一次读取的基本模型，省略替换、写入策略和实际时序优化。块传输与命中／未命中细节回查 §6.3.1，PDF 第 649 页（印刷页 648）。

为什么“留下一块”经常有用？先看数组

int a[8] = {2, 4, 6, 8, 10, 12, 14, 16};
int sum = 0;
for (int i = 0; i < 8; i++)
    sum += a[i];

这里只需跟着下标看：程序依次访问 a[0]、a[1]、a[2]……数组元素连续排列，因此一次取来的邻近数据，有机会很快用上。

教学假设：一块恰好放 4 个整数，a[0] 位于块开头；开始时不在缓存中，中途不被替换。

空间局部性 · spatial locality

刚访问一个位置，接下来很可能访问附近位置。上面连续走过数组，就是直观例子。

时间局部性 · temporal locality

刚使用的信息，短时间内很可能再次使用。循环体的指令会重复执行，就是一个例子。

表格只解释机制，不是实际硬件的缓存行大小或本机测量结果。sum 可能保存在寄存器里，不能仅凭 C 源码断言每轮都读写其内存位置。

回看缓存图：局部性（locality）回答的是“已经填入的块，之后是否有用”。不同程序从缓存中得到的收益并不相同，访问哪些位置、能否重复使用数据，以及工作数据有多大，都会影响结果。

四个容易混在一起的词

位置先抓住的角色此刻怎样与程序关联
寄存器 registersCPU 内的少量工作位置机器指令直接指定使用哪些寄存器
CPU 缓存 caches保存较低存储层内容的副本基本命中、取块通常由硬件处理；程序的访问方式影响效果
主存 main memory运行时的主要内存容量保存正在使用的代码与数据，通常由 DRAM 构成
磁盘等持久存储长期保存文件可执行文件保存于此；相应内容在需要时进入内存体系
