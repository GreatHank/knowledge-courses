读取 8 个元素只发生 2 次缺失，缺失率（miss rate） 1/4。程序即使从不重读某个元素，仍然充分利用了每次搬运的邻近数据。

对足够长的单次顺序扫描，元素宽 w、元素步长 k、块大小 B 时，教材给出近似每次访问缺失数 min(1, wk/B)。它描述这种规则、冷缓存、无干扰的流式模型；短数组、边界不对齐、跨块元素或预热状态都需要按具体地址重新数。

第几次字节地址内存块号组结果替换的块

演示按给定的缓存规则计算：冷缓存起步，只读、无预取、无其他程序干扰。它显示块的地址范围，不模拟数据值和 CPU 周期。

这里的数组占 64 B，每个元素占 4 B，每行正好一块（16 B）。32 B 直接映射缓存只有 2 组。按行访问，一块装入后连续读完四个元素：16 次读取中 4 次缺失。

按列访问时，第一列的四次读取依次落到组 0, 1, 0, 1。等下一列想复用第 0 行的块，它已经被第 2 行挤掉；第 1 行也被第 3 行挤掉。因此这个具体配置下 16 次全缺失。

切换到 64 B 缓存，四个行块能分别保留在四组里。按列访问也只在首次触及每个行块时缺失，共 4 次。访问顺序没变，留住数据的条件变了。

“按列一定每次缺失”不是普遍规律。需要检查步长（stride）、行块数量、组映射以及两次复用之间的访问。

调整内层循环，先检查结果是否保持

/* a 是 C 的连续二维数组；uint32_t 元素。 */
uint32_t sum = 0;
for (size_t i = 0; i < 4; ++i)
    for (size_t j = 0; j < 4; ++j)
        sum += a[i][j];

内层 j 变化，沿一行顺序读。改循环次序之前，必须确认不存在“本次迭代依赖上次写入”的关系；否则顺序可能属于算法本身。

本例用无符号求和，交换求和顺序仍得到相同模 2³² 的结果。浮点累加通常不满足结合律，重排后需要按结果精度要求验证。不能因为两段循环都访问同样的元素，就推断所有类型下结果逐位相同。

结构体中顺手把需要的字段用完

struct point { uint32_t x, y; };
/* p 指向有效数组，n 是元素数。 */
uint32_t sx = 0, sy = 0;
for (size_t i = 0; i < n; ++i) {
    sx += p[i].x;
    sy += p[i].y;
}

教材练习 6.18–6.20 比较了相似的结构体遍历。如果 x、y 相邻并已随同一个块进入缓存，在当前元素上连续使用二者，可以避免“先扫完所有 x，等块被淘汰后再扫所有 y”造成的重复搬运。

如果一个热点循环只用 x，另一种按字段分别存放的布局也值得比较，因为它可能少搬入无用的 y。选择依赖实际访问方式和结构布局，不存在对所有程序都更好的统一答案。

把局部性判断放进第 5 章的优化过程

先确认耗时确实集中在这个循环，再写出它访问的地址序列，估计哪些字节同块、哪些块会复用。候选改动可以是交换合法的循环次序、合并字段使用，或者缩短两次复用之间的间隔。

缺失次数减少只是机制上的解释。最终还要测量：编译器可能改变访存次数，预取（prefetching）可能提前搬入，计算依赖可能成为新瓶颈。下一课用教材的存储器山看访问模式与实际吞吐量的关系。
