同一变量写三次，是否每次都向下传？

假设某块已在缓存里，程序连续把其中的值改为 1、2、3。当前缓存都要接收这些修改；差别是下一级何时得到更新。

直写 write-through

每次写命中都把更新传到下一级，产生相应写流量。真实系统可以配合写缓冲，所以“向下传播”不等于 CPU 必须等外部传输全部完成。

写回 write-back

先修改缓存中的副本，并置脏位 dirty。教材模型在该块被替换时才写回；若中间一直保留，三次修改可能合并为一次最终块写回。

dirty 表示缓存块相对下一级已修改，不表示数据损坏。valid 只说明该行有可用内容。一个块可以 valid = 1、dirty = 0，也可以 valid = 1、dirty = 1。

先看一次脏块被替换的交互

从第一条“写 A：命中”看起，当前缓存更新 A 并置 dirty。第二个请求读 B，假设目标组已满，策略选择 A 的块作为牺牲块；在重用这个位置前，必须保留 A 的修改。

因此图中出现“写回 A 的脏块（dirty block）”，然后装入 B。若 A 没改过，这次替换不需要写回。图把动作排成串行顺序便于追踪副本；真实硬件可以用缓冲重叠部分传输。

写未命中，还要决定是否把块搬上来

独立的问题策略一策略二
写命中后，下一级何时更新？直写：传播这次更新写回：标脏，延后写回
写未命中后，当前层是否分配行？写分配 write-allocate：取来块后修改不写分配 no-write-allocate：绕过当前层向下写

这两组策略不是同一维度。教材说明常见搭配是“写回 + 写分配（write allocate）”和“直写 + 不写分配”，但不是定义上的强制绑定；教材练习 6.17 就给出了直写配合写分配的模型。

写分配使“连续写一个块的多个位置”也能从空间局部性受益，但第一次写未命中可能先引入一次读入。分析写循环时，只数源代码中的 store 次数会漏掉这部分传输。

这里讨论单个缓存层与下一级的副本更新，不展开多核缓存一致性协议；dirty 规则本身也不是掉电持久化保证。

多级缓存把不同的代价放在不同位置

先沿单个核心的两条 L1 分支看：指令缓存和数据缓存分开，可以服务不同访问；再向下到统一的 L2 和共享 L3。本图描述教材选定的 Core i7 组织，不能推广为所有 CPU 的结构。

用表中 L1 d-cache 核对公式：64 组 × 8 行/组 × 64 B/行 = 32768 B = 32 KiB。增加容量、块大小或相联度，各自改变的东西不同。

改动可能的收益需要付出的代价
增大 C容纳更大的工作集较大的结构可能增加命中时间
固定 C 增大 B一次装入更多邻近字节行数减少，带入无用字节，传输更久
固定 C、B 增大 E缓解受组限制的冲突标记比较、选择与替换逻辑更复杂

命中率必须连着时间一起读

缺失率 = 缺失次数 / 访问次数；命中时间（hit time）是一次命中取得数据的时间；缺失惩罚（miss penalty）是由于未命中额外付出的时间。为把这三者联系起来，可以写一个串行、单级的平均模型：

平均访问时间 = 命中时间 + 缺失率 × 额外缺失惩罚

例如设命中时间 1 ns、额外缺失惩罚 50 ns。命中率 99% 时平均 1.5 ns；命中率 97% 时平均 2.5 ns。这是伴读自定参数的算例，说明少量缺失也可能有明显代价。

多级时要说清分母：L2 的局部缺失率以“到达 L2 的访问”为分母。如果 L1 缺失率 10%，到达 L2 的请求又有 20% 缺失，则两级都未命中的请求占最初请求的 2%。实际 CPU 会重叠计算与访存，不能用这个串行模型直接预测整个程序的运行时间。
