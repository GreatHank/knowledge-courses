先固定一个结果元素，看三个下标的职责

C[i][j] = Σk=0…n−1 A[i][k] × B[k][j]

i 选 A 的一行，j 选 B 的一列，k 沿这行和这列配对。下面是伴读写法：A、B、C 是互不重叠的 n × n double 数组，n 为正，索引与存储都有效。

for (size_t i = 0; i < n; ++i) {
    for (size_t j = 0; j < n; ++j) {
        double sum = 0.0;
        for (size_t k = 0; k < n; ++k)
            sum += A[i][k] * B[k][j];
        C[i][j] = sum;
    }
}
k 在内层变化时地址怎样变化复用位置
A[i][k]沿 A 的一行，每次前进 8 B同一块的后续元素
B[k][j]沿 B 的一列，每次跨 8n B下一列可能再用到，但已经隔了很多访问
sum反复更新一个局部值可放在寄存器；C 在内循环后才写

观察地址步长比只数加法乘法更能解释两种读取的差别。

把 j 放到最内层，就能同时顺着 B 和 C 走

/* 先把 C 的所有元素置为 0.0。 */
for (size_t i = 0; i < n; ++i)
    for (size_t j = 0; j < n; ++j)
        C[i][j] = 0.0;

for (size_t i = 0; i < n; ++i) {
    for (size_t k = 0; k < n; ++k) {
        double r = A[i][k];
        for (size_t j = 0; j < n; ++j)
            C[i][j] += r * B[k][j];
    }
}

此时固定 i、k，r 作为一个局部值反复使用，B[k][j] 和 C[i][j] 都按行连续访问。代价是 C 在内层每次都要读和写；收益是减少跨大步长访问造成的缺失。

初始化不能省略，否则 += 会把未准备好的旧值算进去。上面两段伴读代码都以计算 C = AB 为目标；原图 6.44 使用 C += …，需要按教材实验对 C 的初始状态理解，不能把两种形式不加说明地拼在一起。

浮点运算的逐位结果还受累积顺序、舍入、融合乘加和编译选项影响。即使数学表达式相同，也应按数值要求验证；这延续第 5 章的正确性边界。

六种次序，按内层实际访问的数组分组

这张表采用 double = 8 B、块 = 32 B、矩阵一行大到放不进 L1、局部量放寄存器等简化条件。先看每块能容纳 4 个 double：

内层访问类内层 load / store缺失次数怎样得到
AB：ijk、jik2 / 0A 顺行约 0.25；B 跨列约 1；合计 1.25 次/迭代
AC：jki、kji2 / 1A、C 都跨列，各约 1；合计 2 次/迭代
BC：kij、ikj2 / 1B、C 都顺行，各约 0.25；合计 0.5 次/迭代

同一次迭代对 C 先读后写：若读已把块取来，紧接着的写会命中，表中没有机械地再加一次写缺失。AB 类把 C 的操作移到了内循环之外，表里的“0 stores”也不是整个矩阵乘法从不写 C。

这份简化分析没有逐一模拟真实地址冲突和预取。1.25、2、0.5 都是缺失次数/迭代，数值大于 1 完全可能；不能把 1.25 直接叫作 125% 的缺失率。

再看实验图，确认趋势是否出现

沿最下方的 kij、ikj 曲线看，较大的 n 下仍保持较低的每迭代周期数。它们每轮的访存操作比 AB 类更多，却受益于更好的访问顺序。仅数 load/store 条数不足以预测耗时。

图里最快和最慢版本在较大 n 时差距接近 40 倍，这是教材平台、编译与实验条件下的结果。本课没有在本机复测，也不保证任意矩阵、编译器和处理器会出现同样倍率。

分块让复用发生在数据离开缓存以前

若大矩阵整体放不下，可以把计算组织成若干小区域，让一个区域的数据装入后被多次使用，再转向下一块。这里的 tile/block 是算法划分的数据区域，通常包含许多缓存行，不是硬件的一条 cache line。

要改变什么循环重排分块 blocking
主要针对让内层地址步长更小缩短同一批数据两次使用之间的距离
典型效果用完一个缓存块里的邻近元素在小工作集留在缓存时反复利用它
需要核对依赖、数值顺序、编译后访问块边界、尾部、容量、组冲突及额外控制开销

若某个方案同时保留 A、B、C 三个 b × b 的 double 区域，光数据就约需 3 × b² × 8 B。b = 16 时是 6144 B，b = 32 时是 24576 B。这只是容量预算，不能据此保证它们一定留在某一级缓存：地址映射、其他数据和预取仍会影响效果。

§6.6.2 的 Web Aside 提到分块（blocking），并报告其特定 Core i7 矩阵实验没有因此改善性能，讨论了预取的影响。这个结论不能推广成“所有 Core i7 上分块都无用”。使用分块前，仍需检查访问模式并在目标系统上测量。

回到章节总图：怎样解释一个变慢的循环？

从“访问顺序”节点出发，把下标变成地址步长；到“地址与查找”节点，判断哪些块能同时留下；再到“命中时间与缺失代价”，区分少量昂贵缺失和大量便宜命中。最后用测量核对，并保留第 5 章的正确性检查。
