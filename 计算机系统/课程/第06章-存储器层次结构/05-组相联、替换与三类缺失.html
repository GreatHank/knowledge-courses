0 和 8 为什么互相挤掉？

沿用上一课 B = 2、S = 4、E = 1 的模型。地址 0 属于块 0，地址 8 属于块 4，两者组索引都是 0。反复读取 0, 8, 0, 8, 0, 8，组 0 的那一行会反复被替换。

第几次字节地址内存块号组结果替换的块

演示按给定的缓存规则计算：冷缓存起步，只读、无预取、无其他程序干扰。它显示块的地址范围，不模拟数据值和 CPU 周期。

切换为“两路组相联”时，总数据容量仍是 8 B，块大小仍是 2 B。每组放两行，组数从 4 变成 2，即 C = 2 × 2 × 2。这两个块仍落在同一组，但可以同时留下：前两次冷缺失，后四次命中。

这里比较的是固定 C 和 B、改变 E 的两种组织，不能一边把每组行数翻倍，一边保持组数不变，再把收益全归因于相联度。

地址选的是组，不是组内的“第几路”

看原图的 Selected set：箭头落在整个组上。随后要比较该组内各个有效行的 tag。地址中没有另一个字段直接告诉你“在第 0 路”还是“在第 1 路”；一个块在哪一路，取决于装入和替换过程。

组织S、E 的条件查找与代价
直接映射E = 1只比较选中组的一行，位置最受限
E 路组相联1 < E < C/B比较选中组的 E 行，缓解冲突
全相联S = 1，E = C/B整缓存是一个组，无组索引位；并行比较更多标记

相联度（associativity）提高会增加比较和选择逻辑，可能影响命中时间及成本。全相联也不能消除容量限制和第一次访问的冷缺失。

放哪里与换谁，是两个决定

放置规则（placement policy）先决定新块允许进入哪一组；只有这个组内没有空行时，才需要替换策略（replacement policy）挑一个牺牲块。LRU（least recently used）选择最久没有被访问的行；LFU（least frequently used，最不经常使用）看使用频率，含义不同：前者问“上次何时用”，后者问“用了多少次”。

把演示切到 LRU：读取 0, 4, 0, 8, 4。前两次把块 0、2 放入组 0；再次读 0，使块 0 成为最近使用。读 8 时，最久没用的是块 2，所以换出 2。最后读 4 又缺失，并换出此时更旧的块 0。

命中也会更新最近使用顺序。演示采用精确 LRU 作为教学规则，不声称教材参考 CPU 的所有缓存都实现完全相同的替换算法。

三类缺失回答“为什么没有留下”

类型辨认用的情形能改善什么
冷缺失 compulsory第一次访问此前从未装入的块空间局部性让同块后续访问受益；增大总容量不能消除这些首次装入
冲突缺失 conflict工作集能放入同容量的全相联缓存，却被组映射限制挤掉改变布局、错开地址或增加相联度可能有帮助
容量缺失 capacity即便允许任意放置，工作集仍超过缓存可保留的范围缩小同时需要的工作集，或让复用发生得更早

一个访问序列里可以出现多种缺失。不能仅凭“tag 不匹配”就给缺失分类：tag 比较是检测机制，三类缺失是在解释访问历史。初次读 8 仍是冷缺失，即使它同时挤掉了 0。

教材的两个数组：空间局部性好，也可能互相冲突

§6.4.2 的点积使用两个 8 元素 float 数组，x 从地址 0 开始，y 从地址 32 开始；B = 16、S = 2、E = 1。交替读 x[i] 和 y[i] 时，两者对应块落到同一组，造成反复装入和淘汰，称为 thrashing。

教材假设在 x 后填充 16 B，使 y 改从 48 开始，两者当前块就可以落到不同组。这个例子的首次扫描变成 16 次数组读取、4 次缺失。效果依赖已知地址和缓存参数；普通 C 的两个独立数组并不保证恰好相邻，不能只改声明就保证实际地址按图排列。

回到章节图：“局部性”提供复用机会，“地址与查找”决定这些机会能否变成命中。两者要一起看。
