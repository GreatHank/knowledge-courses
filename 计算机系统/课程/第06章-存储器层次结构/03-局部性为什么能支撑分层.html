局部性为什么能支撑分层

容量有限的缓存，凭什么能让大程序经常读到快存储？

同一个求和循环里，两种复用不同

uint32_t sum = 0;
for (size_t i = 0; i < n; ++i)
    sum += v[i];

sum：同一个值反复参与计算

这是时间局部性（temporal locality）：刚用过的对象，很快还会再用。编译器往往能把这个局部累积值留在寄存器里，因此源码中的重复使用未必产生反复访存。

v：这次用过的邻居接着被访问

这是空间局部性（spatial locality）：访问 v[0] 后很快访问 v[1]。每个元素只读一次也能有很好的空间局部性，却不因此具有元素自身的时间复用。

本例是伴读改写，假设 v 是至少有 n 个有效元素的 uint32_t 数组，n 的类型为 size_t。用 uint32_t 累加，结果按模 2³² 计算。教材的 int 版本若产生有符号溢出，需要另外处理正确性，不能只讨论速度。

看 C 数组的地址，不只看下标长什么样

上图按行读取，地址是 0, 4, 8, 12, 16, 20。下图按列读取，地址是 0, 12, 4, 16, 8, 20。C 的二维数组按行连续存放，因此改变内层下标会改变地址步长。

对 a[M][N]，元素宽度为 w 字节时，相邻列相差 w，相邻行同一列相差 Nw。教材的 stride-1 指一个元素的步长，不总是一个字节。

循环体的指令也有局部性：顺序执行常读相邻指令，回到循环又复用刚执行过的指令。但指令的局部性好，并不能保证数据访问的局部性也好。

一层存不下全部数据，就保留近期有用的块

先看图中的 L1 与 L2：L1 保存从较低层取得的部分数据块。若下一次还读这一块，便可能在 L1 命中；若读同块中邻近的字节，整块传输也没有白搬。

再看主存与磁盘：缓存的想法延伸到操作系统，但管理者和搬运单位不同。L1–L3 主要由硬件管理，寄存器分配主要由编译器安排，主存与磁盘之间还涉及地址翻译和操作系统。图是层次概念图，不能理解成每条指令都逐层发起一次相同操作。

概念这次访问发生了什么后续可能的收益
命中 hit所需数据已在当前层的有效块里直接从这一层取得
缺失 miss当前层没有所需块，向下一级取块把块留下，供后续复用
替换 eviction目标位置没有空位，移走已有块为新块腾出位置，也可能丢掉仍有用的数据

时间局部性解释“为何留下这个块”；空间局部性解释“为何连附近字节一起搬”。程序访问模式与存储技术的差异共同支撑了层次结构。

工作集大小与映射位置，都会影响能否留下

一个执行阶段经常使用的块集合称为工作集（working set）。工作集太大，缓存可能装不下；即使总量装得下，块也可能争用同一组的位置。下一课先把地址拆开，随后再区分冷缺失、冲突缺失和容量缺失。

本章使用按字节编址的缓存模型。它只回答当前给出的地址怎样映射到缓存；程序的虚拟地址如何变成物理地址，留到第 9 章，不把两套过程混在一起。
