先比较两个“加法”

long   add_i(long a, long b)     { return a + b; }
double add_d(double a, double b) { return a + b; }
教材平台的简单标量调用整数 add_i浮点 add_d
两个参数位置%rdi、%rsi%xmm0、%xmm1
结果位置%rax%xmm0
一种实现指令addq（整数加法）vaddsd（标量 double 加法）
数值规则固定宽度整数运算浮点格式、特殊值与舍入规则

第 2 章解释“浮点位串怎样表示值”，这里解释它们放在哪里、由什么指令处理。本课沿用教材 AVX 风格的指令；不同目标配置可能生成 SSE 等其他等价形式。

XMM 是寄存器宽度；scalar 是本次处理几个数

名字／后缀含义本课关注的部分
%ymmN256 位寄存器可容纳多个值；本课不展开并行向量运算
%xmmN对应 YMM 的低 128 位标量 float 用低 32 位，double 用低 64 位
ssscalar single单个单精度数
sdscalar double单个双精度数
ps / pdpacked single / double可表示成组数据；指令具体用途仍要看操作数

XMM 有 128 位，不代表一次 vaddsd 就做 128 位精度的加法。它处理低 64 位的一个 double，其余位的更新遵循该指令规则。

浮点与整数参数各自排队，指针仍是整数通道

double f(int x, double y, long z);
// x → %edi；y → %xmm0；z → %rsi

float g(float v, float *src, float *dst);
// v → %xmm0；src → %rdi；dst → %rsi
普通标量参数规则对应位置
前 8 个浮点参数%xmm0–%xmm7，依浮点参数出现次序使用
普通浮点返回值%xmm0
超过寄存器可容纳的参数按调用约定放到栈中
XMM 的保存责任本书 Linux/Unix 约定中属于 caller-saved
double*、float*指针本身是地址，按整数／指针参数规则传递

看 f 的第三个形参 z：它是第二个整数通道参数，所以用 %rsi；不能按它在全部参数中排第三，就给它分配 %rdx。此处仍是普通标量（scalar）分类，未覆盖全部聚合或可变参数规则。

搬位与换数值，使用不同指令

目标代表指令做了什么
内存 double → XMMvmovsd (%rdi),%xmm0复制已有浮点表示
long → doublevcvtsi2sdq %rax,%xmm1,%xmm1把整数值转换成 double，可能舍入
double → longvcvttsd2siq %xmm0,%rax向零截断后转成整数；C 层面需结果可表示
double → float相应浮点精度转换指令缩小有效精度，可能舍入或溢出

对 3.75 做数值转换得到整数 3；把 double 的 64 个原始位搬到整数寄存器，得到的会是编码位串，不是数值 3。转换中的 tt 提醒这里采用截断取整。

教材中三操作数的整数转浮点指令，其第二个源操作数会影响结果的其他位。这里跟踪标量数值，只需关注低位的转换结果。NaN、无穷大或超范围浮点转整数，不应当作 C 的正常可移植转换使用。

三个操作数，要特别读清减法和除法的方向

# 自设寄存器数值：%xmm0 低位 = 10.0，%xmm1 低位 = 4.0
vsubsd %xmm1, %xmm0, %xmm2   # xmm2 = 10.0 - 4.0 = 6.0
vdivsd %xmm1, %xmm0, %xmm2   # xmm2 = 10.0 / 4.0 = 2.5
AT&T 三操作数形式标量结果
vaddsd S1,S2,DD ← S2 + S1
vsubsd S1,S2,DD ← S2 − S1
vmulsd S1,S2,DD ← S2 × S1
vdivsd S1,S2,DD ← S2 / S1
# 教材 §3.11.4 的摄氏转华氏机制
vmulsd .LC2(%rip), %xmm0, %xmm0  # 乘内存里的 double 常量 1.8
vaddsd .LC3(%rip), %xmm0, %xmm0  # 加内存里的 double 常量 32.0

这些浮点运算没有“立即数 1.8”这种操作数形式；常量放在内存，按 RIP 相对寻址（RIP-relative addressing）取得。按第 2 章的表示规则，1.8 在 binary64 中是近似值，运算仍需遵循浮点舍入规则。

有些浮点操作还能用位逻辑完成：例如用适当掩码异或符号位实现变号，用掩码清零符号位实现绝对值。这里操作的是浮点表示的位，不等同于先转成整数再运算（§3.11.5）。

NaN 加入第四种比较结果：unordered

比较 a 与 b 后CFZFPF
a < b100
a = b010
a > b000
至少一个操作数为 NaN111
# 自设语义示例：double a 在 %xmm0，b 在 %xmm1
# 实现有序的 a == b（忽略异常处理路径，关注比较结果）
ucomisd %xmm1, %xmm0
jp      .Lfalse       # unordered：有 NaN，不能判断为相等
jne     .Lfalse
movl    $1, %eax
ret
.Lfalse:
movl    $0, %eax
ret

只看 ZF 会把 NaN 情况误当“相等”。PF 在这里表示无序结果（unordered result）；jp 可单独处理它。涉及 NaN 时，==、<、> 等有序比较为假，但 != 为真。

这是浮点比较自身的规则，不能理解为把 double 当作无符号整数比较。即使表中的 CF、ZF 组合看起来相似，也必须另外处理 NaN。

回到第 3 章总图：现在用同一种读法看整段程序

数据在哪里

通用寄存器、XMM 或内存；宽度与编码由操作决定。

地址怎样得到

基址、位移、索引与缩放，对应数组、结构体和栈布局。

下一条在哪里

顺序、条件、回边、间接目标，或 call / ret 保存的接续位置。

什么约束要保持

类型与对象边界、调用保存责任、对齐，以及整数／浮点各自的计算规则。
