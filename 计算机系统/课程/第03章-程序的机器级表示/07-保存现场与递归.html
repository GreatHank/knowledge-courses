一个值跨越 call 以后，还能直接相信吗？

long Q(long);
long P(long x) {
    long saved = x;
    long y = Q(x);
    return saved + y;
}
P 的需求如果只把 saved 留在 %rdi可行思路
调用 Q 后还要用原 xQ 可以改写 %rdi，返回时未必还是 x调用前另存，或者使用必须由 Q 保持的寄存器

寄存器保存的是当前值，调用另一个 C 函数时不会自动复制一套。调用约定（calling convention）分配保存责任，栈为需要保存的旧值提供位置。

caller-saved 与 callee-saved：谁需要值，谁负责哪一步

类别本书常见通用寄存器责任
callee-saved · 被调用者保存%rbx、%rbp、%r12–%r15Q 如果使用并改变它们，返回给 P 前必须恢复 P 看到的旧值
caller-saved · 调用者保存%rax、%rcx、%rdx、%rsi、%rdi、%r8–%r11P 若需要其中某值跨越调用，须自行保存或重新计算
%rsp · 栈指针另有栈纪律Q 返回时必须使调用栈关系成立；不能作为普通临时值随意破坏

“被调用者保存（callee-saved）”不等于每次调用都无条件压入所有寄存器。需要改写哪些，就保存并恢复哪些；caller-saved 寄存器的值也不一定被改写，但调用者不能假定它保持不变。

用 %rbx 保住 x，也要保住别人的 %rbx

# 自设语义示例，P 的 x 在 %rdi
P:
    pushq %rbx          # 保留 P 的调用者原有的 %rbx
    movq  %rdi, %rbx    # 本次 x 放在 %rbx
    call  Q             # Q 必须维持返回时的 %rbx
    addq  %rbx, %rax    # 结果 = Q(x) + x
    popq  %rbx          # 还给 P 的调用者
    ret
视角谁是 caller谁是 callee谁的旧值要还原
外层调用 P外层函数PP 返回前恢复外层的 %rbx
P 调用 QPQQ 返回前保持 P 的 %rbx（此时保存 x）

P 既是 Q 的调用者，也是上一层函数的被调用者。代码中配对的 push 与 pop 让 P 在使用寄存器时也履行自己的保存责任。这里仍假设 C 的计算结果在类型范围内。

递归没有另一套魔法：每层保留自己的未完成工作

调用展开（n=3）本层暂存的 n暂时还不能完成的乘法
rfact(3)33 × rfact(2)
rfact(2)22 × rfact(1)
rfact(1)1到达基例，结果 1
逐层返回%rax 中子调用结果恢复后的本层 %rbx本层结果
回到 n=2 的调用122 × 1 = 2
回到 n=3 的调用233 × 2 = 6

看原图第 2 行的 pushq %rbx：下一层先保存上一层放在 %rbx 中的 n，再使用同一个寄存器；返回时通过 pop 恢复旧值。因此当前寄存器只有一份，尚未完成各层的旧值保存在不同栈位置。

为什么要有基例，为什么递归深度有代价

基例决定何时开始返回

rfact 的 n ≤ 1 分支直接返回 1；缺少终止条件，调用可能不断增长。

栈空间随未完成调用累积

普通递归的每层都可能保留返回地址、保存寄存器和局部数据；空间有限。

返回顺序服从后进先出

最近进入的一层先返回，正好先得到上一层等待的子结果。

源代码递归与最终机器码有区别
