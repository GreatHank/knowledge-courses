地址算得出来，不能证明对象仍然存在

int a[3] = {10, 20, 30};
int *p = a + 3;    // 合法的一越尾指针
// int x = *p;     // 错误：不能解引用一越尾位置
检查层次问题可能发生的区别
数值计算能否算出起始地址 + 偏移？机器可能算出了某个地址
内存映射与权限这个虚拟地址是否允许这次读写？系统可能报告访问错误，也可能允许访问
C 对象规则对象仍在生命期内吗？是否越界、类型与对齐是否合适？即使这次没有崩溃，也不保证 C 程序合法

本章把“08–09 · 布局”和“06–07 · 调用栈”接起来：越界不总会立刻碰到不可访问的内存，它也可能改坏相邻的有效状态。不崩溃不是正确性的证明。

指针的类型决定操作，机器指令执行具体访问

C 写法理解重点
int *pp 保存地址；解引用访问 int，p+1 按 int 大小前进
char **pp 指向一个 char* 对象；先读出那个指针，再读字符
void *p通用对象指针；标准 C 不直接对 void* 做元素算术或解引用
int (*fp)(int)函数指针，指向代码入口；调用可形成间接 call
强制转换指针类型改变编译器如何理解后续访问，不会搬动或扩大实际对象

还要问生命期：返回局部栈对象的地址，不会让它随函数返回继续存在。指针数值留在寄存器或内存中，也不等于它所指对象仍可使用。

用 GDB 看状态：一次只验证一个具体问题

# Linux/Unix 的使用示意；本课没有在本机执行
# 先将自己的 C 文件编译为含调试信息的程序
# gcc -Og -g -o prog prog.c
gdb prog
在 GDB 内观察什么
break exchange，然后 run在函数入口附近停止
disassemble exchange查看当前构建实际生成的指令
info registers rdi rsi rax rsp rip看参数、结果、栈顶和执行位置
x/gx $rdi从 rdi 指定地址，按 8 字节十六进制查看内容
stepi执行一条机器指令，再比较状态变化
nexti单步时越过调用；用于观察调用前后
bt查看调用栈回溯

例如先记录 rdi 和它指向的内存，再执行 exchange 的第一条 mov；预期变化的是 rax，内存尚未改变。下一条 mov 才修改内存。编译器优化可能让局部变量消失或改变停点，要以当前指令与状态为准。

缓冲区越界怎样碰到控制状态

看原图从 buf 往高地址方向作用
字符数组 buf只允许写入自身对象范围；字符串终止字符也要占 1 字节
Canary受保护函数进入时保存的检查值；返回前核对是否被破坏
Return address决定函数返回后执行哪里；若被破坏，控制流也会出错

一个 8 字节字符数组最多放 7 个普通字符加终止字节。空间计算漏掉末尾的 \0，也会产生越界。原图来自教材历史 gets 例子；gets 缺少容量参数，用于解释缺陷，不作为写程序的方法。

保护机制主要作用不能据此认定
地址空间随机化（ASLR）让地址布局更难预先预测所有越界访问都会被拦截
栈保护 canary在函数返回前检测某些栈状态破坏所有对象访问都经过边界检查
不可执行页面（NX）限制在数据页执行代码数据不能被越界修改，或一切控制流破坏都被消除

这些机制配合源程序的长度和对象检查降低风险；具体是否启用、布局怎样，由实际编译与运行环境决定。本课没有对当前机器的安全配置作判断。

栈大小运行时才知道：需要稳定的参考位置

原图来自 long *p[n]：n 次调用之间可以不同，数组本体需要约 8n 字节，加上对齐和其他局部存储。分配这块空间后，%rsp 会继续向低地址移动。

寄存器／位置在这个实现中的角色
%rbp先保存旧值，再固定为帧参考位置；局部 i 可通过 −8(%rbp) 访问
%rsp随着本次所需空间移动，指向当前栈顶
p数组起点另按对齐条件确定；通过下标访问
leave相当于恢复 %rsp 到 %rbp 所指位置，再 pop 旧 %rbp；随后 ret

因此“动态分配量”和“固定局部位置”可以同时被找到。%rbp 不是每个函数都必须使用的帧指针；是否保留它还受编译选项与调试需要影响。

回到章节图第 10 节点：现在能把指针、对象、栈与控制状态放在同一幅图里检查。最后一课补上浮点数怎样沿着另一组寄存器完成同类工作。
