算 5x + 8，为什么能出现 leaq？

# 自设语义示例；x 在 %rdi
leaq 8(%rdi,%rdi,4), %rax
# %rax = 8 + x + 4x = 5x + 8
同样的括号写法x = 3 时是否读取内存
leaq 8(%rdi,%rdi,4),%rax结果为 23否，只算表达式
movq 8(%rdi,%rdi,4),%rax尝试从地址 23 读取 8 字节是；不能因公式算得出就认定地址有效

单独打开、放大或导出这张 Archify 图 · 依据教材机制重组的伴读解释。

回看图中“有效地址 → leaq 的结果”这条线：leaq 把地址计算器式的加法与缩放用于产生数值。它不解引用，也不改变条件码。名字里有 address，不要求参与计算的值一定是指针。

双操作数指令：第二个操作数也参与计算

指令准确读法例子
addq S,DD ← D + SD=10、S=3，结果 13
subq S,DD ← D − SD=10、S=3，结果 7
imulq S,DD ← 乘积的低 64 位D=10、S=3，结果 30
andq / orq / xorq按位运算，写回 Dxorq %rax,%rax 得到 0
negq D对 D 取补码负值操作宽度仍有限
notq DD 的每一位取反不是 C 的逻辑非 !
# %rax = 10，%rdx = 3
subq %rax, %rdx     # %rdx 变为 3 - 10 = -7
# 源在前；不要读成 %rax - %rdx

寄存器最终保存固定宽度的位串。加法和截断乘法的低位模型接上第 2 章；这不等于 C 编译器必须为有符号溢出保留某种回绕行为。

移位：方向之外，还要看填充和计数

操作左侧空位怎么填8 位画法仅用于直观看位
shrq 逻辑右移补 011111000 → 01111100
sarq 算术右移复制符号位11111000 → 11111100
salq / shlq 左移低位补 0，高位丢出00000101 → 00001010
# 实际指令在 64 位上操作
movq $-8, %rax
sarq $1, %rax       # 得到 -4
# 变量移位量使用 %cl，例如 sarq %cl, %rax

对本书的普通 x86-64 移位，64 位操作只用计数的低 6 位，32 位操作只用低 5 位。C 的移位次数必须落在提升后左操作数的位宽范围内；不能根据硬件会截取计数，就把 C 中移 64 位写成合法技巧。

负数的算术右移按位复制符号，相当于向负无穷方向取整；C 的整数除法向零截断。第 2 章给负数加偏置再右移，正是为了补上这个差别。

乘法有“只保留低位”和“保留完整结果”

形式输入输出
imulq %rsi,%rax两个显式操作数乘积低 64 位写回 %rax
imulq %rsi隐含 %rax × %rsi，按有符号解释128 位结果写入 %rdx:%rax
mulq %rsi隐含 %rax × %rsi，按无符号解释128 位结果写入 %rdx:%rax

%rdx:%rax 表示把两个寄存器拼成高 64 位 : 低 64 位，不是“用 rdx 作地址读取 rax”。同名 imulq 的含义，要结合操作数个数判断。

无符号数值例子高 64 位 %rdx低 64 位 %rax
2⁶³ × 2 = 2⁶⁴0x00000000000000010x0000000000000000

除法前，必须准备整个被除数

# 自设例子：有符号 -17 / 5
movq $-17, %rax
cqto                 # 将 %rax 符号扩展到 %rdx:%rax
movq $5, %rcx
idivq %rcx           # 商在 %rax = -3，余数在 %rdx = -2
要读的部分含义
idivq 的隐含输入完整的 128 位 %rdx:%rax；高半部不能留作未知旧值
cqto把 64 位 %rax 符号扩展为 128 位；负数时 %rdx 全 1
无符号 64 位被除数使用 divq，且通常先把 %rdx 清零
关系检查−17 = (−3) × 5 + (−2)，商向零截断
边界除数为 0 或商超出目标宽度，会导致除法异常
