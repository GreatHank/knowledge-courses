从 while 看见一条回边

long fact_while(long n) {
    long result = 1;
    while (n > 1) {
        result *= n;
        n = n - 1;
    }
    return result;
}

单独打开、放大或导出这张 Archify 图 · 依据教材机制重组的伴读解释。

n = 3 的运行检查 n > 1result随后 n
进入函数尚未检查13

第 3 次假返回 6不再改变

沿“n > 1 ? → result *= n → n = n − 1 → 下一轮检查”跟踪一次迭代（iteration）。回边重复的是检查和循环体（loop body），不是每轮重新执行 result = 1。这里取 n=3；一般 C 阶乘要限制结果不溢出。

检查写在下面，为什么仍然先检查？

原图汇编先把结果设为 1，再用 jmp .L5 跳过循环体。到 .L5 检查 n，jg .L6 成立才回到乘法；完成乘法和减一后又顺着代码落入 .L5。

汇编在纸面上的排列不一定就是执行顺序。要先找入口的跳转目标、条件不成立时会执行的位置，再找返回前面指令的回边。教材将这种形态称为 jump-to-middle。

do-while、while、for，共用测试与跳转

C 结构首次执行关键回边
do-while先执行循环体，再检查条件成立回到循环体；至少一次
while先检查，可能一次也不执行循环体结束后重新检查
for(init;test;update)先 init，再 test循环体 → update → test
// 便于理解的控制顺序，非固定编译输出
init;
goto test;
body:
    /* 循环体 */
update:
    /* 更新迭代变量 */
test:
    if (condition) goto body;
/* 退出循环 */

for 中的 continue 应到 update，再检查；while 中的 continue 则到检查。break 离开循环。机械把 for 改写成 while，若遗漏更新步骤，可能卡在同一个迭代值。

switch：把选择变成“查出下一段代码的地址”

原始 case 值（教材例子）index = n − 100跳转表指向
1000loc_A
101（缺失）1default
1022loc_B
1033loc_C
1044loc_D
105（缺失）5default
1066loc_D（共享实现）
# 教材 Figure 3.23 的入口；n 在 %rsi
subq $100, %rsi
cmpq $6, %rsi
ja   .Ldefault        # 无符号 index > 6：不在范围内
jmp  *.Ltable(,%rsi,8) # 从表里取 8 字节目标地址，再间接跳转

先做范围检查，再查表。机器中的减法按 64 位结果处理；n 小于 100 会落到很大的无符号 index，也会经 ja 跳到 default。若用 C 表达这个范围归一化，写成 (unsigned long)n - 100UL，避免先做可能溢出的有符号减法。

这里的星号 * 表示间接跳转：目的地址来自操作数的内容。表项步长 8 是因为这里每个代码地址占 8 字节。

穿透、共享与编译选择

多个 case 共享代码

104 和 106 的表项可以存同一个地址；不需要复制两份实现。

fall through · 穿透

102 执行完自己的操作后，没有离开的跳转，就继续落到 103 的代码。

缺失与越界

范围内没写的 case 可指向 default；范围外先由检查处理。

不必总是跳转表

case 稀疏、分支很少或优化条件不同时，也可能生成比较链或其他等价结构。

回到“04–05 · 控制流”：循环的核心是回边，switch 的核心是多路目标选择。下一课的 call 也会改变执行位置，同时还要保存返回的位置。
