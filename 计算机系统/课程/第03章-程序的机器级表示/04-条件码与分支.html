同一串位，比大小的方法可以不同

# a 在 %rdi，b 在 %rsi
cmpq %rsi, %rdi      # 设置条件码，依据 a - b
# 不把差值写回 %rdi
a 的位串b按 signed long 比较按 unsigned long 比较
0xFFFFFFFFFFFFFFFF1−1 < 1 为真18446744073709551615 < 1 为假

cmp 指令本身不区分操作数在 C 中是有符号还是无符号类型。同一份减法留下的条件码，可以交给不同条件的跳转或 set 指令。类型影响的是编译器选择哪一种判断。

条件码：保存计算的几个特征

标志要观察什么加／减法中的用途
ZF · Zero结果的所有位是否为 0相等判断
SF · Sign结果最高位是否为 1结合 OF 判断有符号大小
CF · Carry加法进位；减法借位无符号范围或大小关系
OF · Overflow有符号结果是否越出可表示范围修正“只看差值符号”的错误
8 位示意，不是 long 位宽低 8 位结果SFOF有符号 a < b
a=127，b=−1，计算 a−b10000000（按补码为 −128）11SF ⊕ OF = 0，所以为假
a=−1，b=1，计算 a−b11111110（−2）10SF ⊕ OF = 1，所以为真

第一行的真实数学差是 128，8 位补码装不下。只看 SF 会判断错；将 SF 与 OF 异或，就能计入溢出的影响。这里是固定宽度减法模型，不是在 C 中执行溢出表达式。

testq %rax,%rax 根据按位与的结果设置标志，但不改 %rax；它常用来检查 0。mov、leaq 不修改条件码，其他算术指令的标志副作用（side effect）各有规定，不宜一概推断。

同一条件，可以变成值、路径或数据选择

用途例子改变什么
产生真假值setl %al只把一个字节写成 0 或 1
改变执行路径jl .Lsmall成立时转到标签对应的指令
选择寄存器值cmovl %rsi,%rax成立时把源值复制到目标
比较 a 与 b 后有符号无符号
小于jl / setl：SF ⊕ OFjb / setb：CF
大于等于jge / setge：¬(SF ⊕ OF)jae / setae：¬CF
大于jg：¬ZF 且 ¬(SF ⊕ OF)ja：¬ZF 且 ¬CF
相等je / sete：ZF相同位串可用同一相等条件
# 教材 §3.6.2 的 long 比较模式
cmpq   %rsi, %rdi
setl   %al
movzbl %al, %eax     # 把真假字节扩为干净的 int 结果
ret

setl 中的 l 表示 less，不是第 1 课 movl 中的长度后缀。set 只写一个字节，如果其余位仍未确定，就不能直接把它当成完整的 int 返回。

一段 if 的两种实现思路

long smaller(long a, long b) {
    return a < b ? a : b;
}

分支版本 · 选择执行哪段

先 cmp；条件成立跳到返回 a 的代码，否则走返回 b 的代码。执行位置依赖比较结果。

条件传送 · 选择哪个值

先令 %rax = b；cmp 后用 cmovl 把 a 复制到 %rax。后续指令位置不必分叉。

# 自设条件传送版本：两个输入都已在寄存器中
movq  %rsi, %rax
cmpq  %rsi, %rdi
cmovl %rdi, %rax
ret

条件传送（conditional move）能减少某些分支预测（branch prediction）失误的代价，但是否更快取决于计算量、依赖关系和输入规律。第 5 章会详细分析性能原因，这里先确认两种实现的语义是否正确。

直接相对跳转的机器码通常记录相对位移。计算目的地址时，基准是跳转指令之后那条指令的地址，不是这条跳转自己的起始地址（§3.6.4）。

先把两个分支都算出来，有时已经错了

long read_or_zero(long *p) {
    return p ? *p : 0;
}
p 是空指针时正确的条件表达式错误的“先算再选”
是否读取 *p不读取，只得到 0先读 *p，再准备把结果换成 0
结果避开这次非法解引用读内存那一步已经出错，后来选择 0 无法补救

教材 §3.6.6 指出一个限制：不该执行的分支里若有非法访问或副作用，就不能随意提前求值。这个例子可以用先判断再读取的分支实现；更复杂的变换则需要另外确认是否保持原有语义。

回到控制流节点：条件码提供判断依据，跳转改变下一条指令。将跳转目标设在前面的指令处，就能形成下一课要讲的循环。
