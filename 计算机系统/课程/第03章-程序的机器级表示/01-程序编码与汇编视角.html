先看一行 C，与三条机器动作

long add(long x, long y) {
    return x + y;
}
# 语义示意，AT&T 格式；不是本机编译输出
# x 在 %rdi，y 在 %rsi
add:
    movq %rdi, %rax   # 复制 x
    addq %rsi, %rax   # 把 y 加到 %rax
    ret              # 返回，结果在 %rax
C 中看到的东西机器层面怎样体现
形参 x、y调用约定把两个值放在指定寄存器中
x + y读寄存器，进行 64 位加法，更新目标寄存器
return返回值放到约定位置；ret 把执行位置交回调用者

读这三行时，先沿着数据在哪里 → 哪条指令改变它 → 接下来执行哪里来跟踪，不必先记住整张寄存器表。示例只讨论结果能由 long 表示的输入，C 的有符号溢出规则仍然适用。

三种表示，讲的是同一个程序的不同侧面

C 源程序

用变量、类型、表达式和控制结构描述计算；保留面向程序员的抽象。

汇编文本

用指令名、寄存器和地址表达式描述机器操作；标签方便指代位置。

机器码

指令编码为字节。CPU 取到这些字节，按指令集（instruction set）解释。

反汇编

从机器码恢复指令及操作数的可读写法；通常不能恢复全部变量名、类型和原始源码结构。

观察目标教材中的工具方式实际得到什么
汇编文本gcc -Og -S mstore.c生成 .s，止于编译阶段
目标文件gcc -Og -c mstore.c生成 .o，包含机器指令和链接所需信息
反汇编objdump -d mstore.o地址、机器字节与汇编指令的对照
可执行文件gcc -Og -o prog main.c mstore.c链接其他目标文件及库；未定义函数必须有实现

编译器版本、优化选项和目标平台都会改变具体指令。这里要学的是解释具体的机器代码；不同机器并不一定生成同一段汇编。-Og 是本书使用的观察条件。

把汇编真正放回字节里

函数内偏移指令字节汇编读法
0x053push %rbx
0x148 89 d3mov %rdx,%rbx
0xDc3retq

摘取并核对 §3.2.2 中 multstore 的反汇编示例，PDF 211 / 书内 210 页；省略的中间指令未列在表中。

第一条指令占 1 字节，第二条占 3 字节，因此不能按固定的“一格一条指令”读取。x86-64 使用可变长度指令编码（variable-length instruction encoding）；反汇编器必须从指令边界开始解码。

为什么有 ax、eax、rax？

§3.1 先给出历史背景：x86 从 16 位扩展到 32 位，再到 x86-64，保留了许多命名与兼容关系。第 2 课会直接在寄存器原图里看到这些低位别名。

为什么 ISA 不等于某一款处理器？

不同内部实现可以遵循同一指令语义。扩展寄存器和指令属于程序可见接口的演进；流水线等内部实现则是另一个层次。

把“执行程序”改写成“改变机器状态”

状态在 add 例子里后面用来解释
通用寄存器%rdi、%rsi 保存输入，%rax 保存结果快速保存整数、地址和临时值
内存本例的加法不需要从内存读操作数；返回地址在栈中数组、对象、局部存储和机器指令
程序计数器 %rip确定接下来执行的指令位置顺序执行、跳转、调用与返回
条件码add 可以改变若干标志；本例没有使用它们比较、分支、条件传送
浮点／向量寄存器本例没有使用第 11 课的 float、double 运算

ISA（指令集体系结构）规定这些状态和指令效果。它提供程序可观察的行为模型；真实处理器怎样实现流水线执行和乱序调度，会在第 4、5 章继续讨论。

程序里的内存地址在这里按虚拟地址（virtual address）理解。它怎样到达缓存和物理内存，分别留给第 6、9 章；此时先准确追踪程序看到的地址。

读 AT&T 汇编，先认四个记号

写法读法别混淆
%rax寄存器中的值% 是寄存器名前缀
$8立即数 8没有 $ 的数字可能是内存地址表达式
(%rdi)以 %rdi 的值为地址访问内存%rdi 本身是地址值，括号表示解引用
movq S, D从 S 复制到 DAT&T 通常源在前、目标在后；Intel 格式常相反
数据长度常见整数指令后缀教材平台对应类型
1 字节bchar
2 字节wshort；x86 的 word 专指 16 位
4 字节lint；这个 l 不等于 C 的 long
8 字节qlong、指针；quad word

本章按教材的 x86-64 / Linux、Unix 调用约定讲。64 位 Windows 的 long 大小与常用调用约定不同，不能直接套用这里的参数寄存器表。
