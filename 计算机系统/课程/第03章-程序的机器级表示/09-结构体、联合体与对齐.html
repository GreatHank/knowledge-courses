先读一个结构体字段的地址

struct rec {
    int i;
    int j;
    int a[2];
    int *p;
};
字段（教材 x86-64 / Linux 布局）ija[0]a[1]p
字节偏移0481216
占用字节44448
# r 在 %rdi；实现 r->j = r->i
movl (%rdi), %eax
movl %eax, 4(%rdi)

# 计算 &r->a[1]
leaq 12(%rdi), %rax

字段名在编译时变成了固定偏移；运行时用“结构体起点 + 偏移”找到位置。这个 rec 共 24 字节，a 的元素直接嵌在里面；p 则只占一个指针的位置。

为什么 4 + 1 + 4，sizeof 却是 12？

struct S1 { int i; char c; int j; };
位置字节区间原因
i0–3int 从 4 的倍数偏移起始
c4char 只需 1 字节
padding5–7使 j 的偏移达到 8
j8–11满足 4 字节对齐
sizeof(S1)12包含字段和填充

对齐要求某类对象从特定倍数的地址开始。编译器可在字段之间插入 padding；因此“字段大小相加”不一定得到结构体大小。此处按教材通常的 ABI 布局，不使用 packed 扩展。

最后一个字段后面，为什么也要留空？

struct S2 { int i; int j; char c; };
struct S2 d[4];
假设首地址 x 按 4 对齐第 0 项第 1 项第 2 项第 3 项
若错误地只留 9 字节xx+9x+18x+27
实际每项占 12 字节xx+12x+24x+36

尾部 padding 保证数组里每一个结构体的起点仍符合对齐要求。sizeof 描述完整对象跨度，数组步长包含这些尾部字节。

一般布局规则可这样计算：字段从满足自身对齐的下一个偏移开始；全部字段放完后，把总大小补齐到结构体所需对齐的倍数。具体类型的尺寸与对齐由目标平台决定。

union 的字段共享存储，struct 的字段各占位置

struct S { char c; int i[2]; double v; };
union  U { char c; int i[2]; double v; };
教材平台c 偏移i 偏移v 偏移总大小
struct S041624 字节
union U0008 字节

struct 的问题

多个字段要同时存在，地址区间依次安排，并满足各自对齐。

union 的问题

这些字段是同一块存储的不同视图；写一个成员会覆盖其他成员重叠的表示。

union 的大小至少容纳最大成员，还要满足对齐。按另一种类型解释同一串位，不是数值类型转换；例如 double 的位表示不是“把这个 double 转成整数”的结果。跨类型读取还涉及 C 语言规则和可能的无效表示，不能照搬为通用可移植转换办法。

布局会影响空间、访存和接口

要判断的问题从布局得到的答案
&r->a[i]r 起点 + 字段 a 偏移 8 + 4i；i 仍须满足合法范围
结构体数组有多大元素个数 × sizeof(结构体)，填充也计入
怎样确认实际布局查看 sizeof、_Alignof 和 offsetof（<stddef.h>）
重排字段有什么影响可能减少空隙；也会改变布局，影响依赖二进制接口的代码

普通 x86-64 标量访问对许多非对齐地址也能执行，但这不取消 C 类型、ABI 或特定指令的对齐要求；有些向量指令要求严格对齐。性能影响要结合访问是否跨边界等条件，不能只看一个“未对齐”标签。

回到章节图“对象布局 → 调试与内存边界”：知道每块对象占哪里，才能判断一个地址是否还在允许的对象范围里。
