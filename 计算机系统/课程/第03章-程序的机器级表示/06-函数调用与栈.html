P 调用 Q，不能只跳过去

long plus1(long x) { return x + 1; }
long use(long x)   { return plus1(x) + 2; }

下面讨论编译结果中保留 call 的情况。编译器也可能将 plus1 内联，使这次调用消失；那样就不会出现这里的调用过程。

传递控制

进入 Q；之后还必须回到 P 中 call 后面的指令。

传递数据

P 给 Q 参数；Q 把结果交回 P。

管理存储

Q 必要时取得局部空间；返回前恢复栈边界。

遵守保存责任

某些寄存器可以被 Q 改写，另一些返回时必须保持原值；下一课展开。

时序图分别展示控制转移和数据传递：call 保存返回地址（return address）并改变执行位置；参数和结果按约定放置。call 指令本身不会自动向 Q 传递 C 程序中的所有变量。

call 与 ret，具体怎样改变栈？

示意时刻%rsp栈顶内容执行位置
P 执行 call Q 之前0x1000此处内容与示例无关call 指令
执行 call 后0x0FF8A = call 后面的指令地址Q 的入口
Q 准备返回0x0FF8仍然是 Aret 指令
执行 ret 后0x1000旧字节可以仍留在内存A，即 P 的后续指令

call 像一次“压入返回位置＋跳转”；ret 像一次“弹出位置＋跳回”。返回地址决定去哪里执行，返回值是计算结果，两者不是同一东西。

表中假设 Q 返回前已释放自己的局部空间，并恢复按调用约定（calling convention）需要恢复的内容。若 %rsp 指错位置，ret 就可能把普通数据误当成返回地址。

整数与指针参数：先看六个寄存器

参数序号64 位整数／指针32 位整数
1%rdi%edi
2%rsi%esi
3%rdx%edx
4%rcx%ecx
5%r8%r8d
6%r9%r9d
后续按约定放在栈中占位与对齐按 ABI 处理
普通整数返回值%rax%eax

这是本书 Linux/Unix x86-64 的普通标量参数约定。ABI是不同编译单元共同遵守的二进制接口规则，约定参数、返回和保存责任。这张简表没有完整列出结构体传参等更复杂的分类。

例：long f(long x, long *p) 的 x 在 %rdi，p 在 %rsi。p 传递的是地址值；Q 仍要通过 (%rsi) 才能访问它指向的对象。浮点参数另走 XMM 寄存器，第 11 课再补上。

栈帧：本次调用使用的那段栈空间

原图中的区域为什么需要
Return address保存 P 在 Q 返回后的继续位置；本书把它归入调用者 P 的状态
Saved registers把必须保留的寄存器旧值暂存在栈上
Local variables寄存器放不下，或必须有内存位置的局部数据
Argument build areaQ 再调用其他函数时，准备需要放在栈上的参数

图上 %rsp 指向低地址端的当前栈顶。栈帧（stack frame）不是固定模板：并非每个函数都有局部栈空间，也不是每个局部变量都要进栈。

取局部变量地址，会把“位置”变成问题的一部分

long swap_add(long *xp, long *yp);

long caller(void) {
    long a = 534, b = 1057;
    long sum = swap_add(&a, &b);
    return sum * (a - b);
}
按教材 Figure 3.31 的机制为什么这样做
为 a、b 留下局部存储被调用函数拿到 &a、&b 后需要通过地址访问它们
把两个局部地址送进 %rdi、%rsi传入的是位置，不是当前数值
调用 swap_add它交换两个 long，并返回原来两数之和
回来后从局部内存重新读 a、b内存已被改写：a=1057、b=534
结果1591 × 523 = 832093

对局部对象取地址并跨函数使用，通常需要为它安排内存位置；若编译器能消除访问或内联调用，实现仍可能更简单。示例中的栈偏移只对应这份编译结果，不是所有编译结果都要遵守的规定。
