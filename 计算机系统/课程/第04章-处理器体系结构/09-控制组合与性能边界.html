暂停和气泡，都在改变“下一拍保存什么”

寄存器动作下一上升沿对指令的意义
normal加载输入正常向前推进
stall保留旧内容当前指令留在原阶段
bubble加载无副作用的复位配置留空位或取消错误指令

气泡（bubble）需要把指令类型、目的 ID 等字段置为安全组合，效果类似 nop；它不是编译器往程序内存插入了一条真实指令。

章节图位置：09 · 控制组合与性能。上表列出各条件单独发生时的基本动作。多种条件同时出现时，还需要检查动作是否冲突，决定应优先执行哪一个。

一个 ret 既想等返回地址，又等前一条加载的 %rsp

# 初始 %rdx 指向有效内存，里面保存一份有效栈地址
mrmovq 0(%rdx), %rsp
ret
同一拍load/use 的要求ret 的要求
加载在 E；ret 在 DF、D 保持；E 插入气泡F 保持；D 插入气泡
冲突点 D必须留住 ret 等新 %rsp会把 ret 取消
正确动作优先保留 D，先解决 load/use下一拍再按 ret 的等待规则推进

由于 ret 要读取 %rsp，这两种等待可能同时出现。相反，load/use 与分支误预测不能在同一拍由 E 触发：E 中同一条指令不可能既是加载又是跳转。

把条件命名以后，优先级就能直接读出来

# 教材 §4.5.8 的条件，使用便于阅读的别名
bool L = E_icode in { IMRMOVQ, IPOPQ } &&
         E_dstM in { d_srcA, d_srcB };
bool R = IRET in { D_icode, E_icode, M_icode };
bool B = E_icode == IJXX && !e_Cnd;

bool F_stall  = L || R;
bool D_stall  = L;
bool D_bubble = B || (!L && R);
bool E_bubble = L || B;

关键是 !L && R：当加载依赖仍未解决时，ret 不能被 D 气泡冲掉。上式中 L 与 B 互斥，因此有效流水线状态不会同时要求 D_stall 和 D_bubble。

另一个组合为什么仍正确
误预测分支在 E，错误路径 ret 在 DD、E 注入气泡，ret 被取消；下一拍取指优先采用分支恢复地址
同一拍因 ret 保持了 FF_predPC 是否更新不影响恢复；f_pc 的纠正分支优先于 F_predPC
# 异常控制，仍按教材命名
bool bad = m_stat in { SADR, SINS, SHLT } ||
           W_stat in { SADR, SINS, SHLT };
bool set_cc = E_icode == IOPQ && !bad;
bool M_bubble = bad;
bool W_stall = W_stat in { SADR, SINS, SHLT };

这些代码块用于解释控制关系，还缺少其他信号和常量定义，不能作为完整的处理器文件单独编译运行。状态判断使用符号名称，避免混用本版局部表格里不一致的数字。

一拍一条是目标，气泡让平均 CPI 增加

忽略启动/排空和异常停机，按教材的长期执行估算：
CPI = 总周期数 / 完成指令数
    ≈ 1 + 气泡数 / 完成指令数
    = 1 + 加载暂停代价 + 误预测代价 + 返回代价
教材假设的原因占全部指令比例其中触发比例每次代价每条指令平均代价
加载后紧接使用25%20%1 拍0.25×0.20×1=0.05
条件分支预测错误20%40%2 拍0.20×0.40×2=0.16
ret2%100%3 拍0.02×1×3=0.06
合计———CPI≈1+0.27=1.27

这是 PDF 504 的假设频率，不是本机测量。分母始终是全部完成的指令：不能把“加载中 20% 触发暂停”直接当成“所有指令中 20% 暂停”。若事件重叠，实际统计应按真实插入的气泡计数，不能重复计算同一气泡的代价。

比较速度还要看 执行时间（execution time） ≈ 指令数 × CPI × 时钟周期。CPI（cycles per instruction）是平均每条指令所需的周期数。CPI 较低的设计，如果周期更长，未必更快；换程序之后，指令数和冒险频率也会改变。

PIPE 帮我们理解了什么，还省略了什么？

正确性可以分层检查

ISA 解释器描述期望结果；SEQ 和 PIPE 的寄存器、内存及状态结果可与它比较。只跑典型程序不足以检查转发优先级、组合条件和异常边界。

多周期操作

乘除和浮点等可能需要独立功能单元、多周期执行与新的依赖协调。本章 OPq 只有加、减、与、异或。

存储访问并非总是一拍

缓存未命中、地址翻译与缺页会增加等待或触发异常；第 6、9 章再展开，PIPE 中的内存接口并不保证现实中的访问总能在一拍内完成。

接到程序优化

可以用依赖链（dependency chain）、指令重叠和控制代价解释性能差异。第 5 章将从 C 程序出发，讨论哪些改写能让机器并行完成更多有效工作。

回到整张章节图：ISA 规定指令的行为，逻辑和时钟负责实现；流水线让多条指令重叠执行，转发、暂停和取消保证结果正确，性能分析则衡量收益与代价。通过这些关系，本章解释了汇编指令怎样执行，以及不同实现为什么会有性能差异。
