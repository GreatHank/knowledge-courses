压栈看似要先改 %rsp，电路却可以同时写两处

# 伴读示例：初始 %rsp=0x1000，%rax=42，目标地址有效
pushq %rax
# 完成后：%rsp=0x0FF8，M8[0x0FF8]=42

单独打开、放大或导出这张 Archify 图 · 依据教材机制重组的伴读解释。

看 ALU → %rsp 写入端 与 ALU → 内存写入端 两条线：同一个 valE=0x0FF8 同时提供新栈指针和写地址。无需先写 %rsp，再读回它。

No reading back：不要依赖本条指令刚刚写回的状态

阶段状态与信号应当怎样看
周期开始状态器件输出旧值旧 %rsp=0x1000
周期内组合逻辑产生 valE=0x0FF8、valA=42这是导线上的候选新值
周期结束的上升沿寄存器与内存按各自使能更新两处写入同时发生
下一周期后续指令读到更新后的状态下一次依赖已经满足

这就是教材的“不读回”原则：为完成一条指令，不需要重新读出它刚更新的状态。这是本章设计数据通路（datapath）时遵循的原则；下一条指令仍然可以读取上一条指令的结果。

同理，OPq 设置 CC，而条件跳转读取 CC；本章没有一条指令必须先写 CC 再用新的 CC 判断自己是否跳转。

控制逻辑不是另一段顺序程序，而是选择哪些线

# 伴读整理的 SEQ HCL；符号沿正文统一使用
word alufun = [
    icode == IOPQ : ifun;
    1 : ALUADD;
];
bool set_cc = icode == IOPQ;

word dstE = [
    icode == IRRMOVQ && Cnd : rB;
    icode in { IIRMOVQ, IOPQ } : rB;
    icode in { IPUSHQ, IPOPQ, ICALL, IRET } : RRSP;
    1 : RNONE;
];
例子ALU 做了什么允许改变什么
OPq按 ifun 做加、减、与、异或写结果，更新 CC
rmmovq基址加位移写内存，但不更新 CC
cmovXX 条件为假仍可能算出传送候选值dstE=RNONE，不写目的寄存器
pushq旧 %rsp−8写栈与 %rsp，不更新 CC

ALU 算出结果后，是否写入程序可见状态，还要由写目的 ID 与写使能（write enable）决定。

PC 选择：把语义表变成一个 MUX

word new_pc = [
    icode == ICALL : valC;
    icode == IJXX && Cnd : valC;
    icode == IRET : valM;
    1 : valP;
];

逐项看这段 HCL 怎样选择下一条指令的地址：call 和成功的跳转选择编码中的目标地址，ret 选择读出的返回地址，其余情况选择 valP。这是一次组合逻辑（combinational logic）选择，不需要逐项花费多个时钟周期。

本版 Figure 4.26 的个别符号和状态数值与邻近正文存在不一致；本课用 IOPQ、RRSP 与状态名称说明机制，不混用相互冲突的数值编码。实际使用配套工具时应以其统一常量定义为准。

SEQ 正确了，为什么还要改？

周期必须足够长

一条指令所需的信号传播都要在下一上升沿之前稳定。ret 的取指、读栈指针、读返回地址与 PC 选择会形成较长依赖路径。

硬件常在等待

前一条的后半段还没结束，后一条仍不能开始使用已经空闲的前半段。多条指令复用了同一套硬件，却没有重叠执行。
