先确定想接住哪一次调用

int *p = malloc(32);
free(p);

教材用这两次调用解释 library interpositioning，中文常称库打桩：在调用原函数前后加入自己的逻辑，或用自己的实现替代。包装函数（wrapper function）必须保持调用者所期待的接口；若继续调用原函数，还要避免再次绕回自己。

时机改变什么至少需要什么
编译时预处理把源码中的名字替换成包装函数名需要重新编译相关源文件
链接时重定向未定义符号引用，如 --wrap需要重新链接相应目标文件
装入／运行时动态符号查找优先找到预加载实现需要调用仍经过可被替换的动态符号路径

编译时：替换只作用于经过这次预处理的源码

#define malloc(size) mymalloc(size)
#define free(ptr) myfree(ptr)

教材用本地头文件和 -I. 让应用源码看到这些宏，而包装函数自身使用系统声明，内部才可以正常调用原 malloc。若包装函数也把 malloc 预处理成 mymalloc，就会形成意外递归。

已经编译好的库内部调用不会因后来写了这个宏就改变。这一方式修改的是源代码到目标文件的过程，不是在程序运行时搜索并替换每条指令。

链接时：两个名字分别通向包装层和原函数

gcc -Wl,--wrap,malloc -Wl,--wrap,free -o intl int.o mymalloc.o
输入中的未定义引用链接时按 --wrap 处理后
malloc__wrap_malloc
__real_mallocmalloc
free__wrap_free
__real_freefree

-Wl, 把选项传给链接器；逗号分隔其中的参数。包装函数里再次使用原名字 malloc，会重新落入包装路径，因此教材提供 __real_malloc 这条回到原实现的名字。

范围补充：GNU ld 的 --wrap 针对未定义引用（undefined reference）；同一翻译单元内部已经绑定的调用不能一概保证被它拦截，见 GNU ld 的 --wrap 说明。

运行时：预加载库影响动态符号查找

LD_PRELOAD="./mymalloc.so" ./intr

这条是教材的 Linux shell 示例，不是修改机器上的全局环境。预加载库中的 malloc 可先于后续共享库实现被找到。包装函数用 dlsym(RTLD_NEXT, "malloc") 继续查找当前对象之后的定义；“下一个”不必绝对等于 libc，因为还可能有其他包装层。依据 dlsym 手册。

它不能截获已经静态链接进去的实现、被编译器消掉的调用，或所有内部直接绑定的引用。Linux 的安全执行模式也限制预加载环境变量；见 ld.so 手册。教材“任意程序”的宽泛描述要放回这些条件中理解。

原图保留教材代码。它适合解释查找链，不应直接当成可部署的 malloc 跟踪器：包装层的日志、查符号或其他库操作可能再次触发分配，需要额外处理递归与初始化问题。本课没有运行打桩代码，也没有改动系统库。

从报错位置决定先看什么

问题先看什么对应本章概念
undefined referencenm / readelf -s 看引用与定义；检查静态库次序符号解析与按需抽取
multiple definition寻找各模块的定义，核对 extern、static 与 common 设置名字可见性与重复定义
重定位值不对或类型不适配readelf -r 与 objdump -dr 对照字段、类型、指令S、A、P 与指令编码
程序启动前找不到共享库readelf -d 检查记录的依赖；核对运行环境搜索路径构建时查库与运行时查库
程序能启动但调用行为意外检查实际绑定对象、函数类型与打桩范围链接成功不等于语义正确
ar t libvector.a       # 列出归档成员
nm main.o              # 查看符号
readelf -h -S main.o   # ELF 头与节表
readelf -s -r main.o   # 符号与重定位
objdump -dr main.o     # 反汇编并显示重定位
readelf -l prog        # 程序头表
readelf -d prog        # 动态链接信息

教材还列出 size、strings、strip 与 ldd：分别用于看节大小、可打印字符串、移除符号信息和查看运行依赖。这里的排查顺序从证据出发，不要求把工具列表逐个执行；strip 会修改文件，也不能把它当成只读查看命令。

回到全章：链接器把名称与定义连起来，并处理位置；加载器和动态链接器把文件接入进程；PIC、GOT、PLT 让地址变化和代码共享可以共存。第 8 章将接着解释进程怎样启动、异常控制流怎样让操作系统参与运行。第 8 章已备齐十课，可从章节首页进入。
