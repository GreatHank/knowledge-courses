04 · 重定位怎样修补地址

知道 sum 在哪里之后，怎样让指令真的跳到那里？

先识别要改的是哪四个字节

看偏移 e 开始的 call：e8 是操作码（opcode），后面四个零只是位移占位。下面一行 f: R_X86_64_PC32 sum-0x4 不是另一条指令，而是 objdump 把重定位信息放在旁边显示。

call 的起点是 0xe，要修补的字段从 0xf 开始，下一条指令从 0x13 开始。把这三个位置混成一个地址，就会算错那四字节位移。

重定位有两个层次

先布置节与符号

把输入模块的同类节合并并满足对齐要求，为它们决定输出位置，得到 sum 等符号的地址。

再修补引用字段

按重定位项（relocation entry）指定的位置与类型，计算需要写入的值。节之间未必紧密无缝拼接，可能有对齐填充。

本例重定位项含义
offset = 0xf待修补字段在输入 .text 内的偏移
symbol = sum引用的目标符号
type = R_X86_64_PC32写入相对引用字段地址的 32 位结果
addend = −4补偿字段起点到下一条指令之间的四字节距离

令 S 为目标符号地址，P 为被修补字段的运行时地址，A 为 addend。本例计算为：

写入值 = S + A − P

它是链接器计算字段的公式。CPU 执行 call 时，则把有符号位移加到下一条指令地址。这两个参考点通过 A = −4 接起来；不是所有重定位项都固定减 4。

把教材的地址代进去

S = 0x4004e8
P = 0x4004d0 + 0xf = 0x4004df
A = -4
S + A - P = 0x5

call 地址       0x4004de
下一条指令地址  0x4004e3
CPU 目标地址    0x4004e3 + 0x5 = 0x4004e8
写回指令字节    e8 05 00 00 00

低字节在前，是 x86-64 的小端表示。若目标在调用位置之前，位移可以为负，四字节字段按补码编码；但结果必须落在该有符号 32 位位移能够表示的范围内。

地址与公式

写回与执行
计算模型只改变这条 call 的布局，不生成或执行 ELF 文件。平移场景中 S 与 P 同增，差值保持不变。
绝对引用不用减去 P


图中 mov $0x601018,%edi 要把 array 的地址写进立即数字段。它对应 R_X86_64_32、A = 0，所以写入 S + A = 0x601018，四字节为 18 10 60 00。这里写入 %edi 会把 %rdi 高 32 位清零，因此这个低地址能正确成为指针。


相对引用（relative reference）保存距离，绝对引用（absolute reference）保存地址。固定布局的例子可这样修补；把所有模块任意搬到另一个地址，绝对字段未必还能用。后面的 PIC 会解决代码共享时的这类问题。


本课只取教材两种重定位类型说明机制。真实 ELF64 还有 PLT、GOT、64 位绝对引用等类型；不同编译选项可能生成不同指令和重定位项，不能期待字节完全复现教材。
