声明允许使用名字，定义提供实体

/* counter.h */
extern int count;
void tick(void);

/* counter.c */
int count = 0;
void tick(void) { ++count; }

这是补充示例。另一个源文件包含 counter.h 后，可以编译对 count 和 tick 的使用；真正的变量存储与函数实现由 counter.c 提供。多个文件包含同一份声明，与多个文件各自定义（definition）同名对象，是两回事。

符号解析（symbol resolution）要为引用找到对应定义。成功找到同名符号，不等于跨文件的 C 类型、调用约定（calling convention）与程序逻辑全部正确。

链接器的 local，不是“函数里面的变量”

C 中的对象链接器通常看到什么别混淆什么
文件作用域的普通函数或变量可供其他模块引用的全局符号“全局”描述可见性，不表示在任何进程中共享
文件作用域 static 函数或变量模块内部的局部链接器符号另一个文件可以有自己的同名 static
函数里的 static int x独立静态存储对象与局部链接器符号生存期贯穿程序运行，名字作用域仍在函数内
函数里的普通 int temp通常不是 .symtab 中的链接器符号可能放寄存器、栈上，或被优化掉；调试信息另算

教材用两个函数各自的 static int x 说明这点：编译器可以生成 x.1、x.2 一类不同内部名字。后缀只是教材示例，不应写代码依赖它。

看 value 之前，先看它属于什么

字段／标记怎样读
name字符串表里的偏移，不是把名字直接塞入表项
value可重定位文件中通常是节内偏移；不能直接当作最终虚拟地址
section / Ndx指出所属节，或 UND、ABS、COMMON 等特殊标记
UND / UNDEF本模块引用该名字，但没有提供定义
ABS值不随普通节重定位而改变
COMMON尚待分配的公共符号；value 表示对齐要求，size 表示大小

教材 main.o 的符号表（symbol table）中，main 和 array 的 value 都是 0，却分别属于 .text 和 .data；这不表示它们占同一个位置。sum 的 UND 也不表示函数地址是零，而是还要到其他输入中找定义。

重复定义：把教材规则与工具链版本分开

教材采用的传统规则链接结果
同名的多个强定义报错，如两个 main 或两个已初始化全局 x
一个强定义与公共候选定义选择强定义
多个公共候选定义由链接器合并／选择，程序不应依赖某个模块“获胜”

教材把函数和已初始化全局变量称为强符号，把未初始化全局变量按当时的 common 行为称为弱符号。这里的教学说法不要与 ELF 中显式 STB_WEAK 绑定机械等同；COMMON 是节索引层面的特殊情况，WEAK 是另一项绑定属性。二者的字段定义与解析区别可参照 System V ABI 符号表说明。

版本补充：GCC 10 改成默认 -fno-common。把 int x; 放进被多个源文件包含的头文件，可能报重复定义；旧代码可用 -fcommon 恢复传统 common 处理。正确组织仍是头文件写 extern 声明、一个 C 文件提供定义。依据 GCC 10 官方迁移说明。

链接成功也可能留下类型错误

/* 一个模块 */
int y = 15212;
int x = 15213;

/* 另一个模块：错误地声明成了另一种类型 */
double x;
void f(void) { x = -0.0; }

教材在特定旧工具链和布局下让这两个 x 绑定到一起：一边按 4 字节 int 理解，另一边按 8 字节 double 写入，连相邻 y 也被覆盖。PDF 720 给出了当时的地址、警告和结果。这是错误程序的实例，既不是合法 C 程序的输出保证，也不能承诺当前 GCC 会照样链接。

回到图中“定义与引用”的连线：名称绑定只回答引用对应哪个实体。共享头文件使编译器更早看到一致的类型；模块私有对象用 static，可减少不必要的全局重名。
