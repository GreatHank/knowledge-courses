文件布局与运行布局是两个视角

先看图右边的大括号：若干节被放进一个代码段，另一些进入可读写数据段。节（section）便于链接器组织内容；段（segment）给加载器（loader）描述怎样映射一段文件内容、需要多大内存、允许哪些访问。节头表和程序头表（program header table）回答的是不同问题。

图里的 .symtab 和调试信息用于工具分析，不必作为这些可加载段映射到进程中。动态链接需要的 .dynsym 等信息另有用途；不能把“这张图不加载普通符号表”推广成“运行时不需要任何符号信息”。

同一段，为什么文件大小和内存大小不同

数据段字段教材值读法
off0xdf8文件中从这里取内容
vaddr0x600df8映射到这个虚拟地址附近
filesz0x228从文件提供的字节数
memsz0x230该段在内存中需要的总字节数
flagsrw−读写，不能据此当作可执行指令区
align0x200000vaddr 与 off 对此值取余须一致

0x230 − 0x228 = 8 字节

额外八字节由零初始化存储解释，不需要在文件里存八个零。对齐也不是让 vaddr 自己整除 align：这里要求的是 vaddr mod align = off mod align = 0xdf8。

这些是教材中一个具体文件的条目，不是所有 Linux 可执行文件都只有两段，也不是所有段都按 2 MiB 对齐。文件偏移、虚拟地址、物理地址不可混用；本课不靠 paddr 字段推断实际物理内存位置。

“装入”先建立映射，不要求一次读完整个文件

execve 替换当前进程映像

shell 的典型启动路径会先创建子进程，再由子进程调用 execve。创建进程与替换映像是两件事，第 8 章再展开。

按需把页面带入内存

加载器依据文件头建立虚拟内存映射。后续访问到尚未就绪的页面时，由操作系统处理；不能把教材的“复制进内存”理解成无条件预读全部程序。

这对应 PDF 736 的旁注 How do loaders really work?。本课先保留“文件区域 ↔ 虚拟地址区域”的关系；具体缺页、页表和物理页共享留到第 9 章。初始化、动态链接等启动工作也会触碰一部分页面，因此“按需”不意味着启动完全没有磁盘或内存活动。

进入程序，不是立即跳到 main

位置这一阶段做什么
加载器依据可加载段、入口和解释器信息准备映像
动态链接器（若需要）装入依赖库并完成必要的绑定和重定位
程序入口／启动代码教材常规 C 程序从 _start 进入，接上运行库初始化
main开始用户编写的主函数；返回值随后交给运行库处理

章节图中“加载器 → 动态链接器”的边标着“动态程序交接”。全静态程序的路径不同，不需要把这一步也硬套进去。教材使用 _start 与 __libc_start_main 解释常规 C 运行时；ELF 的入口由文件头指定，不能定义成“任意 ELF 的入口都必然叫 _start”。

教材的 0x400000 等地址属于示例布局。后续讨论地址随机化与位置无关可执行文件时，不应把它们当成机器永远固定的边界。这些地址由文件布局与运行环境共同决定。
