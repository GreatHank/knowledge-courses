本章反复修改的是同一件事

给定 [2, 3, 5]，求和得到 10，求积得到 30。把一组元素合并成一个值，称为归约（reduction）。教材用 combine1 到 combine7 追踪不同实现。

沿原图的 data 箭头看：结构体里存的是地址，真正的元素在另一块连续存储区。len 是元素数，不是字节数。本章的“向量”首先指这个数据结构；它与后面 SIMD 指令中的向量寄存器要分开理解。

typedef long data_t;
typedef struct {
    long len;
    data_t *data;
} vec_rec, *vec_ptr;

#define IDENT 0
#define OP +

这是教材类型定义在求和情形下的组合。IDENT 是不改变结果的单位元（identity element）：加法用 0，乘法用 1；OP 分别换成 + 或 *。下面都假定向量有效，长度非负，数组确实含有相应元素。

先把循环里每件工作数出来

/* combine1，教材图 5.5 */
*dest = IDENT;
for (long i = 0; i < vec_length(v); i++) {
    data_t val;
    get_vec_element(v, i, &val);
    *dest = *dest OP val;
}
位置每轮在做什么是否一定要每轮做
循环条件调用 vec_length(v)若长度和调用效果不变，可以移出
取元素调用函数并检查下标是否可省，要先证明访问有效
累积读写 *dest能否延后写入，取决于别名等条件

这段代码清楚地使用了数据抽象（data abstraction），问题在于抽象接口的调用发生得很频繁。没有必要因此放弃抽象：先判断重复工作能否移到循环之外。

长度不变，就只求一次

原来的循环条件

for (i = 0; i < vec_length(v); i++) {
    /* 使用第 i 个元素 */
}

正常完成 n 轮时，条件求值 n + 1 次。

combine2 的做法

long length = vec_length(v);
for (i = 0; i < length; i++) {
    /* 使用第 i 个元素 */
}

函数只调用一次，循环中比较局部变量。

把重复而结果不变的计算移到执行次数更少的位置，叫代码移动（code motion）。这里需要调用没有必须保留的副作用，而且循环内不能改变长度。条件不成立时，提前计算会改变行为。

教材参考机上，整数求和的 CPE 从 10.12 降到 7.02；浮点乘法则仅从 11.14 变为 11.03。移除一项开销，收益取决于它是否正在限制执行。

strlen：循环条件本身可能扫描整个输入

反复扫描

for (size_t i = 0; i < strlen(s); i++)
    if (s[i] >= 'A' && s[i] <= 'Z')
        s[i] += 'a' - 'A';

每次检查条件都从头找字符串结尾。n 次改字母，夹着约 n 次长度扫描。

先确定长度

size_t n = strlen(s);
for (size_t i = 0; i < n; i++)
    if (s[i] >= 'A' && s[i] <= 'Z')
        s[i] += 'a' - 'A';

长度扫描一次，再按下标处理一次。

字符数变化反复 strlen 的工作量移出 strlen 后
nΘ(n²)Θ(n)
2n约为原来的 4 倍约为原来的 2 倍

这是根据教材 lower1/2 改写的 ASCII 字符串示例，需包含 <string.h>。假定字符串可写且以空字符结尾；只改 A–Z，不改变终止符的位置。这些条件使长度在循环中保持不变。它不是 Unicode 大小写转换程序。

这里的复杂度分析针对仍在每轮执行长度扫描的实现。具体编译器是否消除了扫描，应看生成代码；不能把教材对当时编译器能力的描述当作所有版本的永久限制。
