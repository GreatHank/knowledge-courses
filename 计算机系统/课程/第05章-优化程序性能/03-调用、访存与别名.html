去掉循环里的函数调用，可能还没变快

若已知下标满足 0 ≤ i < length，可以先取得数组首地址，循环里直接访问 data[i]。这是 combine3 的做法。

long length = vec_length(v);
data_t *data = get_vec_start(v);
*dest = IDENT;
for (long i = 0; i < length; i++)
    *dest = *dest OP data[i];

这让循环不再反复调用取元素函数，也不再重复做边界检查（bounds checking）。代价是实现开始依赖“数据存为连续数组”这一表示。教材中 combine2 到 combine3 的 CPE 没有明显改善：浮点乘法仍为 11.03。主要瓶颈还在别处，后面的优化才会用到这一步提供的条件。

跟踪累积值：每轮都读回再写回

combine3：内存里的累积值

vmovsd (%rbx), %xmm0
vmulsd (%rdx), %xmm0, %xmm0
vmovsd %xmm0, (%rbx)

%rbx 指向 dest，%rdx 指向当前元素。每轮读旧积、读元素、写新积。

combine4：寄存器里的累积值

vmulsd (%rdx), %xmm0, %xmm0

%xmm0 保留上一轮的积；每轮只需读取新元素，最后统一写入 dest。

这是教材针对 double 乘法展示的循环核心，省略相同的指针更新和分支。vmulsd 在这里做标量双精度乘法；指令名带 v，并不意味着此处同时计算多个数组元素。

局部变量给编译器留下把值保存在寄存器中的机会。不能反过来断言所有局部变量都在寄存器里；第 7 课会看到寄存器不足时的情况。教材参考机的浮点乘法 CPE 从 11.03 降到 5.01。

一个反例，就能说明为什么编译器要谨慎

现在让 dest 指向数组的最后一个元素。两版都从新的 [2, 3, 5] 开始，乘法单位元为 1。

阶段combine3：直接写 destcombine4：局部 acc
初始化数组变为 [2, 3, 1]acc=1；数组仍是 [2, 3, 5]
乘 data[0]最后一项写成 2acc=2
乘 data[1]最后一项写成 6acc=6
乘 data[2]读到自己写入的 6，结果 36读到原来的 5，acc=30
结束[2, 3, 36]最后才写入，得到 [2, 3, 30]

看表中的“乘 data[2]”这一行：读取的对象相同，读到的版本不同。延后写入改变了未来的输入。因此两版不能对所有别名情况互换。若接口保证输出位置与输入数组不重叠，且没有其他相关可观察效果，才可以据此论证这项改写。

保留必要的写，也能消除多余的读

教材还展示了 -O2 生成的一种实现：累积值保存在寄存器中，但每轮依然写回 dest。这样可以省去下一轮读取旧积的动作，同时使后续 data[i] 仍能读到别名（aliasing）位置被更新后的值。

/* 教材生成代码的核心含义 */
acc = acc * data[i];
*dest = acc;

不要把“消除读取”和“推迟写入”视为同一变换。前者在这段代码里可以保留逐轮写入的行为，后者正是上面反例产生差异的原因。

回到总图：这一课减少了重复访存，却留下 acc 对上一轮结果的依赖。下一课解释为什么乘法器即使能接收更多任务，也可能只能等。
