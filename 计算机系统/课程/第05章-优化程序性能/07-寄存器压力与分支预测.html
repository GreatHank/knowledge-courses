10 个累积器改为 20 个，反而变慢

先看表最右一列的浮点乘法：CPE 从 0.52 变成 0.68。单个累积器的依赖链确实更短了，但程序还必须保存所有这些同时活跃的值。

寄存器放得下

vmulsd (%rdx), %xmm0, %xmm0

acc0 在寄存器中；更新时读一个数组元素。

部分累积值放到栈上

vmovsd 40(%rsp), %xmm0
vmulsd (%rdx), %xmm0, %xmm0
vmovsd %xmm0, 40(%rsp)

先从栈中读 acc0，再计算，再写回。多出来的访存进入循环。

这是教材的汇编对照。编译器把暂时放不进可用寄存器的值存到内存，称为寄存器溢出（register spilling），与数值越界的“算术溢出”不同。数组指针、下标和其他中间值也要占寄存器，因此不能把累积器数直接设为架构寄存器总数。

本章采用教材的 x86-64/Haswell 环境。硬件寄存器重命名能缓解名字依赖，但不会给这份机器代码自动增加更多可编码的累积器寄存器，也不会自动删掉编译器已经生成的栈访问。

分支预测错一次，哪些工作白做了

执行阶段预测正确预测错误
按预测路径取指、译码提前准备后续工作准备了错误路径的工作
执行并确定真实方向继续使用正确结果取消错误路径上较年轻的结果
继续取指与执行保持连续推进转向正确地址，重新补充流水线

代价主要来自丢弃工作和恢复正确路径，数值取决于处理器与具体代码。教材参考机测得的约 19 拍惩罚不能套到每种 CPU。第 4 章 PIPE 的固定气泡规则也不能直接当成这里的时序。

循环尾部的分支通常呈现长串相同结果，往往容易预测。边界检查若一直通过，也可能与较慢的算术链重叠。教材 combine4b 加回边界检查后，浮点乘法仍为 5.01 CPE；但整数加法从 1.27 增至 2.02。可预测不等于免费，只是它未必成为主要瓶颈。

把“选择执行”写成“选择结果”

考虑两个不重叠的有效数组。在每个位置，把较小值放入 a，较大值放入 b。

有条件地交换

if (a[i] > b[i]) {
    long t = a[i];
    a[i] = b[i];
    b[i] = t;
}

随机数据可能让条件方向难以预测。

先算两个候选结果

long x = a[i], y = b[i];
long lo = x < y ? x : y;
long hi = x < y ? y : x;
a[i] = lo;
b[i] = hi;

编译器可能用条件传送（conditional move）选择值，避免条件跳转。

教材版本随机数据 CPE可预测数据 CPE
minmax1：条件交换约 13.5约 2.5–3.5
minmax2：条件选择约 4.0约 4.0

右侧写法根据教材示例加了 x、y 局部变量来明确“先读旧值”。表里的数值属于教材原版 minmax1/2，不能当作右侧改写在本机的测量。可预测输入下，原分支版本在教材实验里更快；因此不能规定所有分支都应改成条件传送。

什么时候不能提前求两个分支

long value = p ? *p : 0;

C 条件运算符只求被选中的那个表达式。p 为空时，*p 不能被提前作为普通 C 表达式求值。若两个分支含有副作用、无效内存访问或高昂计算，机械地“都算完再选”可能错误或更慢。

C 的 ?: 也不保证生成 cmov。要结合编译结果、实际输入的分布和测量来判断。回到总图的“07–08 · 其他性能限制”，下一课转向内存操作之间的依赖。
