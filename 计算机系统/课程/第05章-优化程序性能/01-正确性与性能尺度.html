两个指针，可能指向同一个数

先把 x 设为 3，令 xp 和 yp 都指向它。下面两段代码看起来都在“加两次”，结果却不同。这里只用小整数，所有中间结果都能由 long 表示。

分两次更新

*xp += *yp;
*xp += *yp;

第一次：3 + 3 = 6。
第二次再读 *yp，读到的已经是 6。
最后得到 12。

先乘 2，再更新

*xp += 2 * *yp;

右边先用旧值 3 算出 6。
再与原来的 *xp 相加。
最后得到 9。

对象xp 看见的值yp 看见的值
同一块内存，初始33
第一段更新一次后66
第一段更新两次后1212

两个表达式通过不同名字访问同一存储位置，称为内存别名（memory aliasing）。编译器若不能排除这里的别名，就必须保留两次读取所表达的含义。把两次加法合并，需要先证明改写对允许的输入成立。

函数调用也有可观察的效果

long counter = 0;
long f(void) { return counter++; }

/* 从相同的 counter=0 初态分别运行 */
long a = f() + f() + f() + f();
/* 另一版本：long a = 4 * f(); */

原式的四次调用返回 0、1、2、3，和为 6，counter 最终为 4；单次调用的版本得到 0，counter 最终为 1。这里用来说明调用次数的差别，不依赖四个调用从左到右求值。

修改全局状态就是一种副作用（side effect）。调用可能读写状态、执行 I/O，或根据外部状态返回不同结果。编译器在能看见函数体并证明安全时，可以内联或消除重复工作；只知道函数名时，不能默认它是纯计算。

安全优化的要求是保持 C 语言所保证的行为。C 的有符号整数溢出属于未定义行为；不能用“机器会回绕”替它建立正确性证明。这个边界贯穿后面的循环改写。

快多少，要先统一计量单位

看图的横轴 Elements，它数的是处理了多少个元素；纵轴 Cycles 数执行周期。教材对两组实测点拟合得到：

psum1

T(n) ≈ 368 + 9n

每多处理一个元素，约多花 9 个周期。

psum2

T(n) ≈ 368 + 6n

每多处理一个元素，约多花 6 个周期。

CPE（cycles per element） 是每个元素对应的周期成本；在线性拟合 T(n) ≈ K + CPE × n 中，它是斜率。固定开销（fixed overhead）K 包含计时代码、调用以及循环建立和结束等开销。短数组的 T(n)/n 还包含 K/n，不能直接当成斜率。

为什么不用“每轮循环的周期”？因为一轮可能处理 1 个元素，也可能处理 2 个。以元素为分母，才能公平比较展开前后的代码。周期也不等于指令条数，一拍可能有多条指令重叠执行。

这些拟合式来自教材实验，不是本机测试。跨机器比较还要考虑频率、编译结果和数据条件；后文的 Haswell 数值都保留这一来源限定。
