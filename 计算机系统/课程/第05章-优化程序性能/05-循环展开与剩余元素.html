两件事放进一轮，省掉的是哪些工作

每轮一个元素

acc = acc * data[i];
i++;

每个元素都伴随一次下标推进和循环控制。

每轮两个元素

acc = (acc * data[i]) * data[i+1];
i += 2;

一份循环控制处理两个元素；乘法仍是前后相依的两次。

这叫循环展开（loop unrolling）。教材把“一轮处理 2 个元素，使用 1 个累积器”记为 2 × 1；数字的后半部分不是线程数。

收尾循环4data[4]4 < n = 5
/* 教材 combine5 的 double 乘法形式，n 为非负 long */
double product2(const double *data, long n) {
    long i = 0;
    double acc = 1.0;
    for (; i < n - 1; i += 2)
        acc = (acc * data[i]) * data[i+1];
    for (; i < n; i++)
        acc *= data[i];
    return acc;
}

主循环判断 i < n−1，保证最大的下标 i+1 < n。收尾循环（cleanup loop）处理剩余 0 或 1 个元素。n=0 时两段循环都不读数组，返回乘法单位元 1。这里的 n 是有符号且非负的 long；若直接改成无符号类型，n=0 时的 n−1 会回绕，原判断不再安全。

一般的 k 路展开，每轮处理 i 到 i+k−1，共 k 项，最后留下 0 到 k−1 项。改写时要同时检查主循环范围、步长和收尾；只看“通常很长的数组”会漏掉短数组与非整倍数长度。

两次乘法仍连在同一条链上

再看 acc₁ 到 acc₂ 这条连线。把两次乘法放进同一轮，并没有删除它：第二次乘法仍要等第一次结果。如果每次乘法延迟 L，每轮需要沿链走 2L 拍，又恰好处理两个元素，依赖下界仍是 2L/2 = L。

整数加法原来还受循环控制开销（loop overhead）影响，展开使它更接近 1 拍的延迟下界。浮点乘法早已受单链依赖限制，所以没有明显收益。展开也会为进一步改变计算结构提供空间；下一课才真正拆开这条链。
