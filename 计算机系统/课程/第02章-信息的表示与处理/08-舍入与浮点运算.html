“装不下这么大的数”与“分不清相邻两个数”是两种限制。这里碰到的是有效位精度，尚未到 float 的最大有限值。

舍入：先找最近；恰好一半时才看偶数

先用只有两位二进制小数的简化例子：可表示点包括 1.00₂、1.01₂、1.10₂……。表中的中间值要舍入到这些点上。

需要舍入的精确值两个相邻候选距离情况就近偶数结果
1.001₂1.00₂ / 1.01₂正好一半1.00₂，最后保留位为 0
1.011₂1.01₂ / 1.10₂正好一半1.10₂，最后保留位为 0
1.0011₂1.00₂ / 1.01₂更接近后者1.01₂，无需看奇偶

round to nearest, ties to even 的“偶数”指最后保留位为 0。它不会把所有结果都凑成十进制偶整数，也不要求一律朝上。上一节的 16777217 在两个 float 的中点，就按这条规则落到 16777216。

一次运算，要在精确结果后再过一道舍入

浮点加法：x +f y = Round(x + y)
浮点乘法：x ×f y = Round(x × y)

这是教材用来定义运算结果的数学模型，不表示硬件必须先真的构造出无限精度数。硬件需要做到的是：结果与“精确计算后按规则舍入”一致。

输入时就可能舍入

0.1 的二进制展开无限长，存到 double 时已经变成邻近的可表示数。

运算后还可能舍入

两个已经可表示的数相加，精确和也未必可表示；还需要再次舍入。

在本课的 IEEE binary64、就近偶数模型中，0.1 + 0.2 的结果与按同一模型转换得到的 0.3 不相等。这是两次输入近似和结果舍入共同作用，不能用“十进制显示出来差不多”代替位级判断。

换括号，改变了舍入发生的位置

设 a=1016、b=−1016、c=1。下面严格按 binary64、每次加法后就近偶数舍入计算。

顺序第一次加法第二次加法最后结果
(a+b)+ca+b=0，精确0+1=1，精确1
a+(b+c)b+c=−9999999999999999，舍入为 −10000000000000000a+(−a)=00

这里的差别来自中间步骤丢失了 1。后面的抵消操作没法把已经丢掉的信息重新找回来。因此浮点加法通常不能随意使用实数加法的结合律；乘法也会受舍入与溢出影响。

这是明确了格式和舍入点的数值示例。C 编译选项、额外精度或允许重排运算的优化会影响实际执行，不能仅凭源代码括号猜所有编译环境的结果。

特殊值也参与规则，不能当普通实数

IEEE 情形结果或比较含义
正的有限结果太大（就近舍入）可溢出为 +∞没有回绕成某个很小的有限数
+∞ 与 +∞ 相减NaN不能据此推出 0
x 为 NaN，比较 x == x假NaN 不按普通数的相等关系处理
+0 == −0真数值比较相等，表示的符号位不同

这些是 IEEE 模型中的情形。源代码能否直接产生这些行为，还受所用浮点环境约束。识别 NaN 时用 isnan 这类分类操作；把它放进普通大小排序会失去熟悉的数轴关系。

数值转换，不是把原来的位原样换个名字

本书条件：32 位 int、IEEE float / double数值会怎样例子
int → float可能舍入，量级范围足够16777217 转为 float 可变成 16777216
int → double这些 int 均可精确表示double 有 53 位有效精度
有限 float → double保留原数值更宽格式能包含原格式的有限值
double → float可能舍入，或超出有限范围缩小范围和精度
float / double → int丢弃小数部分，向零取整；还须检查范围1.999 → 1；−1.999 → −1

例如整数 5 转成 float，数值还是 5，但原来的整数位模式不会原封不动保留。浮点数会重编码为符号、阶码和有效数。

有限浮点值转整数，如果截断后的整数部分超出目标范围，C11 行为未定义；不能把某条处理器指令的特殊结果当作通用答案。补充：C11 委员会草案 N1570，§6.3.1.4。上表采用本书 IEEE 格式；double 缩窄后超范围的具体行为另受语言实现与浮点环境约束。
