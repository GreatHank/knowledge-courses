先把一个整数拆开

第 1 章说“信息就是位加上下文”。现在把这句话落到四个字节上。设 unsigned int x = 0x01234567U;，在本书的 32 位 int 环境里，x 占 4 字节。

数值写法高位字节……低位字节
十六进制01234567
对应二进制00000001001000110100010101100111

先记两件事：一个字节是 8 位（本书平台）；一个十六进制数字正好表示 4 位。所以两位十六进制数恰好写出一个字节。

十六进制01234567
二进制00000001001000110100010101100111
十六进制89ABCDEF
二进制10001001101010111100110111101111

0x 是 C 中十六进制整数常量的前缀，末尾 U 表示无符号整数常量。这里的 67 是十六进制字节，数值为 6×16+7=103。

地址指定位置；字节顺序决定怎么摆

看原图里的地址 0x100：这是这个示例对象的起始位置，不是 x 的数值。地址每加 1，移动一个字节。四个字节依次占据 0x100、0x101、0x102、0x103。

大端 · big endian

低地址先放数值的高位字节 01，再放 23、45、67。

小端 · little endian

低地址先放数值的低位字节 67，再放 45、23、01。x86-64 使用这种顺序。

两种摆法表示同一个数。变化的是字节的地址顺序；字节内部的 8 位没有被反转。也不要把“低地址”与“数值低位”当作同一个概念。

本书先把程序看到的内存视为按字节编号的虚拟地址空间。这里解释的是程序里的地址模型；虚拟地址怎样映射到物理内存，第 9 章再展开。

用 C 真正查看这些字节

这段代码沿着对象地址逐字节读取。它是参照教材 Figure 2.4 改写的最小例子。

#include <stdio.h>

int main(void) {
    unsigned int x = 0x01234567U;
    const unsigned char *p = (const unsigned char *)&x;
    for (size_t i = 0; i < sizeof x; ++i) {
        printf("%02x ", (unsigned)p[i]);
    }
    putchar('\n');
    return 0;
}
写法在这段程序里的作用
&x取 x 的地址
unsigned char *把地址用于逐字节查看对象表示
sizeof x得到 x 占用的字节数
p[i]读取起始地址之后第 i 个字节

教材 x86-64 / Linux、4 字节 unsigned int、小端条件下，预期输出：67 45 23 01。这是按表示规则推导的输出，本课没有声称在本机编译运行。

同样写着 12345，存法可以完全不同

对象教材条件下的字节（从低地址起）解释方式
int n = 12345;39 30 00 004 字节整数，小端；12345 = 0x3039
char s[] = "12345";31 32 33 34 35 00ASCII 字符，末尾再加字符串终止字节
机器指令由目标指令集及具体编译结果决定CPU 按指令格式解码，不能按字符或整数随意解释

字符串里的 '1' 对应 ASCII 0x31；结尾 00 是 \0，不是字符 '0'（0x30）。字符串按字符次序存放，不把整个字符串当一个大整数再按大小端翻转。

这也解释了“同样的 C 源程序”为什么未必能直接拿同一份机器代码去另一类处理器运行：源代码表达操作，机器代码使用目标处理器的编码。

64 位程序，不代表每个变量都占 64 位

本书常用 x86-64 / Linux 数据模型字节数看到这个大小时应想到
char1一个字节；普通 char 的有无符号性另行判断
short2通常 16 位
int / float4整数与浮点数大小可以相同，编码不同
long / 指针 / double8宽度相同也不表示可以相互当作同一对象

这些是本书平台的数据模型，不是 C 对所有平台的统一尺寸规定。比如换操作系统或编译成另一种程序模式，long、指针等大小可能变化；直接查看 sizeof 才能确认具体程序。

回到章节图的 01 节点：先知道位在哪里、对象有多宽，下一课才能说明“对哪些位做运算”。
