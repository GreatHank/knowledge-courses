明明在做加法，怎么走回去了？

4 位无符号模型完整结果只留低 4 位结果值
12 + 710011（19）00113
15 + 110000（16）00000

完整的数学结果需要 5 位，这里只能保留 4 位。结果超过 15 后，保留低位就相当于减去 16。更一般地，w 位无符号加法就是把结果模 2w。

x +u y = (x + y) mod 2w

这里用 4 位演示机制；C 的 unsigned int 按该类型的完整宽度运算。两个较窄类型的变量相加，也不能直接当作 4 位或 8 位运算。

同一组低位，按补码读可能变成负数

4 位补码模型数学结果保留的位按补码解释
5 + 510，超出最大值 71010−6（比 10 少 16）
−8 + (−5)−13，小于最小值 −800113（比 −13 多 16）
−8 + 5−3，在范围内1101−3

补码截断模型仍保留相同的低 w 位，但结果所属的区间是 −2w−1…2w−1−1。正溢出（positive overflow）越过上界后落到负数侧；负溢出（negative overflow）越过下界后落到非负数侧。

同一位运算按无符号看按补码看
0111 + 0001 = 10007 + 1 = 8，没有越界7 + 1 超过 7，溢出
1111 + 0001 = 0000（丢出进位）15 + 1 越界−1 + 1 = 0，没有溢出

所以最高位以外有没有进位，和有符号结果有没有越界，是两个不同问题。

把“机器的低位”与“C 允许的结果”分开

图里从“数学上的完整结果”向下看无符号分支，再向右看有符号分支。无符号分支规定结果回绕；有符号分支中，只有结果在类型范围内，普通 C 算术才有这里预期的结果。

补码机器能给出低位结果，不等于 C 的 int 溢出就保证回绕。有符号整数运算越界是未定义行为（undefined behavior，UB）；编译器不必保留你预计的低位结果。

这是对教材位级模型的语言边界补充：补充：C11 委员会草案 N1570，§6.5 第 5 段。

因此，检测溢出的代码也分两种

unsigned：可以先算，再判断

unsigned s = x + y;
int wrapped = s < x;

x、y 都是 unsigned。回绕是定义好的；发生回绕时，s 会小于任一加数。

int：先检查数学范围

#include <limits.h>

int add_ok(int x, int y) {
    return !((y > 0 && x > INT_MAX - y) ||
             (y < 0 && x < INT_MIN - y));
}

只有 add_ok 返回真，才执行 x+y。两个减法分别在对应的 y 符号条件下执行，检查过程本身不会先发生溢出。

不能用“先算 s=x+y，再看符号有没有变”来检测普通 C int 的溢出：这会先触发本来想检测的问题。

取负：为什么最小负数没有正数搭档？

4 位补码模型逐位取反再加 1（保留 4 位）结果
5：010110101011−5
−5：1011010001015
−8：100001111000仍然是 −8

在固定 w 位补码模型中，取反再加一得到加法逆元（additive inverse）：两者相加低 w 位为 0。最小负数比较特殊，因为正的 2w−1 根本放不下。

表中的最后一行是位级模型。普通 C int 中的 -INT_MIN 仍然越界，示意中的位模式不代表这段 C 代码有确定输出。

乘法也丢高位，但全宽结果可能不同

同样的输入 101 × 011完整数学结果截为 3 位结果解释
无符号：5 × 315（001111）1117
补码：−3 × 3−9（110111，6 位补码）111−1

两种解释的操作数相差 2 的幂；乘积的差会落在被舍弃的高位里。所以只取低 w 位时，乘法位模式可以一致；要完整乘积、高位或判断有符号溢出，仍必须知道解释方式。

回到 05 节点：位宽决定保留哪些位，类型决定怎样解释它们，语言规则决定程序行为是否有定义。下一课用这些条件判断移位能否替代乘除法。
