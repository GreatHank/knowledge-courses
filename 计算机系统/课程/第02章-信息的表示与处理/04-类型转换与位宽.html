一个比较，怎么变了答案？

-1 < 0     // 1：两个 int，按有符号比较
-1 < 0U    // 0：int 与 unsigned int 比较，-1 转为 unsigned int
32 位 int / unsigned int参与比较的左值右值比较
-1 < 0−10真
-1 < 0U42949672950假

后缀 U 改变了右边的类型。对这一对同级的 int 和 unsigned int，比较前会把有符号操作数转为无符号；−1 变成 232−1。比较规则依赖的是转换后的操作数。

这个例子不能推广成“只要混入 unsigned，一切都变 unsigned”。不同等级的整数类型还要比较范围，并先考虑整数提升。先把当前 int / unsigned int 这一对看清。

同一宽度：位相同，解释不同

16 位例子位模式作为补码作为无符号
同一组位1100 1111 1100 0111−1234553191
转换关系0xCFC753191 − 65536−12345 + 65536

这是教材的例子。对补码模型，最高位从负权重换成正权重，总值就增加 2w。最高位为 0 时，两种解释相同。

转为无符号数按目标范围取模；越界转为有符号数在 C11 中由实现规定结果或信号。这里的“位不变”按教材补码平台解释。补充：C11 委员会草案 N1570，§6.3.1.3。

扩展：为什么有时补 0，有时补 1？

源类型与值原来的 3 位扩成 4 位为什么值不变
无符号 510101010×8 + 4 + 1 = 5
补码 −31011101−8 + 4 + 1 = −3
补码 +301100110×(−8) + 2 + 1 = 3

零扩展在左侧加 0，保留无符号值；符号扩展复制原最高位，保留补码值。位数增加提供更大范围，扩展本身不必改变数值。

这些扩展示例的目标能表示源值。同时改变符号与宽度时，按 C 数值转换规则处理。例如把 int 的 −1 转到更宽的无符号类型，结果是该目标类型的最大值，不是简单给原来的低位补 0。

截断可能丢掉数值信息。留下的位串能否继续表示原数，要同时看目标宽度和目标解释。截断为 k 位无符号数等价于模 2k；补码模型则在此基础上按符号权重解释。

把类型规则带回真正的程序

/* len、i 为 size_t，示意遍历 len 个元素 */
for (size_t i = 0; i < len; ++i) {
    /* 处理第 i 个元素 */
}

教材指出无符号长度的典型问题：如果写成 i <= len - 1，当 len 为 0 时，减法会回绕成很大的无符号数。直接表达 i < len，零长度时自然不进入循环。

常见误会应当追踪的环节
unsigned char 运算一定只有 8 位在本书平台，它常先提升到 int，再运算
比较运算不改变操作数类型隐式转换可能发生在真正比较之前
赋值到宽类型就能挽救前面的窄运算右边表达式先按自己的类型求值，之后才赋值
