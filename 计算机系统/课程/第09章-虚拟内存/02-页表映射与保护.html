两个进程既能隔离，也能共享

先看进程 i 的 VP 0：它指向 PP 6，允许用户读取，但不允许写入。再看进程 j 的 VP 1：它也指向 PP 6，却带着不同权限（permission）。两张页表能引用同一个物理页；是否允许某种访问，还要由各自的权限决定。

分配

程序需要连续虚拟区域时，背后的物理页可以散布在 RAM 中。

装入

把程序内容与虚拟区域联系起来，页面可以按需取得。

隔离与共享

独立映射保护私有数据；有意映射到同一物理页才能共享内容。

图中的 SUP、READ、WRITE 是通用示意位，不是第 5 课 Core i7 PTE 的逐位格式。权限按页检查，通常不能发现同一可写页内的小数组越界。

真正被替换的是页号，偏移原样保留

page_size = 1 << p
VPN = VA >> p
VPO = VA & (page_size - 1)
PA  = (PPN << p) | VPO

沿上方 VPN → 页表 → 下方 PPN 看一次查找：VPN 是虚拟页号（virtual page number），PPN 是物理页号（physical page number），再沿右边直线看偏移。页是等大的，而且页框（page frame）起点按页大小对齐，所以页内第 20 个字节仍是新页框内第 20 个字节。

设虚拟地址有 n 位、物理地址有 m 位，每页含 2ᵖ 字节。下面的位数由这些条件决定。

量含义位数
VPN虚拟页号n − p
VPO / PPO页内字节偏移，两者相同p
PPN物理页号m − p

在单级、等长 PTE 模型中，PTE 地址 = PTBR + VPN × sizeof(PTE)。其中 PTBR 是页表基址寄存器（page table base register），PTE 是页表项（page table entry）。算式给出“找到页表项”的地址；取出项中 PPN 后才构造“要读数据”的 PA。两个访存目标不要混为一谈。

遇到真正无权访问的区域，内核不能靠“把页读回来”解决。在 Linux 用户态，这类访问通常导致 SIGSEGV。也有可修复的暂时写保护，如私有映射的写时复制，需要结合区域属性判断。
