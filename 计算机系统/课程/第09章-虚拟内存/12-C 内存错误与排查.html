一处越界，为什么可能在 free 时才暴露

/* 错误示例：A 要存 n 个 int *，却按 int 分配。 */
int **A = malloc(n * sizeof(int));
for (size_t i = 0; i < n; ++i)
    A[i] = malloc(m * sizeof(int));

在本书的 x86-64 Linux LP64 背景下，int 常为 4 B，指针为 8 B。A 的第一层空间不足，后面的指针写入可能破坏邻居或分配器元数据（metadata）。写入当时若仍落在可写页中，MMU 不一定报错；直到以后读取坏数据或合并块时，问题才显现。

第一层应按 n × sizeof *A 计算，第二层按 m × sizeof *A[i]；仍须另做乘法溢出、分配失败和部分成功时的释放处理。这个修正解决尺寸错误，不自动解决整个函数的全部错误路径。

用四个问题查看一次访问

地址从哪里来

是否正确取得对象地址，是否属于仍有效的分配或存储期？

范围有多大

下标、字节数、字符串终止符和元素步长是否在边界内？

值是否已初始化

第一次读取前是否写过有定义的值？malloc 不保证清零。

寿命到哪里结束

是否已 free，或函数已经返回？还有没有悬空别名？

把两个易混的表达式拆开

*size--    /* 等价于 *(size--)：递减的是指针。 */
(*size)--  /* 递减 size 指向的整数。 */

int a[2];
int *p = a;
p + 1      /* 前进一个 int 元素，不是一个字节。 */

原书 PDF 910 对优先级的文字解释不准确：这里的 -- 是后缀运算符，结合得比一元 * 更紧，不能说二者同优先级再靠从右到左决定。代码本身的改法是对的。作者勘误也指出该段理由有问题；此处直接按表达式语法解释。作者勘误，§9.11.6。

指针算术（pointer arithmetic）还受对象边界限制。可以形成数组尾后一个位置的指针，用于比较和迭代终止；不能把该位置解引用成数组元素。页仍可写，也不会使越界或寿命结束后的访问变合法。

再补两种常见的所有权错误

/* 重复释放：第二次 free 违反接口条件。 */
free(p);
free(p);

/* 丢失旧指针：正长度 realloc 失败时，旧块仍存在。 */
p = realloc(p, new_bytes);

realloc 应先接到临时指针，失败时保留旧块并处理错误，成功后再更新拥有者。这里假设 new_bytes > 0，且大小计算已检查。给一个指针置 NULL 可以防止该变量被重复传入 free，但无法清除其他别名。

让工具指出第一次错误，而不是只看最后一次崩溃

clang -std=c11 -g -O1 -Wall -Wextra -Wpedantic \
  -fsanitize=address -fno-omit-frame-pointer demo.c -o demo
./demo

这是在支持 AddressSanitizer 的 Linux/Clang 环境中的诊断命令示例。它可帮助发现越界、use-after-free、double-free 等；未初始化值的追踪需要别的检查手段，例如 MemorySanitizer，不能说 ASan 覆盖本章所有错误。Clang AddressSanitizer 文档。命令未在本机执行。

排查时先保留触发输入和完整报告，找最早报告的非法读写，再沿“分配 → 初始化 → 使用 → 释放”回查。一次未报错只说明这条执行路径没有被工具发现相应问题，不能证明所有输入都正确。

把整章放回程序执行过程

CPU 用 VA 发起访问，TLB 和页表把它接到物理页；内核根据映射与权限处理缺页；分配器又在进程获得的虚拟区域里划分对象。页、块、C 对象属于不同层次，正确访问必须同时满足映射权限、对象范围和寿命条件。
