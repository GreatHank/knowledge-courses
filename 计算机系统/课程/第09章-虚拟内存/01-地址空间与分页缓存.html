从 fork 后的同名变量开始

int x = 1;
pid_t pid = fork();
if (pid == 0) x = 2;

第 8 章中，子进程修改自己的普通变量，不会把父进程的 x 也改成 2。两边甚至可能打印出相同的 &x。地址数值相同，为什么数据可以独立？这里的指针给出的是各自进程中的虚拟地址（virtual address，VA）。

看图中 4100 → MMU → 4：这两个数属于不同地址空间。内存管理单元（memory management unit，MMU）根据当前进程的映射找到物理地址（physical address，PA）。换了映射，同一个 VA 就可能指向另一个物理位置。原图只演示一次映射，不规定所有程序都从 4100 开始。

先分清“地址范围”和“已经占有的内存”

地址空间

一组可用于命名位置的地址。按字节编址的 n 位线性地址空间有 2ⁿ 个地址。

虚拟页 VP

把虚拟空间按固定大小分块。页大小为 2ᵖ 字节时，页内位置由 p 位表示。

物理页 PP

主存中的同大小页框。虚拟页可以映射到不同位置的物理页。

64 位指针不意味着处理器实际使用全部 64 位地址，也不意味着进程已经占用 2⁶⁴ 字节 RAM。还要区分：地址是否已建立映射、页面是否驻留、访问是否允许。

页表记录哪些页已经在主存

图中虚拟页状态读图方法
VP 0、VP 5尚未分配valid=0 且地址字段为 Null
VP 1、2、4、7已驻留实线连到 DRAM 中的某个 PP
VP 3、VP 6已分配，未驻留虚线指向磁盘中的内容

这是教材的简化页表（page table）。实际内核还用区域信息等数据结构区分“没有映射”和“暂不驻留”；不能只凭一个 present 位判断地址是否合法。书中把 DRAM 看作磁盘内容的缓存，叫作 DRAM cache，与第 6 章的 SRAM 数据缓存是不同层次。

缺页怎样使原指令得以继续

沿图 9.6 的 VA → PTE 3 看：它还没有驻留。硬件引发缺页异常，内核在本例选择 PP 3 中的 VP 4，必要时写回修改内容，再装入 VP 3、更新页表。返回后重新执行原访问，图 9.7 中的新映射就能完成它。

按需调页（demand paging）把装入推迟到需要时。本例涉及磁盘；匿名页首次写入、写时复制等缺页可以不读磁盘，第 6 课会展开。

局部性决定这套办法能否有效

程序近期反复使用的一组页叫工作集（working set）。只要它大体能留在主存，少数缺页之后，大多数访问就能直接完成；若活动页持续超出可用内存，系统可能频繁换入换出，出现抖动（thrashing）。

驻留集（resident set）说的是此刻留在 RAM 的页；工作集描述近期访问行为，两者不能简单画等号。回到章节图：有了“页与驻留状态”，下一课才能解释页表如何隔离、共享和保护。
