运行时才知道需要多少个元素

/* 伴读片段：n 已验证为正数，类型为 size_t。 */
if (n > SIZE_MAX / sizeof(int)) return -1;
int *a = malloc(n * sizeof *a);
if (a == NULL) return -1;
for (size_t i = 0; i < n; ++i) a[i] = 0;
/* 在有效范围内使用 a */
free(a);
a = NULL;

n 在运行时才知道，固定数组就很难选一个合适上限。动态分配器（dynamic memory allocator）接收字节数，返回可供对象使用的区域。它还得保存块大小、满足对齐（alignment），并为之后的释放留下管理信息。此片段需 <stdint.h>、<stdlib.h>，不含输入解析；乘法检查必须在分配之前。

释放后，地址可能仍可映射，但对象已经结束

沿 (b) → (d) → (e) 看 p2 对应的块：它先被分配，随后释放，最后部分空间被 p4 复用。free 不会替应用改写所有别名指针。即使旧指针位模式没有变化，原对象也不再可用。把 a 置 NULL 只改变 a 本身，不会修复其他别名。

接口必须记住的条件
malloc返回内存未初始化；申请失败检查 NULL
calloc分配数组并把字节清零；避免把全零字节泛化为所有类型的语义初值
freeNULL 可以传入；其他指针须是仍有效的分配起始指针，不能重复释放或传入中间地址
realloc对正的新大小，失败时原块仍有效；成功后应使用返回指针，原有别名需重新考虑

这些接口语义见教材 §9.9.1 与 malloc(3)。零长度 realloc 涉及版本与实现差异，这里只讨论正长度请求；free 也不保证立即把对应物理页归还操作系统。

两种碎片占的不是同一种空间

内部碎片

内部碎片（internal fragmentation）发生在已分配块内：块比请求的有效载荷（payload）更大，差额用于头部、脚部、对齐或未分割余量。它已经被圈在已分配块里面。

外部碎片

外部碎片（external fragmentation）是空闲空间分散的问题：空闲字节总数足够，但分散在多个块里，没有一个连续块能满足这次申请。

在图 9.34(d) 中，中间有 6 个空闲字，尾部有 2 个；若申请 8 个字，二者被已分配块隔开，不能直接当成连续的 8 字块返回。这里的连续指进程虚拟地址连续，与物理页是否相邻无关。

分配器同时在意速度与空间

指标或约束含义
吞吐率单位时间完成多少次分配和释放请求
峰值利用率Uₖ = maxᵢ≤ₖ Pᵢ / Hₖ；Pᵢ 是当时活跃请求的 payload 总量，Hₖ 是当前堆大小
应用对象不能任意搬动普通 C 分配器不能偷偷移动仍在使用的对象，应用手里的指针会失效
请求顺序不可预知必须处理各种合法申请／释放交错，不能假定栈式配对

利用率公式采用教材“堆只增不减”的模型；分子是此前活跃 payload 的峰值，不是累计 malloc 字节数。若缩堆，教材建议改用相应期间的堆高水位。只追求快速向后划空间会让 free 无法复用；只追求最紧的适配又可能增加搜索时间。
