局部指针消失，堆块不会自动跟着消失

void example(void) {
    int *p = malloc(100 * sizeof *p);
    if (p == NULL) return;
    /* 假设 p 没有保存到任何其他可达位置。 */
    return;  /* 遗漏 free(p)，普通 C 分配器不会自动回收。 */
}

函数结束后，局部变量 p 的寿命结束，分配出来的块却仍占着堆。垃圾回收器（garbage collector）尝试自动找出程序已经无法再到达的块。标准 C 的 malloc/free 不自带这一机制；教材讨论的是额外集成回收器的模型。

先沿引用找可达对象

看上图从 Root nodes 向下的箭头。根（root）可以来自寄存器、栈或全局位置；堆节点代表已分配块。只要存在一条从根出发的引用路径，块就可达（reachable）。图中蓝色环虽然内部互相引用，却没有从根进入的路径，因此仍不可达。

这里的边表示应用对象之间的引用，与上一课分配器内部的空闲链表指针无关。可达只说明程序还有途径访问，不保证未来一定还会使用；仍被全局容器引用的“用完对象”可能继续占空间。

Mark & Sweep 分成两次不同的遍历

阶段走哪种关系图中的结果
Mark 标记从根沿对象引用扩展，遇到已标记块就停止重复展开标记 4、3、1、6
Sweep 清扫按堆块布局扫描，不沿对象引用决定下一个块回收未标记的已分配块 2、5，并清除存活块本轮标记

mark 在递归访问子对象之前先标记当前块，因此遇到引用环不会无限递归。sweep 扫过的 nextBlock 是堆中的下一块；如果实际 free 会立即合并，遍历实现还必须与这种布局变化配合，不能不加分析地照抄伪代码。它不是可直接编译的 C。

C 中为什么需要“保守”识别

普通 C 内存没有为每个机器字附带“这是指针”的运行时标签。某个整数的位模式可能刚好落在一个已分配块的地址范围内；回收器难以确定它是真引用还是巧合。

保守保留

无法排除是指针时，把目标块也标为可达；可能多留垃圾，以免误收仍可访问的数据。

模型条件

必须能发现真实根与指针。隐藏、编码或以回收器不支持的方式保存指针，会超出该保证。

精确回收器（precise collector）依靠语言和运行时提供更多类型、布局信息；保守回收器（conservative collector）则可能把整数误认作指针。Mark & Sweep 的基本版本不移动存活块，所以不会自动消除全部外部碎片。回到章节图：自动回收解决一部分寿命管理，但不能替 C 程序证明每一次访问都合法。
