文件内容怎样成为指针可访问的字节

沿图中两条虚线看：文件中的一段字节范围，与进程中的一段虚拟范围建立联系。程序以后使用 load/store 访问映射；页面是否已经在 RAM，则由按需调页和缓存状态决定。内存映射（memory mapping）建立这种联系，不要求调用当场把整个文件复制进内存。

后备内容最初读到什么典型用途
普通文件映射文件区间内的字节程序代码、文件数据
匿名映射初始为零的内容堆、栈等运行时数据

零填充（zero fill）描述新匿名内存的初始语义；它不能推出 malloc 每次都返回全零。分配器可能把之前用过的块交给新对象。

共享和私有，区别出现在写入之后

MAP_SHARED

映射更新可被映射同一区域的其他进程看到；文件映射的更新可写回文件。共享本身不提供并发同步。

MAP_PRIVATE

本映射的修改不会写回文件，也不作为修改传播给其他进程的对应映射；可用写时复制实现。

MAP_PRIVATE 不保证文件在映射后被别人改动时，你仍看到一个冻结快照。MAP_SHARED 的可见性与何时写回存储也要区分，精确控制写回可涉及 msync。mmap(2)。

重新理解 fork 与 execve

操作地址空间的变化与物理页的关系
fork子进程获得自己的地址空间描述，普通私有数据保持独立语义私有可写页可先共享、写时分离；共享映射仍然共享
execve 成功同一 PID 换成新程序映像，旧用户映射被替换文件页和匿名页按新映像需要建立，不必一次性读入全部内容

这张图用于追踪内容来源。装载器实际按 ELF 段及其权限映射；共享库代码的物理页可以复用，但不能把图中整个“共享库区域”理解为所有可写数据都采用 MAP_SHARED。普通共享库的可写数据仍需保有进程私有语义。

读懂一个最小 mmap 片段

/* Linux 片段：len > 0，fd 是可读普通文件，文件至少有 len 字节。 */
void *base = mmap(NULL, len, PROT_READ, MAP_PRIVATE, fd, 0);
if (base == MAP_FAILED) {
    perror("mmap");
    return -1;
}
const unsigned char *bytes = base;
unsigned char first = bytes[0];
/* 使用 first；映射期间不得让文件被截短。 */
if (munmap(base, len) == -1) {
    perror("munmap");
    return -1;
}

NULL 让内核选择地址；偏移 0 满足页对齐要求；失败要比较 MAP_FAILED。匿名映射（anonymous mapping）使用 MAP_ANONYMOUS，fd 通常写 -1，offset 为 0。映射文件范围越过实际文件末尾的整页，或文件后来被截短，访问可能引发 SIGBUS，不能泛化成“所有超出文件的内容都补零”。接口条件据 mmap(2)；代码片段未在本机执行。

教材 PDF 870 把总分配量约束归结为 swap 大小，是过度简化。Linux 还受 RAM、提交策略、地址空间与资源限制等影响；严格提交模式的上限也包含配置比例的 RAM。Linux Overcommit Accounting。
