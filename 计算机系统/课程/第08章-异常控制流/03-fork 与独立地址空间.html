一次 fork，为什么会从同一行走出两条执行流？

先看 fork 前后的 x

原图中 fork 前 x=1。子进程（child process）执行 ++x，打印 2；父进程（parent process）执行 --x，打印 0。两边的普通变量互不覆盖，因此父进程不会因为子进程的加法而打印 1。

fork() 成功时创建子进程，父子都从调用返回处继续。所谓“一次调用，两次返回”，指成功创建后的两个执行流；创建失败时只在父进程返回 -1。

先用返回值辨认自己，再做各自的事

fork 返回值当前执行者应该怎样理解
-1父进程创建失败，没有新子进程
0子进程这是分支标记；不表示子进程的 PID 为 0
正数 pid父进程返回值是新子进程的 PID
pid_t pid = fork();
if (pid < 0) {
    perror("fork");
    exit(EXIT_FAILURE);
}
if (pid == 0) {
    /* 子进程路径 */
} else {
    /* 父进程路径，pid 标识刚创建的子进程 */
}

伴读代码片段，使用 POSIX fork；需要相应头文件和外围程序。教材的大写 Fork 是它的错误处理包装函数，不是另一个系统调用。

本章常见的系统调用失败约定是返回 -1 并设置 errno，但要逐个看接口。不要只检查 errno：成功调用不必把旧 errno 清零。错误处理发生在主流程时可以使用 perror；信号处理函数里的限制留到第 7 课。

哪些复制，哪些仍指向共同对象

对象fork 后的关系实际影响
普通用户内存父子有各自的内存语义；Linux 常用写时复制实现普通 x 的写入互不影响
打开的文件描述符两边的描述符引用相同的 open file description可共享文件偏移；不能当作独立打开两次
stdio 用户缓冲区缓冲内容随内存状态继承fork 前尚未刷出的文本可能被父子各刷一次
程序计数位置都从 fork 返回处继续子进程不会重新从 main 开始

父子继承关系见 fork(2)。这里按单线程程序讲解；多线程父进程 fork 后，子进程在 exec 前还受异步信号安全操作的限制。

“写时复制（copy-on-write，COW）”说明实现可以延后复制物理页，不改变普通变量各自独立的语义。stdio 重复输出则来自两份缓冲区；它与文件描述符引用共同的内核对象发生在不同层。

用进程图列出允许的次序

每条父子路径上的程序顺序必须保留，分叉后不同路径的事件却可交错。要判断某个输出是否可能，先检查它有没有违反一条路径上的先后约束；不要凭“父进程通常先运行”排除情况。

连续 n 次 fork 只有在所有现存进程都执行每次调用、每次都成功、途中没有退出或分支跳过时，才得到 2ⁿ 个进程。画出控制分支比直接套公式可靠。
