一条 shell 命令，经过了哪些控制转移

看到的动作本章机制应观察的状态
输入命令，shell 开始执行它fork 创建子进程父子 PID 与分支
子进程开始运行另一份程序execve 替换映像PID 保留，程序映像改变
程序请求读取或写入系统调用进入内核返回值、错误、是否阻塞
CPU 去执行其他进程上下文切换运行状态与调度，而非 C 函数调用栈
孩子结束，shell 得到通知SIGCHLD 与处理函数待处理／屏蔽状态
提示符再次出现前台等待完成或后台启动返回孩子是否已回收、作业表是否一致

这里按一个普通外部命令的执行过程排列；章节总图则表达机制之间的关系。fork、execve 和信号不是每个程序都必须依次调用的流水线。内建命令、后台作业和没有子进程的程序会走不同路径。

程序“卡住了”，先区分在做什么

CPU 使用率高

可能在计算，也可能在忙等某个永远不变的条件。需要结合执行位置判断。

CPU 使用率低

可能在等 I/O、等子进程或等信号；也可能被停止。低占用本身不说明正确。

例如第 8 课的错误 pause 循环：孩子已经回收，标志也已设置，但父进程在错过通知后睡下去了。单看“没有孩子了”无法解释卡住；把检查、处理函数、pause 的时序放回一起，才找得到原因。

反过来，作业表还留着记录也不证明进程活着。先回收后登记的竞态（race condition）会留下过期记录。内核进程状态和应用自己的表，需要分别核对。

每种工具只能看见一部分

工具或位置适合回答什么看不到或不能直接推出什么
psPID、父 PID、进程组、某一时刻的状态一次快照不能还原完整交错
top持续观察 CPU 与进程活动高占用不等于有效工作，低占用不等于死锁
strace系统调用和信号相关事件；-f 可跟踪创建的子进程不展示全部 C 函数调用，也不等于完整调度轨迹
pmap、/proc/PID/maps查看进程的虚拟内存映射映射大小不直接等于实际物理内存占用
信号与进程组信息解释通知目标、停止与继续父子关系不自动等于同一前台进程组
# Linux 阅读示例：先找出自己的目标进程，再把 PID 换成实际数值
ps -o pid,ppid,pgid,stat,comm -p PID

# 跟踪自己启动的简单程序及其孩子
strace -f ./hello

工具范围来自 §8.7；命令为伴读示例，未在本机执行。strace 会增加观测开销，轨迹也可能因观察而改变时序。ps 的 Z 常指僵尸、T 指停止、S 指可中断睡眠，要结合具体工具显示解释。命令选项另核对 ps(1) 与 strace(1)。

把常见现象交还给对应的机制

现象先查什么为什么
execve 后 PID 没变程序映像、执行路径execve 替换当前进程，不创建新 PID
孩子已退出，却还有 Z 记录父进程是否执行 wait／waitpid终止与回收分开
退出三个孩子，只进一次处理函数是否循环回收所有当前可回收孩子普通 SIGCHLD 可以合并
加一段 sleep 后似乎正常共享状态与事件先后关系延时只改变发生概率，没建立同步条件
解除屏蔽后马上进处理函数pending 集合被屏蔽时事件仍可发生
longjmp 后数据没恢复原样对象类型、修改与清理路径恢复执行环境不等于回滚内存

这些都是排查方向，不是只凭表面现象就作出的诊断。看不到证据时，应保留问题，不把一次正常运行当成竞态已消失。

从本章回到“程序怎样运行”

第 7 章解释程序怎样被链接和装入；本章说明运行中控制为什么会离开顺序路径，以及程序怎样管理这些转移。回看章节总图时，可以从“异常入口”走到“进程”，也可以沿 shell 的退出通知走到信号同步；两条路径在解释同一个运行环境的不同部分。

还有一个没有展开的问题：进程为何能各自使用相同数值的地址，fork 的独立内存又怎样避免立刻复制所有物理页？下一章《虚拟内存（virtual memory）》从地址翻译、页表、缺页和内存映射回答它。第 9 章十二课已准备，可从章节目录继续阅读。
