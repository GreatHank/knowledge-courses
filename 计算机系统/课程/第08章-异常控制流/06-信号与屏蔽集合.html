孩子退出了，父进程怎样知道

后台孩子结束时，父进程可能还在读取下一条命令。内核可通过 SIGCHLD 通知它：某个孩子的状态有变化。通知到达后，父进程再调用 waitpid 取得具体状态。

信号（signal）是向进程报告事件的一种软件通知。信号告诉父进程有事件发生；具体有哪些孩子可回收，仍要调用等待接口查询。图中 handler 属于用户程序，与第 1 课内核中的异常处理程序分处不同层。

发送、待处理、接收是三个时刻

时刻或集合含义常见误读
发送／生成事件使信号指向目标进程不保证处理函数立即执行
pending：待处理集合信号已经生成，尚未被接收处理普通信号的 pending 位不是计数器
blocked：屏蔽集合当前暂不允许接收的信号不阻止事件发生，也不阻止孩子退出
接收／递送未被屏蔽的待处理信号得到相应处置处置可以是默认动作、忽略或调用处理函数

用集合写就是 eligible = pending ∩ 非 blocked。这只说明哪些信号可以递送，不承诺多种信号的先后顺序。

Ctrl+C 发给谁，要看前台进程组

终端通常把 Ctrl+C 对应的 SIGINT 发给前台进程组（process group）。一个管道可以有多个进程，共同属于前台作业；信号目标由进程组决定，不是“把所有后代都杀掉”。Ctrl+Z 通常产生 SIGTSTP，SIGCONT 则可使停止的进程继续。

kill 的 pid 参数Linux 目标含义
pid > 0指定 PID 的进程
pid = 0调用者所在进程组
pid < -1组 ID 为 -pid 的进程组
pid = -1特殊的广泛目标规则，不能当作进程组 1

函数名 kill 不意味着只能终止；动作还取决于发送的信号和接收方处置。上表用于解释目标选择，不是在本机执行操作。详细边界见 kill(2)。

屏蔽要保存旧集合，结束时恢复

看原图的三步：把 SIGINT 加入集合；用 SIG_BLOCK 把它加入当前屏蔽；最后用 SIG_SETMASK 恢复 prev_mask。恢复旧集合比“把所有信号一律解除屏蔽”更准确，因为外层代码可能本就屏蔽了其他信号。

操作对当前 mask 的影响
SIG_BLOCK加入 set 中的信号
SIG_UNBLOCK移除 set 中的信号
SIG_SETMASK用 set 完整替换

SIGKILL 与 SIGSTOP 不能被捕获、忽略或屏蔽。Linux 的屏蔽集合（signal mask）按线程维护；本章例子按单线程进程解释，见 sigprocmask(2)。

fork 后孩子继承屏蔽集合，但初始待处理信号集合为空；exec 后屏蔽仍保留。暂时屏蔽 SIGCHLD 的 shell 因而需要让子分支在执行新程序前恢复原集合。下一课看处理函数本身怎样写才不会破坏被打断的代码。
