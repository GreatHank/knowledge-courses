结束执行后，还可能保留一条状态记录

终止 terminated

进程不再执行，主要运行资源被释放；内核仍需让父进程取得退出状态（exit status）。

回收 reaped

父进程通过等待接口取得状态，内核清理相应的终止记录。

已终止但尚未被回收（reaping）的子进程称为僵尸进程（zombie）。它不在继续占用 CPU 执行旧代码；保留下来的是供等待接口使用的状态等信息。

暂停的进程仍然活着，不能与僵尸混为一谈。一个后台作业结束后，shell 也必须安排回收，只是不用在启动它的那一刻阻塞等待（blocking wait）。

waitpid 的返回值比“等到了没有”更具体

返回结果含义下一步
大于 0某个匹配子进程发生了所请求的状态变化用返回 PID 确认对象，再按状态宏解释 status
0使用 WNOHANG，当前没有匹配的可报告变化这次没有有效的新 status，不要读成退出码 0
-1，errno=EINTR等待被信号打断根据等待目的重试或处理其他工作
-1，errno=ECHILD没有匹配的可等待子进程回收循环可结束；指定孩子的等待则需检查程序逻辑

默认选项 0 等待终止；如果还要观察停止或继续，需要相应选项。WNOHANG 只让本次等待不阻塞，不会让子进程更快结束。

先判断终止方式，再读取相应字段

int status;
pid_t r;
do {
    r = waitpid(child_pid, &status, 0);
} while (r < 0 && errno == EINTR);
if (r < 0) {
    perror("waitpid");
    exit(EXIT_FAILURE);
}
if (WIFEXITED(status)) {
    printf("exit=%d\n", WEXITSTATUS(status));
} else if (WIFSIGNALED(status)) {
    printf("signal=%d\n", WTERMSIG(status));
}

这是等待一个指定子进程的伴读片段。正常退出时才能取 WEXITSTATUS，它提供退出状态的低 8 位；被信号终止时应读 WTERMSIG。原始 status 包含编码信息，不能直接当作 exit 参数。

原图按实际可回收的孩子逐个返回；若要按创建顺序报告，可以保存各个 PID 后依次 waitpid。但这只规定父进程取状态的顺序，孩子仍可能以另一顺序结束。

给数组下标一个明确的边界

for (size_t i = 0; i < N; ++i) {
    pid_t r;
    do {
        r = waitpid(pids[i], &status, 0);
    } while (r < 0 && errno == EINTR);
    if (r < 0) {
        perror("waitpid");
        exit(EXIT_FAILURE);
    }
    /* 此处处理 pids[i] 的 status */
}

上段是伴读修正，假设 pids 中恰有 N 个成功创建且尚未被其他路径回收的孩子。教材 Figure 8.19，PDF 786 页 在 while 条件中使用 pid[i++]，没有 i<N 的检查；回收完 N 个孩子后再次判断会越界读取。这里先检查数组边界，不改动教材原页。

sleep 和 pause 不能代替条件同步

sleep 表达等待一段时间，不保证醒来那一刻另一个进程已完成某件事；被信号打断也可能提前返回。pause 等待信号，处理函数返回后它以 -1／EINTR 返回。把“检查状态”与“开始等待”分成两步，仍可能错过通知，第 8 课会逐步演示。

在当前 Linux 中，孤儿进程可被相应的 subreaper 或 init 接管。SIGCHLD 的默认动作与显式设为 SIG_IGN 对僵尸处理的效果也不能简单等同；见 waitpid(2) 的 NOTES。本章先保持通常的信号设置，由父进程负责回收。
