处理函数可能插在一次 printf 的中间

设主流程正在更新 stdio 的内部缓冲状态，信号插入后，处理函数（signal handler）又调用 printf。第二次调用可能看到更新到一半的状态。问题不是两个 CPU 同时运行：同一条执行流被插入一段代码，也足以出现重入冲突。

异步信号安全（async-signal-safe）要求函数能在这种异步插入的环境里使用。线程安全（thread safety）不能自动推出信号安全；靠锁实现线程安全的函数，也可能在处理函数里等待被中断代码持有的锁。

让处理函数只做明确允许的事

做法本章需要记住的条件
printf、malloc、exit通常不应放入异步信号处理函数
write、_exit、waitpid属于 POSIX 异步信号安全接口；仍需考虑错误，write 也可能阻塞
volatile sig_atomic_t 标志适合简单赋值和读取；不因此获得任意复合操作的原子性
保存并恢复 errno处理函数调用可能改写 errno，返回主流程前应恢复

接口范围见 signal-safety(7)。教材的 Sio_* 是配套支持库函数，使用时需要它的信号安全实现。volatile 也不能用来代替多线程锁或内存同步。

static volatile sig_atomic_t noticed;

static void on_signal(int sig) {
    (void)sig;
    noticed = 1;
}

这个片段只登记“至少来过一次”，不计数。noticed++ 是读、改、写的复合操作，不能从类型名字推导它在所有情形下不可打断。主流程何时读取和清零仍需安排，尤其要避免检查后错过通知。

一次 SIGCHLD，可能需要回收多个孩子

假设三个孩子在信号被屏蔽时先后退出，父进程只看到一个待处理的 SIGCHLD。处理函数因此应查询到没有当前可回收的孩子为止，不能固定“一次信号只 wait 一次”。

static volatile sig_atomic_t reap_error;

static void reap_children(int sig) {
    int saved_errno = errno;
    (void)sig;
    for (;;) {
        pid_t p = waitpid(-1, NULL, WNOHANG);
        if (p > 0) continue;
        if (p == 0) break;
        if (errno == EINTR) continue;
        if (errno != ECHILD) reap_error = 1;
        break;
    }
    errno = saved_errno;
}

伴读片段有意丢弃退出状态，假设本程序统一在此回收所有孩子，主流程检查 reap_error 并报告异常。若还要维护作业表，应保存必要状态并保护共享数据，不能再让另一条路径抢着回收同一孩子。

原图使用选项 0 的阻塞等待，并用 sleep 展示通知合并。上面的 WNOHANG 改写只收走当前已终止的孩子；若仍有孩子在运行，返回 0 后退出处理函数，不把处理函数挂在等待活孩子的位置。

sigaction 明确规定处理函数运行时的环境

看原图的三个字段：sa_handler 指定处理函数，sa_mask 指定处理期间额外屏蔽的信号，sa_flags 选择行为。通常，正在处理的信号本身也会暂时加入屏蔽集合；其他未屏蔽信号仍可能嵌套进入。

SA_RESTART 只会让某些被打断的接口自动重启，不保证所有阻塞调用都无需处理 EINTR。具体规则见 sigaction(2)。安装处理函数时也要检查 sigaction 的返回值；教材的大写包装函数负责其错误路径。
