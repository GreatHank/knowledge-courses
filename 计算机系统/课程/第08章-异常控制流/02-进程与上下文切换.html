两个程序的指令，可能交错使用同一个核

先沿 A 的线向下看：它中间有空白，但再次运行时会接着先前的位置执行。再横着看某一时刻：在单核模型中，只有一个进程正在使用这个核。

进程（process）是正在执行的程序的一个实例。同一个可执行文件可以启动多个进程，每个实例有自己的运行状态。教材强调两种抽象：一条逻辑控制流（logical control flow），以及一个私有地址空间（private address space）。

并发看时间交叠，并行看是否同时执行

并发 concurrent

两个执行流在时间上有交叠。A 暂停时 B 可以前进；单核交错也能并发。

并行 parallel

两个执行流在同一时刻实际运行，需要相应的硬件执行资源。

原图 A 与 B 并发，A 与 C 也并发；B 与 C 的时间段没有交叠。并发不要求指令逐条轮流执行，也不能从图中空白的长短推算调度算法。

进程恢复运行时能接着原来的寄存器状态和指令位置执行；从整个机器看，它的运行被其他活动插开了。

私有地址空间，使相同地址可以指向不同内容

观察对象进程 A进程 B
同一数值的虚拟地址按 A 的映射解释按 B 的映射解释
普通局部变量 x由 A 的程序修改通常不随 A 的修改而变化
显式共享映射可以映射共同的对象需要另行考虑共享与同步

这里说的是地址空间的抽象，不是承诺每一页都独占一份物理存储。代码页可以共享，fork 可以借助写时复制，程序也能显式建立共享映射；第 9 章解释映射如何做到这些。

教材中的固定起始地址来自其示例布局。实际程序是否采用位置无关可执行文件、是否启用地址随机化，都会影响地址，不能把某个图上的数值当成所有进程的固定位置。

上下文切换保存的是“接着运行所需的状态”

沿 A 的 read 向下：A 先进入内核；如果读取还不能完成，内核可保存 A 的上下文（context）并恢复 B。设备完成工作时，中断使内核有机会处理完成事件；A 变为可运行后，调度器会在适当时机恢复它。

上下文包括寄存器、程序计数器、栈及内核维护的相关状态。切换要让 B 使用自己的寄存器状态和地址空间，不能只把 PC 改成 B 的地址。

用户模式 → 内核模式

权限级别发生变化。内核可以仍在替 A 完成系统调用；不一定换进程。

进程 A → 进程 B

正在执行的进程发生变化，需要保存和恢复上下文。内核负责这个切换。

“阻塞等待 I/O”与“被作业控制信号停止”也是不同状态。前者在事件完成后可继续竞争 CPU；后者通常需要继续信号。下一课从观察切换转到主动创建进程。
