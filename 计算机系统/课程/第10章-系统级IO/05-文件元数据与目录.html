文件里装了什么，与文件本身是什么

图 10.9 的 st_size、st_mode、st_ino 等字段属于元数据（metadata）。stat(path, &st) 从路径查询，fstat(fd, &st) 从已经打开的描述符查询；它们不把文件正文读入缓冲区。

字段／判断含义容易混淆之处
st_size普通文件的字节长度不等于已分配的磁盘块数。
S_ISREG(st.st_mode)是否普通文件st_mode 也包含权限，需用对应宏判断类型。
st_ino文件系统中的 inode 编号不是数据的内存或磁盘地址；跨文件系统不能只比这个数。
st_mtime / st_ctime内容修改时间／状态变更时间ctime 不是文件创建时间。

图中 read: yes 究竟证明了什么

看图 10.10 第 15 行：它只检查 S_IRUSR，即“所有者读权限位是否设置”。这个 yes 不能直接证明当前进程一定读得了文件；当前身份、组、其他权限机制和路径访问也会影响结果。真正打开时仍须检查 open 的返回值。字段与权限说明见 Linux stat(2)。

目录也是文件，为什么要用 readdir

看 stream → de → d_name：opendir 建立目录流（directory stream），readdir 每次提供一个目录项（directory entry），d_name 是该项的名字，最后 closedir 释放目录流。不要把“Unix 用统一文件接口”理解成应用能用普通 read 可移植地解析任意文件系统（file system）的目录布局。

目录项

把名字联系到文件。一次 readdir 返回一个目录项，不能把它当成 read 读出的一行文本。

返回对象的寿命

下一次 readdir 可能覆盖返回的存储；需要长期保留名字时自己复制。

可移植字段

不要依赖 d_name 固定为 256 B，也不要假定 d_type 总能给出文件类型。

NULL 同时可能表示结束和错误

/* 已有有效 DIR *stream；这里只展示每次调用的判定。 */
for (;;) {
    errno = 0;
    struct dirent *de = readdir(stream);
    if (de == NULL) {
        if (errno != 0) perror("readdir");
        break;
    }
    puts(de->d_name);
}
/* 随后调用 closedir，并检查其返回值。 */

每次 readdir 前清零 errno，返回 NULL 后立即判断。这样循环体中其他调用对 errno 的影响不会被误判成目录读取失败。图 10.11 为简短示例，只在循环前清零；上面的改写突出更明确的判定范围，未展开输出与关闭错误的完整处理。见 Linux readdir(3)。
