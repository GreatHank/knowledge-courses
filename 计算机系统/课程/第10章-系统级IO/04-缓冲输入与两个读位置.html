读到第一行之后，还有多少数据留在里面

文件内容（转义表示）："ab\nCD\nXY"
其中 \n 代表一个换行字节；文件共 8 B。

假设教学缓冲区只有 8 B，一次内核 read 取得全部数据。rio_readlineb 只交出 ab 和换行共 3 B，另外 5 B 留在 rio_t 中。教材实际缓冲区大小是 8192 B；演示缩小它便于逐字节观察。

单独打开交互图 · Archify 伴读示意；关键关系均显示在图中。

看“内核 read → 用户态输入缓冲区（user-space input buffer）”：这条线搬来一批字节。再看“缓冲区 → rio_readlineb → 调用者数组”：每次可以只取其中一部分。两条线处理的字节量不必相同。

逐步查看两种位置

可逐步操作的教学模型；状态按下述规则计算，没有实际调用 Linux I/O。

    第一行已返回时状态下一次读取从哪开始
    内核文件偏移8原始 read 从文件末尾开始。
    rio_bufptr指向 CRIO 从缓冲区剩余内容继续。
    rio_cnt5这 5 B 尚未交给调用者。

    在这个固定文件例子里，混用原始 read 会立刻得到 EOF，但 RIO 内仍有 CD\nXY。数据没有被内核丢掉；程序绕过了保存它们的那份用户态缓冲区。

    rio_t 保存哪些状态

    看图 10.6：rio_fd 记录输入描述符，rio_cnt 记录未消费字节数，rio_bufptr 指向下一字节，rio_buf 是保存数据的数组。rio_readinitb 只设置初始状态，不会当场读取文件。图 10.5 每次用返回的 n 写出数据，因此写出的数量不靠 strlen 猜测。

    沿第 5–15 行看补充过程：只有 rio_cnt ≤ 0 才调用内核 read；得到新数据后把指针放回数组开头。第 18–25 行复制 min(n, rio_cnt)，再同时更新指针与计数。向内部 rio_read 要 1 B，通常只是一次内存复制。

    按行读与按数量读共用这一份缓冲

    接口停止条件返回数据
    rio_readlineb(rp, buf, maxlen)换行、maxlen−1 个字节、EOF 或错误非空成功结果后补 NUL；NUL 不计入返回值，读到的换行计入。
    rio_readnb(rp, buf, n)凑够 n、EOF 或错误字节块；不会补字符串终止符。

    例如 abcdef\n 配合 maxlen=4，连续返回 abc、def、\n，然后才遇到 EOF。长行剩余部分保留给下次调用；一次 readlineb 返回不一定代表一条完整逻辑行。本课使用 maxlen≥2 且目标数组至少有 maxlen 字节。

    EOF 前已有字符时，readlineb 返回这部分字符；EOF 前一个字符都没有时返回 0，教材代码直接退出，不应依赖它此时替你写入 NUL。若输入可能包含 NUL，返回的字节数仍有意义，但字符串函数会在 NUL 处停止。

    可以交替调用，但必须共享同一个状态对象

    readlineb 与 readnb 可以在同一 rio_t 上交替使用，因为它们看见同一份未消费数据。另建一个 rio_t 绑定相同 fd，并不会自动共享这份缓冲。

    教材称缓冲 RIO 例程具有线程安全性，应理解其状态由各自 rio_t 保存；多个线程并发修改同一个 rio_t 仍需同步。回到章节图：明确缓冲归谁管理，才能继续分清内核中的共享状态。
