open 返回的整数，怎样让程序找到一个文件？

同一段代码，可以读文件，也可以读终端

int fd = open("hello.txt", O_RDONLY);
if (fd == -1) { perror("open"); return 1; }
/* 后续用 fd 读字节；成功后由本程序负责 close(fd)。 */

这是 main 内的 C 片段，需 <fcntl.h>、<stdio.h>、<unistd.h>。路径只在打开时交给内核；成功后，read、write、close 使用文件描述符（file descriptor，fd）。fd 是本进程描述符表的索引。

路径名

目录层次中的名字，例如 /home/droh/hello.c。

文件描述符

open 返回的非负整数。它属于当前进程，不能单凭数值判断文件身份。

文件内容

普通文件中的字节序列。内核不会替应用判断它是 C 源码还是一张图片。

沿目录树把名字走完

看根目录 / → home → droh → hello.c，得到绝对路径（absolute pathname） /home/droh/hello.c。若当前工作目录是 /home/bryant，先用 .. 回到 /home，再进入 droh，所以相对路径（relative pathname）是 ../droh/hello.c。

原书 PDF 930 的示例写成 ../home/droh/hello.c；按图中的目录树，它会多走一层 home。本课按实际路径关系纠正。

Unix 文本通常用换行字节 0x0A 分行。文件末尾由长度与读操作的返回值表示，不需要在文件里放一个 EOF 字节。C 字符串末尾的 NUL（0x00）是另一回事。

打开时要决定哪些事

问题设置具体含义
能读还是能写？O_RDONLY / O_WRONLY / O_RDWR选择一种访问模式。
文件不存在怎么办？O_CREAT允许创建；本身不会清空已有文件。
从头覆盖还是追加？O_TRUNC / O_APPEND前者在适当写模式下清空普通文件；后者使每次 write 在文件末尾定位。

open 成功会返回当前未占用的最小描述符。常见 shell 环境把 0、1、2 分别接到标准输入（standard input）、标准输出（standard output）、标准错误（standard error）；如果其中某个已关闭，新的 open 也可能取得它。O_APPEND 管理每次 write 的追加位置，不把一串 write 自动合成一条不可分割的应用消息。接口细节见 Linux open(2)。

权限位为什么还要经过 umask

/* 仅说明参数：执行会创建或截断 out.txt。 */
open("out.txt", O_WRONLY | O_CREAT | O_TRUNC, 0666);

图中三组 r/w/x 分别对应所有者、组和其他用户。无默认 ACL 等额外规则时，新文件权限按 mode & ~umask 得到：0666 配合 0022 得到 0644，即 rw-r--r--。这是位掩码操作。mode 用于创建的新文件，不会重新设置已有文件的权限。

关闭的是哪个东西

普通文件的偏移也可以通过 lseek 调整；例如 lseek(fd, 0, SEEK_SET) 请求回到开头。定位本身不传送文件数据，终端、管道和套接字等对象也不一定支持定位。调用后仍须检查是否返回 -1。

close(fd) 释放这个描述符；它的数值以后可以重新使用。若其他描述符仍引用同一打开文件描述，它们仍能访问文件。关闭描述符不等于删除路径，也不等于数据已经持久化到磁盘。

应检查 close 的返回值。Linux 上发生错误后，盲目重试 close 可能误关已经复用的描述符；具体规则与可移植性见 Linux close(2)。
