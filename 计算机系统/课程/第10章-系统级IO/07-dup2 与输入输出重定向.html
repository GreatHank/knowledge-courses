shell 替程序接好了标准输出

./hello > out.txt

hello 仍然向标准输出（standard output）写。shell 在启动目标程序前，把它的 fd 1 接到 out.txt 对应的打开文件描述。程序继续使用同一个整数 1，数据去向已经改变。

看 fd 1 的实线：它从 File A 改接 File B。fd 4 的线没有改变。dup2 不复制 File B 的内容，也不修改变量中存着的整数；它调整的是内核描述符表的引用。原图的虚线表示旧内核对象在本例中不再有引用，不表示磁盘上的文件被删除。

为什么不自己先 close(1)，再 dup(4)

调用／条件结果
dup2(oldfd, newfd)，两个描述符不同且 oldfd 有效成功时，以原子方式关闭／替换 newfd 的占用，使其引用 oldfd 的打开文件描述。
oldfd == newfd，且有效直接返回这个描述符，不关闭它。
oldfd 无效失败；不会先把 newfd 关闭。

close 和 dup 分成两次调用，中间可能有信号处理等动作占用刚空出的描述符。dup2 把关闭与复用合在一个原子操作（atomic operation）中。它仍可能失败，应检查结果；规则见 Linux dup(2)。

把它放回 fork 与 execve 之间

/* 子进程中的示意片段，使用 csapp.h 错误处理包装。
   执行会创建或清空 out.txt；argv 与 environ 已由调用者准备。 */
int fd = Open("out.txt", O_WRONLY | O_CREAT | O_TRUNC, 0666);
Dup2(fd, STDOUT_FILENO);
if (fd != STDOUT_FILENO)
    Close(fd);
Execve(argv[0], argv, environ);

打开输出文件 → 改接 fd 1 → 关闭多余引用 → execve，这才是此处的执行顺序。fd 若本来就是 1，不能再把它关掉；execve 通常保留打开的描述符，带 close-on-exec 标志的描述符除外。

关闭临时 fd 后，fd 1 仍保存一份引用。若是在已有 stdio 缓冲的进程中临时改接输出，还要先妥善处理那些尚未提交的缓冲数据；下一课会区分这两层。

两条看似相同的命令，stderr 去向不同

cmd >out.txt 2>&1
cmd 2>&1 >out.txt
命令第一步第二步最终去向
>out.txt 2>&1fd 1 → out.txtfd 2 → fd 1 此时的目标stdout、stderr 都去 out.txt。
2>&1 >out.txtfd 2 → fd 1 原来的目标fd 1 → out.txtstdout 去文件；stderr 保留原 stdout 的目标。

2>&1 复制的是执行当时的引用关系，不是建立“以后永远跟随 fd 1”的绑定。Bash 从左到右处理重定向（redirection），见 GNU Bash：Redirections。

重定向为什么适合组合程序

程序只约定读 fd 0、写 fd 1，调用方就能改变它们的来源与去向。回到章节图：“共享位置”解释引用的状态，“重定向”利用这些引用组合程序。最后还要区分，printf 等库函数在到达 fd 1 之前做了什么。
