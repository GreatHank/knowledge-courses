printf 写到了哪里

先看图底部 Unix I/O：它通过系统调用访问内核。标准 I/O 和 RIO 分别建在它之上，并不是“stdio → RIO → Unix I/O”的串联。FILE * 指向 C 库管理的流对象（stream object），里面有用户态状态与缓冲；fd 是内核接口使用的整数。

Unix I/O

open、read、write、close：直接使用描述符与返回计数。

标准 I/O

fopen、fread、fprintf、fflush、fclose：提供流、格式转换和库级缓冲。

RIO

教材提供的可靠读写辅助函数；输入缓冲状态保存在 rio_t 中。

三种“已经写出”不能混为一谈

观察到的结果通常说明什么尚不能证明什么
数据进入 stdio 输出缓冲C 库暂存了输出内核已接收到全部数据。
fflush 成功库把待输出数据交给底层写接口数据已持久化到磁盘。
write 返回正数该数量字节已被接受后续没有写回错误，且断电后数据仍在。

fflush 主要处理用户态输出缓冲；持久化（persistence）还涉及内核与设备，通常需要 fsync 等专门操作及错误处理。不要把 fflush 当作通用的“清空输入”办法。见 Linux fflush(3)。

fclose 会刷新输出并关闭流，仍应检查返回值。库缓冲的存在，也说明为什么改接 fd 之前必须考虑尚未提交的数据：缓冲的字节并不会自动记住你最初想写向哪里。

读操作的计数和结束条件也不同

size_t got = fread(buf, 1, sizeof buf, stream);
/* 项大小为 1，所以 got 正好也是字节数。
   短读之后用 ferror(stream) 与 feof(stream) 区分原因。 */

fread 一般返回成功读取的“项数”，不能对任意项大小都当成字节数，见 Linux fread(3)。feof 记录此前读取是否遇到文件结束，不能在读取前预测“下一次还有没有数据”。若需要按行处理文本，仍要考虑行长与缓冲区大小。

同一个更新流，输入输出能随意交替吗

同一更新流的方向变化所需衔接
输出 → 输入中间需要 fflush 或文件定位操作。
输入 → 输出中间需要文件定位操作，除非输入已经遇到 EOF。

这些是标准 I/O 更新流（update stream）的方向切换规则（教材 PDF 949）。fopen 的 r+、w+ 等模式建立可读写的更新流；不同模式的创建、截断语义见 Linux fopen(3)。网络套接字不能像普通文件那样任意定位，所以教材建议网络代码使用 Unix I/O 或 RIO，减少流方向切换带来的问题。这是针对教材网络程序的选择，不等于标准 I/O 在任何网络程序中都绝对不可用。

fdopen 把已有描述符交给流管理，不会自动 dup 出新描述符。用同一个 fd 建两份 FILE *，再分别 fclose，会发生重复关闭的所有权问题；其中一次关闭后 fd 数值还可能被复用。不能靠“两份流”就认为读写状态已彼此隔离。

从需求选择入口

当前需求本章给出的选择依据
查文件属性、设置描述符或重定向使用 stat/fstat、open、dup2 等相应 Unix 接口。
普通文件的格式化文本标准 I/O 直接提供格式转换和缓冲；检查长度及错误。
教材中的阻塞网络字节读写RIO 补齐短计数；根据协议决定按行还是按固定数量读取。
非阻塞网络、超时与多连接本章 RIO 循环还不够，需要等待与并发机制。

网络程序若先把文本格式化到数组中，应选择有界格式化并检查结果，再按实际长度发送；不要把未检查的格式化输出当作可靠 I/O。

回到这一章的总图

路径找到文件，描述符提供访问入口；read/write 返回实际传送量，RIO 用循环与缓冲管理这些字节；内核打开文件描述保存共享偏移，dup2 改变引用，标准 I/O 再提供流与格式化。每一层都各自保存状态，混用前必须知道状态在哪。
