这个例子由伴读设定，用来观察循环变量。始终保持 已完成量 + nleft = n，目标指针始终指向尚未填充的位置。EINTR 没有完成新字节，因此不推进指针。

把变量放回教材代码

先看上半图第 3、5 行：nleft 保存剩余量，bufp 从调用者缓冲区（buffer）起点开始。每次把二者传给 read；第 16–17 行按 nread 同步更新，最后返回 n-nleft。

read 的结果rio_readn 的动作理由
正数推进指针、减少剩余量，再检查循环已经成功得到的数据不能丢。
-1 且 EINTR本轮当作完成 0，再尝试这一次没有新字节。
0退出并返回已读量EOF 时无法继续凑足。
其他错误返回 -1把失败交给调用者。

错误发生前，缓冲区可能已经写入一部分内容；返回 -1 不会撤销那些写入。RIO 并不是事务接口。

写循环有什么不同

看下半图：rio_writen 同样移动 bufp、减少 nleft，直到 n 个字节全部交给 write，成功时返回 n；错误时返回 -1。写入失败前，目标文件或网络中也可能已经收到部分数据，不能把整段从头重发当作通用恢复办法。

RIO 是 Robust I/O，意为健壮的输入／输出。这里的 robust 表示教材帮助处理短计数和 EINTR，并不保证永不失败。这组例程围绕阻塞描述符（blocking file descriptor）使用；非阻塞 I/O 的等待、取消与超时需要另外设计。

“无缓冲”省略的是哪一层

rio_readn / rio_writen

在调用者缓冲区和 Unix I/O 之间循环，不额外保存一批未消费的输入字节。

内核仍可能缓存

无缓冲 RIO 不表示绕过内核缓存，也不等于直接访问磁盘。

RIO 的来源

它是 CSAPP 配套的辅助库，不是标准 C 库或一个新的系统调用（system call）。

大写 Rio_readn、Rio_writen 在这些小写函数之外再加错误处理；看教材代码时，注意自己正在哪一层。

可靠之后，还要减少调用次数

若每次只要一个字符，每次都调用 read 会产生大量系统调用。回到章节图的“可靠循环与缓冲”：下一课一次取回一批字节，再在用户态逐行消费。
